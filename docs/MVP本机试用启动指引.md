# TeamHub MVP 本机试用启动指引

适用：当前这台 macOS ARM64 电脑，以及 `/Users/maoshitao/开发项目库/TeamHub` 项目。更新日期：2026-09-28。

**首次建议按第 1—5 节使用浏览器试用；之后按第 6 节体验桌面版。两种方式不要同时管理同一个个人库。** 当前电脑已有依赖与打包产物，通常无需重新安装或构建。

## 1. 先了解这次试用怎么运行

所有资料和服务都在本机，不需要部署内网服务器。页面中的“云仓库”“云服务”指本机组织共享服务，并不表示文件上传到公网。


| 组成         | 用途                         | 本次位置                                                                      |
| -------------- | ------------------------------ | ------------------------------------------------------------------------------- |
| 浏览器界面   | 查看、整理、共享资料         | 通常`http://localhost:5173`                                                   |
| 个人后端     | 管理当前个人库               | `http://127.0.0.1:8001`                                                       |
| 组织共享后端 | 保存组织副本、共享标签与权限 | `http://127.0.0.1:9000`                                                       |
| A/B/C 个人库 | 模拟三个人各自的私人资料     | `.mvp-sandbox/personal-a/library`、`personal-b/library`、`personal-c/library` |
| 组织共享库   | 三个人共同访问的组织资料     | `.mvp-sandbox/shared-server/`                                                 |

启动器一次运行一个个人库，可以顺序切换 A、B、C 模拟协作。**退出登录只切换共享账号，不会切换个人文件库。** 后文会同时切换库和账号，避免把“换账号”误认为“换人”。

先准备 3—5 份可用于试验的资料副本：一份文本/Word 文件、一份 PDF、一个小文件夹即可。第一轮先跑通流程，不必导入整个资料库。

## 2. 首次准备账号——只做一次

如果已经有可用账号、账号所在团队和工作空间，可跳过本节。自动化验收用的临时账号不等于你的本机试用账号；本指引不会预置或公布默认密码。

### 2.1 打开终端，进入项目

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
```

如果之前用本项目启动器运行过服务，先停止它管理的服务：

```sh
npm run dev:stop
```

该命令不删除资料，也不会结束未知归属的服务。若桌面版正在运行，也先用 **⌘Q** 退出它。

### 2.2 在同一个终端复制执行下面整段

```sh
(
  cd "/Users/maoshitao/开发项目库/TeamHub" || exit 1
  mkdir -p .mvp-sandbox/shared-server/storage
  export TEAMHUB_SANDBOX=1
  export DATABASE_URL="sqlite:///$PWD/.mvp-sandbox/shared-server/cloud.db"
  export STORAGE_DIR="$PWD/.mvp-sandbox/shared-server/storage"
  cd cloud_backend || exit 1

  venv/bin/python provision_mvp.py --email trial-admin@example.com --name 试用管理员 --team-slug trial --team-name 本机试用团队 --workspace-name 试用资料库 --role owner --system-admin
  venv/bin/python provision_mvp.py --email trial-a@example.com --name 试用A --team-slug trial --team-name 本机试用团队 --workspace-name 试用资料库
  venv/bin/python provision_mvp.py --email trial-b@example.com --name 试用B --team-slug trial --team-name 本机试用团队 --workspace-name 试用资料库
  venv/bin/python provision_mvp.py --email trial-c@example.com --name 试用C --team-slug trial --team-name 本机试用团队 --workspace-name 试用资料库
)
```

执行过程中，每个账号分别输入两遍密码。终端不会显示输入的字符，这是正常现象。使用至少 8 个字符的密码并自行记住；邮箱只是登录名，不会发送邮件。

每个账号成功后会输出 `user_id`、`team_id`、`workspace_id` 等信息。四个账号应属于同一个团队和空间。若某一步失败，先看错误，不要认为整段已经全部成功。


| 登录账号                  | 用于体验                   |
| --------------------------- | ---------------------------- |
| `trial-a@example.com`     | 收录、整理、发布资料       |
| `trial-b@example.com`     | 获取资料、补充标签         |
| `trial-c@example.com`     | 用别人的标签找到资料       |
| `trial-admin@example.com` | 共享回收站、恢复和成员停用 |

提示“该账号已存在”表示命令没有覆盖原账号，也没有修改原密码。已有账号不用重复创建；忘记密码时不要删数据库重新开始，可另行处理账号恢复。

**不要点击登录页的“立即注册”来开通试用账号。** 公开注册在当前 MVP 中停用，使用上述维护者开通方式。

## 3. 启动浏览器版——每次试用

### 3.1 终端一：启动 A 的个人库和组织共享服务

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
bash scripts/mvp-dev.sh start a
```

看到两个“已就绪”提示后，可检查：

```sh
npm run dev:status
```

预期两个服务返回 `status: ok`。个人库路径应以 `.mvp-sandbox/personal-a/library` 结尾。

如果提示“端口已占用”，先按第 7 节处理，不要自行清理端口上的未知进程。

### 3.2 终端二：启动界面

打开另一个终端窗口，执行：

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
npm run frontend:dev
```

保持这个终端运行，在浏览器打开它输出的地址，通常是：

**http://localhost:5173**

若 5173 已占用，优先确认是否已有本项目的前端，不要重复启动。当前浏览器联调已配置 5173/5174 来源；若自动跳到更高端口，先处理重复前端，再使用 5173 或 5174。

### 3.3 确认个人库并登录

1. 欢迎页面中确认路径为 A 的沙箱库，点击 **“打开文件库”**。
2. 如果出现初始化页面，填入 `/Users/maoshitao/开发项目库/TeamHub/.mvp-sandbox/personal-a/library`，点击 **“开始使用”**。不要选择真实资料库替代沙箱。
3. 点击右上角设置齿轮，找到 **“云端同步” → “云服务地址”**。
4. 填写 `http://127.0.0.1:9000`，点击 **“保存”**。
5. 点击 **“前往登录”**，使用 `trial-a@example.com` 和你设置的密码登录。
6. 返回设置，确认工作空间为 **“试用资料库（本机试用团队）”**；如果未绑定，选择该空间后点击 **“绑定”**。
7. 打开顶部 **“云仓库”**，应看到共享资料页面。新空间没有资料是正常的。

首次准备完成。下次启动后可能自动恢复账号；仍需核对当前个人库与账号是否匹配。

## 4. 建议按这条路线试用

### 第一步：A 收录、整理和查找

1. 打开 **“待整理” → “收录本机文件”**。
2. 输入试验文件的完整路径，例如 `/Users/你的用户名/Desktop/试用资料/检修说明.txt`，点击“收录”。路径不要额外加引号。
3. 系统复制收录，原文件保持原位。关闭详情后，在待整理列表点击 **“整理”**。
4. 选择存放目录，添加几个自己理解的标签，例如 `1号主变`、`检修`、`运行部`，点击 **“完成整理”**。
5. 到 **“文档库”** 用名称或标签查找这份资料，并体验个人收藏。

在 Finder 中选中文件，按 **⌥⌘C** 可复制完整路径。浏览器模式没有桌面的原生打开文件能力，收录以手动输入路径为准。

观察重点：不记得文件夹分类时，能否用行业线索找到资料？不必追求只剩一个结果。

### 第二步：A 保存版本

1. 从资料详情查看其个人库工作文件路径，在 Finder/编辑器中打开**库内副本**。
2. 修改内容并保存，然后回到资料详情。
3. 在 **“个人版本历史”** 点击 **“检查工作文件修改”**，填写说明后点击 **“保存新版本”**。
4. 应看到 v1、v2 及当前版标记；可用 **“导出此版本”** 检查 v1 仍是原内容。

收录后继续修改最初的源文件，不等于修改库内工作副本。**“恢复为新版本”会追加历史版本，不会自动覆盖正在编辑的工作文件。**

### 第三步：A 主动共享

1. 在文档库找到资料，打开右侧“…”菜单。
2. 选择 **“发布 / 更新共享资料”**。
3. 核对共享范围、标签和版本，点击 **“确认共享”**。
4. 到“云仓库”确认这份资料已经可见。

首次发布使用当前已保存版本，未保存的工作修改不会自动混入。后续更新要再次明确操作；不是自动同步文件夹。

### 第四步：切换为 B，取回并补标签

保留前端终端运行，在终端一执行：

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
bash scripts/mvp-dev.sh stop
bash scripts/mvp-dev.sh start b
```

刷新浏览器页面，确认个人库变成 `personal-b/library`。首次使用 B 时，重复第 3.3 节设置共享地址、登录 `trial-b@example.com`、绑定同一个“试用资料库”。如果仍显示旧账号，先退出登录，再登录 B。

1. 到“云仓库”找到 A 发布的资料。
2. 点击 **“取回到个人库”** 并确认，检查 B 的文档库中出现个人副本。
3. 返回共享资料详情，补充一个 A 尚未使用的标签，例如 `年度停电计划`。
4. 确认新增标签显示 B 为贡献者；B 可以撤销自己的标签，不能撤销 A 的标签。

### 第五步：切换为 C，用 B 的标签找到资料

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
bash scripts/mvp-dev.sh stop
bash scripts/mvp-dev.sh start c
```

刷新页面，确认 `personal-c/library`，设置同一个共享服务地址，登录 `trial-c@example.com` 并选择同一空间。

1. 到“云仓库”的标签框输入 `年度停电计划`，选择联想出的标签。
2. 检查能否找到 A 发布的那份资料。
3. 打开详情，体验 **“收藏此共享资料”**，再从 **“共享收藏”** 重新打开。
4. 尝试取回当前版或某个历史版到 C 的个人库。

**这一段是本次最值得验证的核心：B 顺手补充的线索，是否真正帮助 C 找到了同一份资料。**

### 第六步：管理员回收与恢复（可选）

在当前个人库退出共享账号，登录 `trial-admin@example.com`，进入相同空间：

1. 对试验资料执行 **“移入共享回收站”**，确认普通查找不再显示。
2. 到 **“共享回收站”** 恢复资料，确认可以再次找到。
3. 若要体验停用账号，进入 **“成员账号”**，选择一个试用成员。停用影响该账号全部空间，但保留其资料和贡献。

第一轮只需体验回收与恢复；永久删除可以等确认资料不再需要时再试。管理员在这里用于组织操作，登录管理员不会把当前 C 的个人库切成另一个库。

## 5. 正常退出、再次启动和保留数据

结束浏览器试用时：

1. 在运行 Vite 的终端二按 **Ctrl+C**。
2. 在终端一执行：

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
npm run dev:stop
```

停止服务不会删除资料、标签、版本或账号。下次执行 `bash scripts/mvp-dev.sh start a`（或 b/c），再运行前端，即可继续。

**不要删除 `.mvp-sandbox/` 来“重启”。** 它保存本次试用数据；也不要把本机测试脚本生成的临时账号或截图目录当成正式试用库。

开始积累重要试用记录后，按 [MVP运维与交接](MVP运维与交接.md) 第 3—4 节停写备份。设置页仍保留旧 **“备份数据库到云端 / 从云端恢复”** 入口，该路径在当前 MVP 停用，不作为本轮备份方式。

## 6. 想体验桌面版时

桌面版使用同一套个人与共享功能，额外提供本机文件打开等桌面能力。当前已生成本机测试产物，无需重新打包。

### 6.1 先退出浏览器试用服务

停止 Vite，执行 `npm run dev:stop`。桌面自身启动个人后端，接下来只单独运行组织共享服务。

### 6.2 终端一：单独运行共享服务

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
env TEAMHUB_SANDBOX=1 \
  DATABASE_URL="sqlite:///$PWD/.mvp-sandbox/shared-server/cloud.db" \
  STORAGE_DIR="$PWD/.mvp-sandbox/shared-server/storage" \
  cloud_backend/venv/bin/python -m uvicorn main:app \
  --app-dir "$PWD/cloud_backend" --host 127.0.0.1 --port 9000
```

保持终端运行。此服务使用前面准备的同一份组织库和账号。

### 6.3 终端二：打开桌面产物，指定 A 的试用库

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
mkdir -p .mvp-sandbox/personal-a/library .mvp-sandbox/desktop-profile-a
env -u ELECTRON_RUN_AS_NODE \
  TEAMHUB_SANDBOX=1 \
  TEAMHUB_USER_DATA_DIR="$PWD/.mvp-sandbox/desktop-profile-a" \
  LIBRARY_PATH="$PWD/.mvp-sandbox/personal-a/library" \
  TRASH_AUTO_CLEAN_DAYS=0 \
  "$PWD/dist-electron/mac-arm64/TeamHub.app/Contents/MacOS/TeamHub"
```

这样不会误用默认应用 profile 或其他个人库。进入后确认 A 库，登录 A，必要时按第 3.3 节设置共享服务地址和空间。

若要换 B/C，先 **⌘Q** 退出应用，把命令中的 `personal-a` 和 `desktop-profile-a` 同时换成 b/c 后再启动。不要让浏览器个人后端和桌面后端同时管理这一库。

桌面退出用 **⌘Q**，仅关主窗口在 macOS 上不等于退出应用。共享服务单独在终端一按 **Ctrl+C** 停止；它不是由 `mvp-dev.sh` 启动的，因此不使用 `dev:stop` 管理这个手动进程。

该 `.app` 是已实测但未签名/公证的本机产物。如果系统阻止打开，先记录提示；不要修改系统整体安全设置。

## 7. 常见问题


| 现象                          | 先检查什么                                                                                               |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 8001 或 9000 已占用           | 是否已有本项目沙箱或桌面运行；沙箱用`dev:status` 查看、`dev:stop` 停止，桌面用 ⌘Q。未知服务不要直接终止 |
| 网页打不开                    | Vite 终端是否还在运行；使用终端实际输出的地址，而不是 8001/9000 的 API 地址                              |
| 页面提示网络错误              | `npm run dev:status` 是否两个服务都正常；浏览器是否使用 5173/5174                                        |
| 账号登录失败                  | 是否真的完成本机开通；密码是否正确；云服务地址是否为`http://127.0.0.1:9000`                              |
| 已登录却没有共享资料          | 是否选了相同的“试用资料库”；A 是否已确认共享，而不仅是收录到私人库                                     |
| 换成 B 后仍看到 A 的个人资料  | 只换了账号，没有切库；按第 4 节 stop/start b，并刷新页面核对库路径                                       |
| 文件修改后版本没变化          | 是否编辑了库内工作副本；是否点击“保存新版本”                                                           |
| 无法用浏览器直接打开本机文件  | 浏览器能力限制；从 Finder 手动打开详情中的路径，或使用桌面版                                             |
| 点击旧云端备份/注册提示已停用 | 属于明确停用的旧入口；按本指引开通账号，按维护脚本备份                                                   |
| 依赖缺失或 .app 不存在        | 按[README](../README.md) 的依赖安装/构建步骤恢复环境，不删数据目录                                       |

需要反馈时，记录：**当前 A/B/C 库、登录账号、点击路径、预期结果、实际提示**。不要提供密码或令牌。

沙箱个人日志：`.mvp-sandbox/personal-a/logs-local-backend.log`（B/C 替换字母）；共享日志：`.mvp-sandbox/shared-server/logs-cloud-backend.log`。

## 8. 第一轮试用结束后，回答这几个问题

- 找到资料时，是否比原来的文件夹/问人方式更省事？哪个步骤仍然费劲？
- 自己添加的标签，换成另一个人的视角后是否有用？
- 补一个标签的操作成本，是否低到愿意顺手完成？
- 当前版本与历史版本是否容易理解？是否会误以为工作文件已经保存或共享？
- 哪个入口、名称或提示最容易让人产生误解？

先记录实际体验，不要求每项都给好评。工程能运行已经验证；是否值得成为日常工作的伙伴，需要这轮试用给出答案。
