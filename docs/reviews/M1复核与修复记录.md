切库相关补充修复：

- 配置写入使用同目录临时文件、刷新落盘与原子替换，写入失败向调用者报告；bootstrap 写入失败时恢复原运行库，原 bootstrap 内容保留。
- 目录可写性探测使用临时文件，不覆盖用户可能已有的 `.teamhub_test` 文件。
- 后台哈希任务携带来源库路径；执行前确认会话所属库，旧库排队任务不会向切换后的库写入。计算期间持有受跟踪会话，切库会被拒绝。

## 迁移边界

1. 正常历史：版本号唯一、至多一个旧当前标记、没有子文件版本记录时，按契约回填。没有当前标记时以最大版本号兜底；不重排历史。
2. 歧义历史：停止并报告，保留原始记录；先在副本中核实，不能通过删行或任意重编号绕过问题。旧子文件记录不能直接当作整份文件夹快照。
3. 前次代码若已重编号，程序无法从修改后的库可靠推断原始顺序；需核对原始副本。本轮没有自动撤销既有迁移，也没有对已处于共享 004 的库重跑该 revision。
4. 本轮使用构造的临时库验证；真实资产迁移与恢复演练仍属于 M6。
5. 切库协调针对当前架构的单进程本地服务及受支持的 SessionLocal 入口，不构成多进程跨进程锁方案。
