# AI 对话期间及结束后连接中断修复

日期：2026-10-18。交付范围：macOS Apple 芯片桌面版，Hermes AI 伙伴连接稳定性。

## 1. 使用入口

[连接修复版 TeamHub.app](../../dist-electron/hermes-connection-fix-2026-10-18/mac-arm64/TeamHub.app)。先正常退出原 TeamHub，再打开新版。项目根目录的一键启动入口已优先指向此包；无需重新配置资料库或 AI 服务。

历史 Hermes 集成包保留。本次包约 446.2 MiB，已通过本机 ad hoc 签名校验；未进行开发者分发签名、公证或 Windows/Linux 运行验收。

## 2. 原因与修复

用户确认在与 AI 伙伴对话时或之后出现连接错误。个人后端日志出现多次 `127.0.0.1:8002: address already in use`，旧服务晚于新启动尝试退出；界面却固定提示检查 8001。

代码与隔离重现确认两处故障相互叠加：

1. 每次模型流块和预览都完整检查已暴露资料。30 份资料时，一次完整检查可触发约 61 次同步密钥读取；系统钥匙串命令和数据库检查占据 ASGI 主循环，可能使健康检查误判服务故障。
2. 自动重启只向 PyInstaller 引导进程发信号，引导进程退出后可能遗留仍监听端口的实际服务进程，后续重启发生端口冲突。

本次调整：

- 已提交的钥匙串凭据按设备配置绝对路径、来源和槽位在宿主进程内缓存，不缓存缺失凭据；命中前仍执行沙箱隔离检查。更换、清除成功提交后立即更新缓存；失败保留原凭据及配置修订号。钥匙串写入后的读回核验始终直接读取系统存储。
- AI 流式热路径的配置与资料检查移入线程，避免等待配置锁或系统调用时阻塞主循环。每块输出仍检查取消、个人库绑定与配置一致性；完整资料版本校验保留在真正外发前、工具边界、最终/暂停结果接纳前，数据库最终事务校验保留。
- POSIX 后端每次启动建立专属进程组；引导进程退出后仍保留归属，停止时先 TERM，必要时 KILL，并等待进程组退出再启动下一实例。只处理自身进程组，不按端口终止未知进程；启动等待已有停止操作完成。
- 网络错误显示实际本机服务 origin，区分断连与超时；保留错误代码和请求上下文，支持静默请求，无新增自动重试。地址不会包含凭据、路径或查询参数；排除 `127.example.com` 等伪回环域名。

Hermes 引擎和工具能力未变，真实 API 密钥仍仅由 TeamHub 宿主持有。

## 4. 范围与后续事项

- 缓存限本进程及已提交槽位。通过应用更换、停用密钥立即生效；直接在系统钥匙串修改同一槽位，须重启后端后生效。
- 本次消除流式热路径的阻塞放大。既有 `start()` / `continue_task()` 启动入口仍可能在并发修改密钥时同步等待配置锁，后续应将完整启动事务移入线程并保持幂等性；不能在持有线程锁时直接跨 `await`。
- Windows 只验证了仍存活根进程的树终止命令。包装进程提前退出而后代存活的恢复尚未解决或运行验收；本轮 macOS 专属进程组修复不代表 Windows 已具备相同保障。
