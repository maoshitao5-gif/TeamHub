# AI 整理与准确检索第一阶段验收

日期：2026-10-23。范围：[准确检索蓝图](../product/AI整理与准确检索实施蓝图.md)的 R1，承接[项目基石 §10.9](../product/TeamHub项目基石.md#foundation-accurate-retrieval)。本文记录工程结果，不代替真实资料上的查找效果评测。

## 1. 结论与交付范围

R1 已完成代码集成、独立审查和本机验证，提供可试用的 macOS ARM64 桌面包。用户确认后入库的整理流程保持原有规则；本轮增强其后的查找基础，不自动替用户决定资料归属。

本轮实现：

- 按当前已保存版本持久保存原文片段与来源位置，原文、资料卡、AI 线索及人工补充分开。
- 解析结果持久保存后，每批最多发布 128 个原文单元；游标与片段在同一事务提交，重启可从已发布位置继续。旧索引逐步回填，回填期间保留有效旧正文的检索兼容。
- 资料列表和伙伴工具共用多词词法检索。先按关键词覆盖数量，再按命中来源权重排序，按资料去重、分页，返回匹配片段、位置、来源类型及覆盖情况。
- 设备编号进行边界核验；真实工作表名称可参与编号查找，自动生成的“第几行”等位置标签不能冒充设备编号。
- 伙伴取得命中位置的后续阅读参数，实际读取固定版本原文后才建立来源引用。搜索命中 AI 卡片或线索不等于原文已经证明结论。
- 界面显示命中摘录、来源和位置，搜索默认按相关程度排序，清空关键词后恢复原浏览排序。片段发布进度与内容提取覆盖分别显示。

这不是全蓝图完成。R2 的全格式大文件持续解析、R3 的真实 Embedding 与视觉索引、R4 的真实业务检索评测仍待推进；两档预处理的切换界面也未包含在本次交付。

## 2. 数据、版本与安全边界

新增 `IndexChunk` 与 `IndexWorkItem` 派生数据。升级幂等创建表、FTS 与必要列，不删除数据库、不新增资料版本、不修改原件。原文片段按资料、已保存版本、内容哈希、解析器版本和 generation 关联。

检索必须提供明确可见资料范围；空范围不返回结果。资料列表保留状态、标签、类型、收藏及文件夹筛选；伙伴保留当前任务授权范围。回收站、失效旧版、旧 generation、旧解析器及其他资料库的结果不能混入。工作副本未形成已保存版本的修改不进入索引。

查询采用参数和字面匹配，排序使用白名单；关键词最多 512 字符、16 项，异常输入返回明确的用户错误。摘录以纯文本显示，HTML 不执行；搜索不自动外发资料、不触发付费 AI 请求。派生卡片/AI 线索有效性仍按版本及对应元数据规则校验，人工补充保留独立维护方式。

旧正文尚未回填为片段时，可以继续命中；无法确认的片段位置不伪造 `unit_id` 或阅读游标。未知编号边界按保守规则处理，避免截断造成错误精确匹配。

## 3. 审查中发现并修复的问题

| 问题 | 修复及验证 |
| --- | --- |
| 编号跨 4000 字符片段边界后漏检，截断片段又可能把长编号前缀误当完整编号 | 只在真实连续原文间建立桥接；记录真实相邻字符。缺少权威解析产物且结束位置不能证明时保留未知边界 |
| 旧库没有新片段时正文搜索出现空窗 | 按当前版本保留旧 `IndexText` 原文兼容，分批幂等回填，回填未完成时明确覆盖状态 |
| Unicode 大小写转换可能改变查询字面值 | 保留原查询拼写，限制去重归一化；覆盖 Straße、İNPUT 等回归 |
| 日期中的年份与相似设备编号需要不同边界 | 纯数字使用数字边界，混合编号使用标识符边界；验证 2026 日期、5053/50530 等 |
| 生成位置“第 5053 行”可能被误当设备 5053 | 编号只核验真实正文、连续桥及保存的真实工作表名称，排除生成位置标签和上下文 |
| 缺少解析产物的短截断片段仍可能伪造尾边界 | 用真实解析器 13 字符额度生成短片，模拟解析产物丢失和旧表迁移；重复迁移后均不能误报编号前缀 |
| 摘录挤压资料名称、清空搜索未完整恢复排序、部分覆盖被误显示完整 | 摘录归入名称布局区域；恢复排序字段与方向；覆盖判断同时检查 complete 与 gaps |

最终独立代码审查、Python 审查及前端审查均为 APPROVE；最后两项后端增量分别独立验证 13 项与 19 项，无剩余阻断。审查包括范围过滤、版本隔离、SQL/FTS 输入和摘录显示安全，未声称进行外部渗透测试。

## 5. 检索基准与适用范围

新增可重复工具：`scripts/evaluate_retrieval.py`；合成资料与问题：`backend/tests/fixtures/retrieval_cases.json`。运行方式：

```sh
venv/bin/python scripts/evaluate_retrieval.py --output /tmp/teamhub-retrieval-evaluation.json
```

测试自行建立临时资料库，9 份合成资料、12 个查询（11 个有答案、1 个无答案），比较旧字面搜索基线与新词法检索；模型请求为 0。覆盖站点+编号+业务词组合、相似编号、长文本尾部、表格内容、年份、Unicode 和无命中。

| 合成基准 | 旧字面搜索 | 新词法检索 |
| --- | --- | --- |
| 平均 Recall@5 / Recall@10 | 36.36% / 36.36% | 100% / 100% |
| 平均 Precision@5 / Precision@10 | 31.82% / 31.82% | 90.91% / 90.91% |
| 返回错误候选的无答案查询数 | 0 | 0 |

召回与精度只统计有答案的题；精度按实际返回的前 K 项计算，不足 K 不填充。无答案题单列有错误返回的查询数，每题最多计 1 次，结果见 `evaluation.json`。这些数值只说明固定合成样本的回归通过，**不能解释为真实资料、专业结论或语义问题有 100% 准确率**。数据规模很小，记录的延迟也不是生产性能承诺。

下一步需在授权范围内建立真实回找题集，保留独立测试题，分别测解析覆盖、召回、精度、位置、版本和耗时；同义表达及图像内容不足的失败再用于决定 R2/R3 的优先级。

## 7. 仍需推进的工作

1. 解析器内部的持续处理和检查点：目前一次有界解析完成并落盘后才能续跑发布；解析阶段崩溃仍会重解析，租约到期接管最长约 300 秒。
2. 原有 32 MiB、PDF 页数、原文单元数及字符额度等限制仍在；本轮没有以分块发布代替全格式流式解析。图片、扫描件和图形未自动全库 OCR，缺口继续显示。
3. 当前相关性是关键词覆盖和来源加权，不是 BM25、Embedding 或语义融合。通用同义表达仍依赖用户词语或伙伴改写；真实语义检索按 R3 接入后另行验证。
4. 深入建档的精确续读、档位切换及真实业务效果评测仍须独立交付。当前工程通过不能推导与模型官方产品具有同等对话或专业分析质量。
