## 问题与修复

| 问题 | 修复后的行为 | 主要实现 |
| --- | --- | --- |
| 快速收录移动原文件，版本仍指向工作位置 | 普通与快速收录共用流程；快速收录复制原文件并同步建立 v1 快照及当前引用。新收录拒绝 move 参数；index 兼容入口保留 | `api/documents.py` |
| 查重只给资料入口，未明确命中的历史版本 | 收录查重覆盖历史，返回 `document` 和匹配的 `version`；重复收录不新建资料，界面打开既有资料并提示版本号 | `api/documents.py`、`App.vue`、`PendingPage.vue` |
| 整理、移回待整理、重定位和扫描改写历史路径或摘要 | 这些操作只改变工作位置及资料元数据，不再把快照路径改回工作路径，也不以指针生成结果覆盖历史摘要 | `api/documents.py`、`api/settings_api.py` |
| 两套当前版本来源 | 版本服务只更新 `current_version_id`；新版本旧标记固定为 false，API 的 `is_current` 从资料当前引用推导；相关本地读方同步调整 | `services/versions.py`、`api/versions.py`、`api/documents.py`、`api/sync.py` |
| 永久删除回收站资料误删后来收录的同名工作文件，或误删其他记录引用的快照 | 回收站严格按资料 ID 定位，不再删除原工作路径；活动资料删除前排除其他资料仍使用的工作位置。所有快照对象暂留，不随资料删除直接物理清除 | `api/documents.py`、`core/file_utils.py` |
| 旧时间戳文件名无法证明回收站条目归属 | 停止按文件名猜测恢复或删除。无法按资料 ID 定位时恢复返回明确错误；旧条目保留待迁移核实 | 回收、恢复、手动及自动清理的公共定位函数 |
| 复制、快照落位、导出或数据库提交失败遗留半份文件 | 快照读取检查源文件变化；已有对象复用前同时校验大小和摘要；暂存统一清理。导出完整写入后以不覆盖方式落位，失败不留下半份目标文件；收录提交失败清理本次工作副本 | `services/snapshots.py`、`api/documents.py` |
| 工作文件移动后提交失败导致库与文件位置不一致 | 整理、批量整理、移回待整理、回收及恢复有移动补偿。显式永久删除先移入隔离区，提交失败移回，提交成功后清理工作副本 | `api/documents.py` |
| 重试回收请求会永久删除，批量恢复冲突仍报成功 | 重复软删除保持回收站状态；永久删除必须显式请求。批量恢复遇冲突失败并回滚；批量路由移到动态资料路由之前，避免被误匹配 | `api/documents.py` |
| 缺少个人版本操作界面 | 待整理页增加本机路径收录；详情提供保存新版本、历史列表、当前标记、指定版导出、恢复为新版本，以及加载失败重试 | `PendingPage.vue`、`DocumentDetailDrawer.vue`、`api/document.js` |

恢复历史会追加一个新的当前版本，**不覆盖用户正在编辑的工作文件**。界面在恢复前说明这一点；使用恢复后的内容可导出指定版本。单文件统计同步到恢复后的版本。

## 保留边界与后续要求

1. **快照物理回收暂缓。** 资料永久删除会移除记录和工作副本，但暂不物理删除快照；磁盘占用可能累积。后续清理必须检查全部版本引用。已有内容寻址实现仍可能复用跨资料对象，本轮通过保留对象消除误删，未另建物理去重系统。
2. **异常退出不等于普通异常。** 本轮验证了可捕获的磁盘错误和提交失败；未做断电或强杀进程注入。异常退出仍可能留下未引用对象或 `trash/purge-*` 隔离条目，需后续核对清理，不能声称文件系统与数据库完全原子。
3. **旧数据不能凭空修复。** 历史版本若已被旧代码改写或内容已经删除，本轮不会重建丢失字节；需从原始副本核实。旧回收站文件名条目和真实资料迁移仍在 M6 演练。
4. **导出不覆盖。** 单文件通过同目录暂存及硬链接落位保障不覆盖；目标文件系统不支持时明确失败。本轮验证环境为 macOS，其他目标平台仍需部署阶段验证。
5. 本轮没有修复或验收 M3 文件夹快照一致性、M4 共享发布、M5 协作或 M6 打包备份问题。
