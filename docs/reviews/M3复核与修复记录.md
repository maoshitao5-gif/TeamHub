日期：2026-09-28。范围：文件夹整体快照、个人检索与收藏、相关交互提示。

本轮依据《TeamHub-MVP实施蓝图》M3 与 V-03、V-11/V-12 的个人侧要求修复。不重新验收 M4—M6，不将共享权限、共享收藏或多账号协作归入本轮完成项。

## 1. 复核结论

此前 8 项测试只能证明基础快照与收藏 API 可用，不能证明文件夹异常处理可靠或收藏界面闭环完整。本轮已修复识别出的 M3 问题，补齐个人操作入口，并完成定向回归与真实 Electron 渲染验证。可继续后续阶段；真实行业样本限额校准仍是试用前待办，不能以构造样本替代。

## 2. 问题与修复

| 问题 | 影响 | 本轮处理 |
| --- | --- | --- |
| 文件夹先使用 copytree 复制，再检查链接 | 嵌套符号链接可能已被跟随，收录目录外内容 | 严格检查原目录；先生成快照，再从快照生成工作副本；普通和快速收录共用规则 |
| 清单哈希与 ZIP 分两次读取源内容 | 制作期间修改可能导致清单与归档不一致 | 同一批流式字节同时用于文件摘要与归档；捕获前后核对路径集合及文件身份 |
| 遍历读取失败可能被默认跳过 | 不完整目录被报告为成功 | os.walk 错误显式抛出；链接、特殊文件及不安全路径明确拒绝 |
| 缺少文件夹数量、大小与解包上限 | 大目录、异常归档可能耗尽资源 | 可配置条目、单文件、累计字节限额；解包前检查且实际读取累计检查；流式处理 |
| 工作副本与快照统计来源混用 | 保存后统计可能与已保存内容不符 | 文件数及总字节从快照归档统计；恢复历史时同样使用对应快照 |
| 收藏只有 API、没有可达的个人界面 | 使用者不能完成低成本再次查找 | 详情页收藏/取消，个人资料页收藏列表、打开详情、取消与失败重试 |
| 工作文件是否已保存不明确 | 容易把外部编辑误认为已有版本 | 增加只读修改检查，区分未检查、一致、已修改、缺失和不可检查；不创建版本或对象 |
| 搜索失败缺少提示、旧响应可覆盖新结果 | 旧结果可能误认为当前条件结果 | 显示失败及重试，保留条件，最新搜索请求才可更新结果 |
| 名称联想使用未经转义的 HTML | 文件名或标签可能被解释为 HTML | 高亮前转义文本，只生成受控 mark 标签 |
| 共现重复选中 ID 影响交集计数 | 本可找到的建议为空 | 去重 ID；后端及外部数据建议均有返回数量上限 |
| 整体文件夹拖入不处理查重信封 | 返回既有内容时出现错误的撤销入口 | 跳转既有资料并提示匹配版本 |

## 3. 保持的产品语义

- 自由标签、多标签 AND 收敛；不引入强制分类。名称检索与标签筛选继续沿用已有交互。
- 文件夹是一个整体资料，不为内部文件伪造独立历史；中文名、隐藏项、空目录保留，应用管理目录 `.teamhub` 排除。
- 版本恢复追加新版本，不覆盖工作副本；如需使用历史内容，通过导出获取。修改检查会如实显示工作副本与恢复后的当前版不同。
- 收藏以资料 ID 为引用，改名不改变引用，个人库切换隔离；已删除或不可用资料显示状态，允许取消收藏。
- 个人查询、收藏不依赖共享服务。共享收藏及共享权限仍按后续阶段单独验收。

## 4. 实现选择与限制

蓝图原表述为复制到临时目录再生成归档。本轮采用**直接写入临时归档，并用同一批内容生成规范化清单**，验证成功后落入对象库，再还原工作副本。这避免重复读取实时源内容和完整目录的额外暂存，保留不可变快照边界。蓝图同步更新。

捕获前后核对文件路径、类型、大小、设备/inode、修改及状态变更时间；检测到变化明确失败。它不是操作系统级全目录原子快照，外部持续写入期间仍应停止编辑后重试。

文件夹默认上限：10,000 个文件/目录条目、单文件 1 GiB、累计内容 2 GiB；分别可用 `SNAPSHOT_MAX_ENTRIES`、`SNAPSHOT_MAX_FILE_BYTES`、`SNAPSHOT_MAX_TOTAL_BYTES` 调整。它们是初始工程限制，尚未以真实电力资料校准；不代表共享服务限额已统一。不安全的跨平台路径（如反斜线、冒号、大小写冲突）直接拒绝。

版本操作提供忙碌状态，不虚构字节百分比。修改检查是按需结果，不是实时文件监视。M2 的快照垃圾回收、断电/强杀验证等剩余事项保持原记录。未进行全量其他阶段回归、服务器部署或打包发布。
