# MVP 系统级测试报告

日期：2026-09-28。对象：当前工作区中的 TeamHub 本机 MVP。环境：macOS ARM64、Python 双环境、当前安装的 Node/Electron。依据：M0—M6 蓝图、各阶段修复记录及本机试用指引。

## 1. 结论

**本轮已测范围全部通过，未发现新增的阻断本机试用问题。** 共 178 项自动化测试通过，另有 5 组真实界面/产物流程通过；前端构建、Python 可执行文件构建、独立 macOS 应用打包及双环境依赖检查通过。

结论适用于当前 macOS ARM64 本机 MVP，不等于所有平台、生产部署、所有容量或所有故障条件均正常。既有停用入口和未覆盖事项见第 5 节。

本轮没有修改产品业务实现；只增强了测试脚本的隔离与覆盖，并记录结果。用户原有 8001 服务（PID 1568）在测试前后均保留，没有停止、接管或写入其个人库。

## 3. 测试隔离和补强

1. 启动检查发现 8001 已有用户服务。原启动器测试会因固定端口占用跳过；改为只在临时副本中替换为动态端口，6 项均实际执行，生产启动器端口不变。
2. 打包测试支持 `TEAMHUB_TEST_APP` 指定独立产物。本轮构建到 `/private/tmp/teamhub-system-build.LopKzX/mac-arm64/TeamHub.app`，未覆盖 `dist-electron` 中可能正在使用的应用。
3. 多人协作脚本新增 B 的真实页面邮箱/密码登录。C/管理员仍通过 API 准备会话后验证各自界面；不把所有账号都宣称为表单登录覆盖。
4. 所有数据操作使用测试临时个人库、共享库及测试账号。各脚本清理自有服务，原有 8001 服务前后仍在运行。
5. 本轮测试补强文件：`scripts/test_mvp_launcher.py`、`scripts/test_m6_packaged.cjs`、`scripts/test_m5_ui.cjs`。没有修改业务代码、账号或真实资料，也未提交 Git。

## 4. 可复跑命令和证据

基础回归与构建：

```sh
venv/bin/python -m pytest backend/tests -q
cloud_backend/venv/bin/python -m pytest cloud_backend/tests -q
venv/bin/python -m unittest discover -s scripts -p test_mvp_launcher.py -v
node --test scripts/test_m6_backend_manager.cjs
npm run frontend:build
npm run backend:build
```

界面脚本 M2、M3、M4、M5 使用 5174 静态资源端口，须**依次执行**，不能并行争用该端口；若已有其他服务占用，不应直接终止它。

```sh
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/Electron.app/Contents/MacOS/Electron scripts/test_m2_ui.cjs
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/Electron.app/Contents/MacOS/Electron scripts/test_m3_ui.cjs
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/Electron.app/Contents/MacOS/Electron scripts/test_m4_ui.cjs
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/Electron.app/Contents/MacOS/Electron scripts/test_m5_ui.cjs
```

重新打包时指定全新输出目录，再把其中可执行文件路径传给产物测试：

```sh
node_modules/.bin/electron-builder --mac --dir --config.electronDist=node_modules/electron/dist --config.directories.output=/绝对路径/独立构建目录
TEAMHUB_TEST_APP=/绝对路径/独立构建目录/mac-arm64/TeamHub.app/Contents/MacOS/TeamHub node scripts/test_m6_packaged.cjs
```

## 5. 非阻断提示与未覆盖范围

- 测试仍有 Pydantic 弃用、Python crypt/cgi 弃用、SQLAlchemy 子查询隐式转换提示；前端仍有大包提示。当前均未导致测试失败，不能据此认定未来升级无兼容风险。
- 产物未签名/公证。Windows、Linux、Intel Mac、安装升级/卸载流程没有本轮实测证据。
- 未做全新机器依赖重装、内网部署、10 人持续压测、真实大容量、断电/强杀恢复或真实旧资产迁移。本轮并发用例验证业务冲突与标签写入，不等于性能压测。
- 暂存、未引用对象及发布日志自动回收仍未实施，磁盘增长需关注。
- 登录页/设置页仍有“立即注册”“云端备份”等旧入口，对应服务在 MVP 明确停用。正常试用按启动指引走维护者开通和脚本备份；本报告不把这些旧入口列为可用功能。
- 系统测试证明已覆盖的工程行为；是否提升找资料效率、是否愿意持续贡献标签，仍需真实试用反馈。
