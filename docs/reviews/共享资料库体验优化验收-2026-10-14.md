# 共享资料库体验优化验收

日期：2026-10-14。依据：[项目基石 §9.7](../product/TeamHub项目基石.md)及用户授权的共享入口方案。

## 本轮行为

- 设置只保留“云服务”地址、账号和登录；普通成员无需绑定工作空间或创建组织。
- 桌面与网页统一显示“组织 / 资料库”；单库自动进入，多库恢复当前服务和账号仍有权限的上次选择，首次多库由用户点击卡片。
- 云仓库和投递共享当前选择；管理员页面独立选择管理组织，不改日常浏览位置。
- 新发布直接选择目标及成员，不要求已有当前库；更新原资料展示原组织、资料库、资料名称，目标仍由 ShareLink 决定。
- 查重后明确选择“查看已有资料”会进入其目标库并打开资料；失败留在对话框提示原因。
- 请求与成员列表按服务、账号、个人库和目标隔离，重试保持已确认的内容、范围和目标。没有资料库和加载失败分别表达。

无需数据库迁移。原 workspace API 与离线 ShareLink 查询保持兼容；新增已鉴权的原目标查询，禁止缓存，不因查看组织管理而获得受限资料权限。

## 审查发现与修复

独立 JavaScript、Python 审查发现并修复：

1. 独立发布到 B 后查看重复资料，旧入口仍留在浏览库 A；现显式进入已核验目标后跳转，失败不假跳转。
2. 连续选择 B、C，B 已保存而 C 失败时界面可能仍显示 A；现记录本会话最后确认保存的库，使失败后界面、后台与偏好一致。
3. 退出写失败仍报成功，及旧退出清除新账号；现严格原子保存并串行会话变更，界面仅在后台确认后退出，失败保留已登录状态并明确提示，迟到响应不清理新会话。
4. 校验会话后切个人库，二次动态读取可能将 B 的配置写入 A；现始终读取捕获的原路径，校验服务、凭据与当前路径，禁止跨库合并写入。
5. 冻结的发布重试被当前成员列表变化或读取失败阻塞；现保留原目标、原成员及请求内容，允许向服务端核对原结果，新请求仍须通过当前成员校验。

上述核心问题都有修复前失败与修复后通过的回归证据。初审的 Block 结论是修复依据，最终结论以当前代码终审及下表为准。
