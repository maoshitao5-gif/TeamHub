# M5 复核与修复记录

日期：2026-09-28。依据：《TeamHub-MVP实施蓝图》M5，V-06、V-10、V-14 及 V-11 的共享协作部分。

## 1. 范围与结论

本轮修复多人标签贡献、共享检索可见范围、组织回收站、账号停用及共享收藏，并联调本地适配层与桌面界面。M5 核心闭环已完成定向复验；不将本轮结果扩展为 M6 打包、备份或生产部署验收。

原有实现存在“服务端有接口，用户端无法完成操作”的断层；顺序请求也不足以证明并发标签不会丢失。初次缺陷复现记录为 `/tmp/teamhub-m5-before.log`，6 项失败、6 项通过；后续增加覆盖并修复。此前 M5 完成记录中的证据不足，以本记录为准。

## 2. 问题及修复

| 问题 | 修复结果 |
| --- | --- |
| 共享页缺少标签贡献入口，管理员权限在界面写死 | 新增逐条补充/撤销标签，显示贡献者；操作能力来自服务端 context，服务端仍逐请求鉴权 |
| 同时新增标签采用先查后写，可能竞争；批量操作可能先新增再发现越权 | SQLite 写事务先加锁，再重新检查身份和空间权限；所有移除权限预检后执行，越权整批不落库 |
| 重复添加可能混淆贡献归属 | 同空间复用标签，资料与标签只保留一个关联；重复添加不抢占原贡献者，普通成员只能撤销自己的关联 |
| 回收后可通过详情、历史、下载等入口继续访问 | 默认资料查询拒绝回收状态；详情、历史、下载及标签操作统一隐藏，管理员需先恢复才能访问内容 |
| 标签列表/联想泄露回收或无关联资料的标签 | 仅查询当前可见空间、未回收资料实际关联的标签；计数、名称、标签与共现搜索范围一致 |
| 按逗号分隔标签名称，破坏含逗号的自由标签 | 新界面使用 tag_ids 做 AND 查询；共现去重已选 ID，并叠加名称条件；保留旧名称查询兼容入口 |
| 删除对象发生在数据库提交前；文件夹对象摘要取错 | 先提交资料删除与审计，再加写锁检查所有空间、所有历史版本引用；文件夹使用归档摘要定位对象 |
| 未回收即可永久删除、失败容易误报或误删内容 | 必须先回收；数据库提交失败保留对象，物理清理失败保留待清理对象；其他资料引用始终受保护 |
| 删除账号可能破坏作者及组织内容，停用未撤销刷新令牌 | DELETE 用户返回 410；改为停用并保留作者/资料/版本/标签；撤销刷新令牌，停用期间旧访问令牌也被拒绝 |
| 另一用户更新接口绕过停用保护 | 统一用户状态变更入口；禁止自停用、自撤销系统管理员，保留至少一个可用系统管理员；记录状态变更审计 |
| 标签与管理请求缺少完整本地代理 | 标签读取、联想、权限上下文、回收站和账号停用经本地适配层；错误透传，网络错误明确反馈 |
| 登录恢复、切换空间只更新部分状态 | 修正团队接口末尾斜杠重定向；恢复请求合并，路由等待恢复；保留有效空间并正确解包；切换先服务端校验并持久化 |
| 搜索与详情旧响应覆盖新范围、失败被视为空列表 | 按请求序号与空间范围接收响应；显示错误及重试入口，避免以空结果掩盖请求失败 |
| 共享文件夹与指定版本缺少可用取回流程 | 共享页通过 M4 已校验的取回接口导入个人库，支持文件夹及指定历史版 |
| 共享收藏只有引用模型、没有使用闭环 | 补齐收藏、列表解析、再次打开与取消；重复收藏复用引用；打开时重新鉴权，回收或失权显示不可访问 |

## 3. 关键契约

### 3.1 贡献与可见范围

- 标签没有新增私有/共享双属性；对共享资料补充的标签仍为共享贡献。
- 标签按关联增删，不整组替换。新增名称去除首尾空白，拒绝空名称和超过 100 字符的名称；每次 add/remove 各最多 100 项。
- 关联读取返回 contributor_name、added_by 和 can_remove。viewer 不可写，member 仅移除本人贡献，admin/owner 可移除任意贡献。
- 真实并发验证覆盖不同成员添加不同标签、同名标签；均保留正确关联与贡献归属。
- 无空间成员资格返回 404；空间内权限不足返回 403。隐藏的回收资料不出现在普通搜索、详情、历史、下载或标签联想中。
- 名称与标签联想各最多 10 项，共现最多 8 项。自由标签按 ID 筛选，不要求统一分类树。

### 3.2 回收、永久删除与审计

回收、恢复及永久删除仅空间所属团队的 admin/owner 可以执行；重复回收/恢复不重复改变状态。永久删除必须有明确确认且对象已在回收站。

删除分两阶段：第一阶段在事务中删除资料元数据并写 AdminAction；只有提交成功后，第二阶段才重新取得 SQLite 写锁，检查 CloudVersion 在全部空间、全部版本（含其他回收资料）中的 storage_key、manifest_hash/content_hash 引用。与发布共用写锁，防止检查与删除之间新增引用。

文件夹对象以 manifest_hash（ZIP 字节摘要）定位，不能用 content_hash（规范化清单摘要）代替。对象清理失败不回滚已成功提交的资料删除，响应提供 objects_deleted / objects_retained。后者也包含仍被其他资料引用的对象，不能直接当作错误数量。

**永久删除不是全盘空间回收保证。** M4 为重试保留的上传暂存硬链接、未引用对象及本地请求日志仍待后续安全回收；本轮不会简单按文件年龄删除这些内容。

### 3.3 停用账号的权限边界

空间管理员管理本空间标签与回收站；**全局账号停用限系统管理员**，因为该操作影响账号的所有工作空间。共享页只向系统管理员展示停用入口，并提示影响范围。没有把单空间管理员提升为全局管理员。

停用保留用户、组织资料、作者和标签贡献；停止当前访问并撤销已有刷新令牌。重新启用不会复活旧刷新令牌。尚未加入账号 token epoch，不承诺重新启用后所有未到期的旧访问令牌仍永久无效。

### 3.4 共享收藏

收藏属于当前个人库，只存服务器、空间和资料 ID，不下载文件、不改变共享权限。列表在当前服务器/空间范围展示，解析时使用当前账号重新请求真实服务；收藏不能绕过回收或成员权限。

解析只允许访问当前配置服务器，收藏中记录的 URL 不决定令牌发送目标；服务器不一致明确返回 409。资料不存在或不可见显示不可访问，允许保留引用重试或取消收藏。临时离线也不把引用自动删除。

## 5. 保留事项

1. M4 暂存及未引用对象回收仍未实施；真实大容量、断电/强杀、旧文件夹记录迁移和目标服务器性能不是本轮结论。
2. 共享页收敛到资料查找、标签贡献、收藏、取回、回收站和账号停用；旧的不可用入职审批/活动占位没有继续保留在此页，不等于新增这些产品能力。
3. 多账号自动化证明流程和权限可执行；真实用户是否愿意补标签、是否降低找资料成本，仍需 M7 试用验证。
4. 本轮未新增模型迁移，未操作真实资料、部署服务器或提交 Git；不覆盖他人的 M0—M6 工作区变更。
