# AI 资料卡与 Skill 验收

日期：2026-10-21。依据：[基石 §10.8](../product/TeamHub项目基石.md#foundation-document-cards) · [实施蓝图](../product/AI资料卡与Skill实施蓝图.md)。操作见[资料卡使用指引](../guides/AI资料卡使用指引.md)。

## 交付内容

预整理中的资料理解已从临时方案摘要中独立出来，形成绑定已保存版本的资料卡。资料在待整理时即可产生卡片，确认整理、改名、调整标签或分类后继续保留；不改写原文件，也不制造文件版本。

本轮形成以下闭环：

- 预整理在一次结构化提交中同时给出整理方案和资料卡，不额外请求模型重复总结；历史方案保持可读兼容。
- 待整理窗口和文档详情支持独立生成、补全、取消和查看卡片。摘要默认可见，导航、事实、检索词、用途、依据及缺口按需展开。
- 人工补充独立保存，AI 重算不覆盖；并发修改或文件换版时保留正在编辑的草稿，核对后再保存。
- 当前有效卡片与人工补充加入现有本机搜索。伙伴可先读卡片定位资料，再读取原文形成本轮依据；旧卡来源编号不直接成为新答案引用。
- 卡片按资料 ID、版本 ID、内容哈希和生成规则维护。新内容显示待更新；恢复历史版本可立即复用对应有效卡片。逐份资料的持续更新默认关闭，明确开启后才在新版本产生时排队；服务变化后暂停。
- 原文索引与旧摘录增强保留，后者收起为兼容入口。没有卡片或 AI 失败时，原有整理、版本及本地搜索仍可使用。

## Skill 的组织与实际接入

| 资源 | 用途 |
| --- | --- |
| [资料理解主 Skill](../../backend/app/skills/document-understanding/SKILL.md) | 区分预整理快速理解、独立补全与问题驱动阅读；规定产物、证据、缺口和结束条件 |
| [文字方法](../../backend/app/skills/document-understanding/references/text.md) | 阅读章节、规范条款与长文，核对范围、例外和附录 |
| [表格方法](../../backend/app/skills/document-understanding/references/tables.md) | 识别非首行表头、模板、多个区域、单位与公式缓存，避免抽样冒充全表统计 |
| [视觉方法](../../backend/app/skills/document-understanding/references/visuals.md) | 观察扫描页、图纸与图像，保留不可辨识部分和关系不确定性 |
| [混合方法](../../backend/app/skills/document-understanding/references/mixed.md) | 用明确对象、表号、图号等建立正文、表格和图示之间的联系 |
| [整理 Skill](../../backend/app/skills/document-organization/SKILL.md)、[伙伴 Skill](../../backend/app/skills/ai-partner/SKILL.md) | 接入共同资料理解，不强制普通聊天执行完整卡片流程 |

Hermes 通过受限的 `read_skill_reference` 工具按需加载上述方法，同一任务避免重复加载。资源仅限随包发布的允许列表，不开放任意路径或模型自行安装技能。主 Skill 和引用方法均包含判断步骤、适用边界与案例；规则不是越多越好，应先选择能解决当前阅读难点的一种方法。

程序负责结构、版本、授权与来源编号校验，实际覆盖由阅读工具记录。模型负责内容理解及阅读策略。来源编号真实存在，并不自动证明语义推断正确；本轮不把结构校验当成专业质量认证。

## 保存位置与边界

资料卡和任务状态存于当前个人资料库的 `.teamhub/db.sqlite`，与资料库一起备份和迁移。

| 数据表 | 保存内容 |
| --- | --- |
| `document_cards` | 按资料与版本保存内容 JSON、来源、覆盖、模型、规则版本、卡片修订和检索文本 |
| `document_card_annotations` | 独立用户补充、修订号、关联版本及更新时间；跨版保留并待核对 |
| `document_card_jobs` | 当前生成任务、冻结范围、服务修订、执行状态和安全错误说明 |
| `card_refresh_policies` | 单份资料的持续更新选择及所授权服务修订 |
| `document_card_requests` | 请求收据，用于重复请求去重 |

实现见[数据模型](../../backend/app/card_models.py)、[任务模型](../../backend/app/card_job_models.py)、[持久化服务](../../backend/app/services/document_cards.py)、[后台任务](../../backend/app/services/card_jobs.py)。检索复用原有索引投影，没有新增向量数据库。

卡片没有另存一份 Word、Excel 或 PDF；`.teamhub/objects/` 仍保存不可改写的文件内容快照。卡片修订与文件版本相互独立，卡片重算不会改写快照。个人卡片不会自动传到组织共享空间。

## 复核中修复的问题

1. **删除旧版本误伤当前搜索**：删除没有卡片的 V1 时，旧索引的外键级联可能带走 V2 的卡片与补充搜索投影。增加版本删除后的当前投影恢复及回归测试。
2. **历史与过期显示混淆**：补齐卡片来源版本号；同一文件版本因规则变化而过期，明确显示“待更新”，不误称来自旧文件版本。
3. **人工草稿跨版冲突无法恢复**：独立维护编辑时的版本与修订；轮询、父组件更新和 409 冲突均保留草稿，由用户核对后重新关联当前版本。
4. **补全缺少已有理解语境**：执行前冻结已有卡片导航、缺口及用户补充；剥离历史来源编号，跨版内容明确为待核对线索，不冒充当前证据。
5. **覆盖判定误用显示名格式**：改用已保存快照的原始文件名判定读取类型，避免把改名后的 Office 文件错误视为已完整读取的纯文本。
6. **新预整理可能漏交卡片**：新提交结构要求提供资料卡，旧持久化方案保持兼容；缺失或空卡片不能作为新的有效提交。
7. **较浅结果保留后缺少解释**：新阅读范围少于已有成果时保留原卡，并明确提示，避免用户误以为已被新结果替换。

相应失败与修复后日志保存在本轮证据目录，覆盖数据库、任务、真实 Hermes 工具协议及前端交互。独立 Python、前端和跨组件审查已通过；新提交的卡片缺失或为空时，同一任务可修正后继续，58 项相关回归及独立 3 项检查通过。

## Skill 质量试读及限制

除工具协议测试外，使用独立智能体试读 4 份合成输入：偏移表头的申请表、含后部例外条款的长制度、缺失可读图像的混合报告、缺少判断依据并含指令性文本的记录。试读不提供评分答案；观察阅读顺序、事实关系、缺口与证据使用。

初轮发现混合资料存在不必要地加载多种阅读方法的倾向，因此修订“先选解决当前难点的一种方法”的规则，并重试该案例。4 份初轮及 1 份修订后输出共 5 份通过卡片结构校验。保留[案例与评价规则](../../backend/tests/fixtures/document_understanding_cases.json)、[试读输入](../../.mvp-sandbox/document-cards-2026-10-21/skill-trial-inputs.json)、[初轮输出](../../.mvp-sandbox/document-cards-2026-10-21/skill-trial-output.json)和[修订后输出](../../.mvp-sandbox/document-cards-2026-10-21/skill-trial-refined.json)。

这属于独立阅读策略试验，**不是 DeepSeek 真实调用，不是同模型新旧方案对照实验，也没有完成多次统计评测**。工程测试证明流程和约束可执行；仍需固定业务样本、模型与预算，评价关键事实准确性、遗漏、检索收益、用户修改量、耗时和费用。

当前边界：

- 补全可以参考旧卡和缺口，但没有跨任务精确游标缓存或分段增量合并，可能重读原文。
- 部分理解如实保留；模型不具备视觉能力、工具未还原布局或预算不足时，不承诺全面理解。
- 尚未提供组织云端共享卡片、向量检索、跨资料自动关系图或长期偏好学习。
- 首版针对单份受管文件，整体收录的文件夹仍按原有手工流程处理。
- macOS ARM64 本机包通过验证，尚未完成其他操作系统、开发者分发签名或公证验证。

## 使用入口

先按 **⌘Q** 正常退出旧版，再双击项目根目录[启动TeamHub.app](../../启动TeamHub.app)。启动器优先打开[本轮应用](../../dist-electron/document-cards-2026-10-21/mac-arm64/TeamHub.app)，缺失时回退此前格式修复包等既有交付。

本轮桌面沿用已配置个人库。仅更新源码不会更新旧应用包；已经打开的旧进程也不会因双击启动器自动换成新版本。个人资料卡无需组织云端运行，操作见[资料卡指引](../guides/AI资料卡使用指引.md)。
