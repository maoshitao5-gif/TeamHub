# AI 自然交互重构验收

开始日期：2026-10-19；完成验收：2026-10-20。范围：个人端 AI 伙伴、TeamHub 与 Hermes 的会话和任务协作、桌面交互及打包交付。

结论：本轮架构、代码、独立复核和本机工程验收已完成，根目录启动入口已指向新版。普通对话直接发送，多轮保留有效上下文，内部执行段自动衔接，连接故障及停止保留已有进度。工程测试使用真实 Hermes 和本机合成模型；未据此宣称已经达到 DeepSeek 官方产品的实际回答质量。

设计依据：[自然交互重构蓝图](../product/AI自然交互重构蓝图-2026-10-19.md)先于生产代码修改形成；产品规则同步[项目基石 §10.7](../product/TeamHub项目基石.md#foundation-ai-partner)，操作见[使用指引](../guides/AI智能伙伴使用指引.md)。

## 1. 问题与最终架构

原体验问题集中于编排：逐轮准备和确认、跨轮原生历史为空、内部额度被暴露为用户中断、工具可恢复失败升级为整轮失败、长流容量过小、断线后任务状态不清晰。单纯增加调用次数不能解决这些问题。

| 部分 | 最终职责 |
| --- | --- |
| TeamHub 页面 | 自然输入、服务与资料范围、流式回答、停止、恢复和成果保存 |
| TeamHub 会话服务 | 持久会话、固定版本、幂等提交、任务状态、资料范围与真实用量 |
| Hermes | 接续原生对话历史、理解任务、调用工具、管理上下文并组织回答 |
| TeamHub 工具桥 | 实际搜索、快照读取、来源登记、阅读进度和文本草稿 |
| TeamHub 模型网关 | 持有真实密钥，固定服务目标，处理流式传输、累计额度与取消 |

采用有状态会话与独立任务进程。Hermes 随应用交付，按需启动；用户无需另装服务。保持固定上游 v0.22.2，未修改校验锁定的上游源码。适配器修订为 2，旧适配器在模型请求发出前明确拒绝，避免新前端误接旧引擎。

## 2. 用户可见改进

- 输入后直接发送，Enter 发送、Shift + Enter 换行，中文输入法选字不会误触发。无需逐轮准备、勾选和确认。
- 默认普通回复，可开启深度思考；资料范围和思考方式随会话恢复，预算放入高级选项。
- 三轮及后续追问接续原生角色、工具调用和有效证据，当前问题以自然语言传入 Hermes。
- 内部执行段在同一任务总预算内自动衔接；后台其他 AI 作业占用时聊天可排队、可取消。已暂停任务允许直接提出新问题。
- 空检索、重复读取或证据容量问题先交由伙伴调整方法；单个无效引用保留正文并标明引用缺口。
- 长回答统一容量，停止或可恢复失败保留已显示的部分回答，并标记未完成。
- 事件流中断后恢复查看同一任务；发送响应不确定时按原编号只读核对，不自动重发问题。编辑下一条草稿不会覆盖未确定的原请求。
- 用户向上阅读时不强制滚动；成果与对应回答放在一起，已完成处理过程默认收起。

成果真正入库仍由用户点击保存；普通阅读和交流无需增加确认步骤。

## 3. 数据及执行规则

新增直接聊天配置、发送、继续和请求查询接口，旧准备接口保持兼容。服务修订绑定地址、模型和引擎身份，不包含密钥；同请求编号、同内容只创建一个任务，不同内容不能复用编号。公开任务提供 `request_id` 与最近已接受操作的 `last_request_id`，支持首次发送和继续的结果核对。

原生历史保存在私有任务状态，最多 512 条、4 MiB，不进入公开任务 DTO。跨轮先核验服务、资料权限、实际版本依赖及来源对应关系；不可复用时回退到有效文字上下文。图片字节不无限保存，必要时重新看图。

授权来源 `authorization_scope_ids` 与精确版本依赖分开记录，沿用户输入、助手复述及已采用历史传递。收窄范围同时过滤用户原话、助手转述、摘要和原生历史；无关资料改版不会被错误提升为全部对话的版本依赖。

新聊天默认总预算为 64 次模型请求、160 次工具调用、128000 输出 tokens、1800 秒；内部执行段为 24 次模型请求、64 次工具调用，累计消耗和时间不因续段重置。Hermes 单次响应容量为 8 MiB，回答及部分预览上限为 64000 字符。重复输出、上下文耗尽等保护保留，但使用明确原因提示，不统一要求缩小问题。

此次没有变更数据库表结构，新增内容使用既有 JSON 字段，旧会话缺少原生状态或授权来源字段时保守恢复；不删除旧库或用户资料。

## 4. 独立复核及修复

| 发现的问题 | 修复与验证 |
| --- | --- |
| POST 响应丢失后无法可靠判断任务是否接受 | 保留不可变原请求，GET 只读核对，暂时 404 退避继续，明确错误与未知结果分开处理；前端独立复核通过 |
| 有原 context 时，续段未发送最新 checkpoint | 始终传入最新证据、来源、读取范围、阶段摘要与草稿；实际 Hermes 自动续段和手动继续均完成 RED→GREEN，Python 复核通过 |
| 助手无工具复述可能绕过收窄后的资料范围 | 独立授权来源链；1、3、10 轮转述及旧消息摘要 RED→GREEN，新旧数据合成秘密标记复验通过；安全复核关闭 P1 |
| 子进程启动时取消可能丢失进程句柄 | 启动过程受保护，取得句柄后终止并回收；取消回归通过 |
| 上游把正常结果中的 `failed: 0` 当工具失败 | 适配层明确结果状态，保留真正失败反馈；专项回归通过 |
| 仅检查模型一次请求，不能证明前端没有重发 POST | 桌面测试增加 POST 增量严格为 1、全部对账使用 GET 且沿用原编号的断言；增强后的 13 组重新通过 |

通用代码、Python、JavaScript 及安全独立复核完成；所报告的阻断问题均已关闭。复核与测试不构成对所有潜在缺陷的绝对保证。

## 7. 实证边界与下一步体验评价

本轮完成 macOS ARM64 的工程验证，未执行真实收费模型调用，也未外发用户资料。Windows、Linux、Intel Mac 和正式分发安装包未验收。云端功能未修改，本轮没有重跑完整组织端测试套件。

此次解决的是会话衔接、交互打断和执行可靠性；真实回答仍受所选模型、供应商服务、资料解析和检索质量影响。当前仍是个人库关键词/正文检索、受管快照阅读和 Markdown/TXT 草稿，组织库直接检索、向量检索、任意原件编辑和长期记忆没有随本轮默认开放。

后续用同一模型配置和典型任务检验：普通连续交流是否自然、资料查找是否找全、阅读分析是否准确、来源能否核对、完成任务所需时间与费用。与官方产品的体验差距应以这些真实结果继续判断，不能以测试数量代替。
