## 2. 发现及修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 恢复直接 copy2/copytree 合并至目标 | 覆盖现有库、失败留下混合数据 | 拒绝非空目录/既有数据库及 WAL/SHM；先校验并暂存，完成后发布目标 |
| 备份只计对象数，共享恢复不验摘要 | 文件缺失、被篡改或损坏仍报成功 | 格式 2 清单逐文件 SHA-256/大小及目录集合；恢复前校验、复制后复查 |
| 个人备份遗漏工作文件与回收站 | 历史能导出但恢复库缺当前工作副本 | 备份库内工作文件、未保存修改、空目录、回收站及受管快照；库外 index 文件明确排除 |
| 只复制活动 SQLite 主文件的风险、文件和库复制窗口不受保护 | WAL 数据或引用与对象不一致 | SQLite backup API 加源库 BEGIN IMMEDIATE；维护者先停服务和编辑，复制期内容变化拒绝 |
| 文件夹对象身份与旧版本路径处理不严谨 | 校验错对象、全局字符串替换错路径 | 归档使用 manifest_hash，严格核验受管对象路径；恢复按对象相对路径重写 file_path |
| 配置仅删除两个已知 token 字段 | 后续增加的凭据字段可能进入备份 | 改为非凭据配置白名单；共享备份清除刷新令牌表，不复制 JWT 签名密钥或 .env |
| 旧备份无逐对象校验证据 | 不能证明可恢复 | 明确拒绝旧清单自动恢复，保留旧备份并要求副本核验，不伪造兼容 |
| 前端用固定 8001 先发请求，异步 IPC 才回端口 | 可能连接错误个人服务 | preload 在渲染入口前同步取得自有后端端口；真实占用 8001 场景通过 |
| 健康检查只看 HTTP 200 | 外部同端口服务可被误认作本次后端 | 每次启动分配 instance_id，健康响应匹配实例身份；不接管或停止未知服务 |
| 退出回调和健康检查都可重启、停止后仍有重启定时器 | 重复进程、退出后复活、日志流泄漏 | 合并启动/重启/停止任务，限制重试次数；清理定时器，等待自有进程退出，必要时终止该子进程 |
| macOS 关闭主窗后重新激活又创建后端 | 后端进程重复、存在悬浮窗时主窗不能重开 | 主窗重建复用后端；按主窗是否存在判断激活，不按所有窗口总数判断 |
| 生产 CSP 只通过 HTTP 响应头注入 | file:// 产物未真正获得该策略 | 构建时插入 CSP meta；脚本只允许 self，禁止 eval/内联脚本；主窗禁止页面导航和新窗口 |
| 后端 CORS 未包含打包 file:// 来源 | Electron 页面请求可能被拒绝 | 仅桌面模式加入 null 来源；个人服务继续仅绑定回环地址 |
| 构建后端依赖全局 pyinstaller、可能装入旧二进制 | 包含错误环境或旧业务代码 | 构建脚本固定仓库 venv，electron:build 先重建后端及前端 |
| 默认开发命令调用旧清端口流程 | 可能终止未知进程 | npm dev/dev:api 改用 M0 隔离启动器，补 dev:status/dev:stop；前端可单独启动 |
| 共享服务启动仍访问已经停用的 OSS | 与内网受管存储方案不一致，产生不必要外连 | 移除启动期 OSS 初始化，既有停用路由继续保持 410 |

## 3. 备份与恢复边界

### 3.1 受管内容与凭据

个人备份保留数据库中的资料、标签、收藏、版本及共享引用；保留 `.teamhub/objects`、`.teamhub/trash` 及库内工作文件。未保存的工作修改也保存，但不会伪造为已保存版本。个人库外 index 源文件不备份；其已保存的快照仍属于受管对象。

配置仅保存白名单，未知字段默认不备份。共享数据库必须保存用户及密码散列才能维持账号与归属，因此共享备份仍是敏感资产；清除 refresh_tokens，不保存环境密钥。恢复后重新登录，灾难恢复应更换 JWT 签名密钥。未备份应用 profile、暂存、未完成发布日志，不能承诺恢复未完成发布的全部客户端状态。

### 3.2 一致性、失败及落位

`--services-stopped` 要求维护者已经停止对应服务和外部编辑；不会自动停止用户进程。SQLite 写锁保护数据库复制窗口，不能替代对外部编辑器停写。源/目标重叠、符号链接及特殊文件拒绝；备份期间可观察到的变更拒绝，临时产物清理。

清单格式 2 校验文件集合、长度和摘要，数据库执行 integrity_check / foreign_key_check，并逐个验证历史版本对象。恢复严格保留当前版指针，不重编号。个人目录整体发布；共享对象目录准备后最后排他发布数据库，失败清理本次自建目录。不存在“损坏备份先写坏目标再报错”的正常流程。

共享数据库与对象目录是两个文件系统目标，断电不是跨目录原子事务；可能留下独立的部分恢复目录，需检查并换新目录重试。既有库和源备份不会因此被覆盖。未把这套停写工具宣称为在线热备、自动灾备或断电安全产品。
