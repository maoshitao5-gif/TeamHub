# 全项目审计、瘦身与测试验收

日期：2026-10-21。

结论：在 AI 预整理功能交付基础上，完成个人服务、共享服务、桌面桥接、前端、Hermes 接入及构建启动链的审查与整改。最终全量自动化回归 **1644 项通过**，另完成桌面、云网页、预览、投递、资料生命周期与 AI 的端到端验证。已生成新版桌面应用和独立云端部署包。

本次与开始审计时的工作树副本比较，不把此前尚未提交的改动算作本次新增。没有清空真实资料库、删除用户历史版本或备份，没有提交 Git。全部测试使用隔离库、合成资料和账号；AI 使用真实 Hermes 配合本机模拟模型，没有调用真实付费服务。

## 1. 保持的产品与架构边界

- 个人库和共享服务仍独立；共享、取回、投递和更新均为明确操作，不变为双向自动同步。
- 文件只处于待整理、文档库或原有回收站生命周期；标签、分类、收藏不改变对象身份。历史版本仍是不可变对象，恢复历史直接切换工作内容。
- AI 预整理仍在待整理中准备方案，用户确认后采用；四状态、批量审阅、手工整理和撤销保持可用。
- Hermes 继续作为独立本机引擎，TeamHub 控制资料范围和实际操作。锁定的上游 Hermes 源码未修改。
- 兼容性 410 路由、历史数据库模型和迁移保留；管理员身份不获得定向资料默认读取权。

## 2. 主要发现与整改

| 范围 | 原问题 | 本次处理 |
| --- | --- | --- |
| 本机服务访问 | 原先仅配置 CORS，恶意 Host、非本机连接和未可信 Origin 的请求仍可执行资料操作 | 增加统一访问守卫，验证回环主机和连接、来源；Electron `null` 来源须携带当前桌面能力凭据。所有本地 Axios 请求补齐凭据，外部来源不携带 |
| Electron 开发启动 | 扫描端口遇到任意 HTTP 200 即加载，页面获得高权限 preload | 启动自己的 Vite，用随机 HMAC 挑战验证精确实例，拒绝重定向。动态端口只在 Electron 模式严格加入来源列表 |
| Electron IPC | 文件操作等 IPC 缺少统一调用者校验 | 限定受管窗口、顶层 frame、精确入口 URL；保留可信开发页面外链功能，出站过滤阻止重定向转发能力凭据 |
| 旧云备份接口 | 仍可联网并覆盖运行中的个人数据库 | 原路径统一返回 410，删除旧执行实现；保留现行停服务备份恢复工具 |
| 目录及资料归属 | `parent=..` 可列出库外目录，普通整理可写入已登记的整体文件夹内部 | 统一使用分类目录校验；目录列表与收录/整理遵循相同归属规则 |
| 回收站与旧重叠登记 | 清理先删文件再提交，数据库失败会丢失工作修改；重叠父子资料软删后不可恢复 | 复用隔离移动、提交后清理和失败补偿；旧重叠记录在软删/永久删前返回 409，保留状态、文件与版本 |
| 旧配置启动 | 已停用版本清理字段仍赋值到 Settings，造成启动失败 | 加载时忽略停用字段，保留配置文件原值 |
| 云端认证 | 缺少配置时使用公开默认 JWT 签名密钥 | 数据库初始化前拒绝空值、短值和示例值；本机启动器生成并持久保存随机密钥，0600 权限，不写入日志 |
| 登录服务 | 两登录入口无限速，异步路由中的同步密码校验阻塞事件循环 | 两入口共用原子账号/IP 限流；密码校验进入线程池。账号默认每分钟 10 次、IP 60 次 |
| 云端暂存 | 未提交上传无累计预算、无过期回收 | 实际流写入计量，跨进程锁与活跃上传租约；默认 6 GiB / 1000 份 / 24 小时，后续上传清理过期暂存 |
| 投递配额 | 配额拒绝前已将暂存提升为永久对象，可能累积孤立对象 | 先校验配额，再在原有写事务中建立正式对象 |
| 损坏压缩包 | 解压异常返回 500，部分 I/O 信息可能暴露服务器路径 | 统一返回受控 422 等业务错误，不回显宿主路径 |

重要安全及一致性修复保留了修改前失败、修改后通过的证据。通用代码、Python、JavaScript 和安全审查分工执行，最后增量亦完成独立复核；已确认问题没有留下未处理的 P1/P2。

## 3. 代码和依赖瘦身

1. 删除无生产调用的 `pointer.py` 及仅验证该死模块的测试，不再创建新的 pointers 目录；不删除用户原有目录。
2. 删除旧云备份实现、三个无调用的云端 helper 和五个停用 OSS 配置字段。
3. 旧 PydanticAI 运行适配器迁至 `backend/tests/support/legacy_partner_agent.py`，仅供历史行为回归。真正共享的传输、提示和引用校验提取到 `partner_protocol.py`，定义与原实现 AST 一致。生产 Hermes 不再间接加载旧 SDK；原有行为测试保留。
4. PyInstaller 只收录所需 skills 数据，不再重复携带完整后端源码树；明确排除旧 SDK 和停用对象存储 SDK。
5. 移除无调用的 `wait-on`、`concurrently` 以及两套 Python 环境中的停用依赖，更新锁文件，保留测试专用锁。完整后端回归需安装 `requirements-legacy-tests.lock`。
6. 删除可重建的 PyInstaller 编译缓存 **274.20 MB**，保留最终产物、上游引擎构建输入、前一可用应用、审计证据和真实备份。

| 指标 | 审计前 | 审计后 |
| --- | ---: | ---: |
| 个人基本依赖锁条目（含构建/基本测试） | 70 | 41，另有 13 个历史测试专用条目 |
| 云端依赖锁条目 | 52 | 43 |
| 个人后端可执行文件 | 59,986,096 字节 | 31,620,592 字节，减少 **47.3%** |
| 桌面应用逻辑文件总量 | 446,617,096 字节 | 417,918,509 字节，减少 **28.70 MB / 6.4%** |

以上体积按文件实际内容计量，排除符号链接重复计数；Finder 和 `du` 的块占用数字可能不同。桌面仍包含 Electron 与独立 Hermes，不能将后端 47.3% 的缩减解释为整个应用缩减比例。

## 4. 依赖安全检查

- 前端 npm 官方检查从 **13 项（11 高、2 中）降至 0**；升级 Axios、Vue、Vite 等兼容版本。
- 用户授权后完成根目录 npm 官方检查：原 **10 项（2 高、8 中）降至 0**。兼容补丁更新后，将 `@electron/get` 的可选 `global-agent` 精准覆盖为 4.1.3，移除 `roarr → sprintf-js` 漏洞链；实际本机 HTTP 代理回归及打包均通过，没有采用 npm 建议的强制降级。
- 个人及云端升级 FastAPI / Starlette，云端升级 python-jose；两套 Python 环境 `pip check` 通过。Starlette 升级覆盖官方披露的 [Host URL 路径问题](https://github.com/Kludex/starlette/security/advisories/GHSA-86qp-5c8j-p5mr)和[主机名处理问题](https://github.com/Kludex/starlette/security/advisories/GHSA-jp82-jpqv-5vv3)。代理依赖变更依据 [global-agent 发布记录](https://github.com/gajus/global-agent/releases)，其中 4.1 移除了旧日志依赖。

“0 项”仅指本次 npm 官方数据库对这两套锁定依赖的查询结果，不代表项目不存在任何未知漏洞；没有声称进行完整 Python/Hermes 第三方漏洞数据库扫描或互联网渗透测试。

## 6. 使用新版与剩余边界

先按 **⌘Q** 退出旧桌面，再双击根目录[启动TeamHub.app](../../启动TeamHub.app)。启动器优先打开[本轮应用](../../dist-electron/security-audit-2026-10-21/mac-arm64/TeamHub.app)，之前的预整理版本保留为回退包。用户无需单独安装 Hermes。

云端代码和 `dist/teamhub-cloud.zip` 已更新；正在运行的云服务需按维护流程重启才会载入修改。本机启动器将签名密钥持久保存在 `.mvp-sandbox/shared-server/.jwt-secret`。从旧默认密钥首次升级后需重新登录，账号和资料保留。实际部署见[云端启动与迁移指引](../guides/云端与投递启动及迁移指引.md)。本次未替用户迁移或重置真实云库。

尚需保留的工程边界：

- 本轮实机平台为 macOS ARM64；Windows、Linux、Intel Mac、网络文件系统和多实例部署未完成实机验收。登录限流当前在单进程内，多个 worker 需外层全局限流；暂存锁使用 POSIX flock。
- 文件系统操作与 SQLite 的异常补偿不等于跨介质断电事务；本轮未增加断电恢复日志，也未主动清理历史孤立正式对象。
- 应用为本机 ad hoc 签名，尚未完成开发者分发签名或公证。
- 没有用全新机器重装所有锁定依赖。测试使用模拟模型证明工程流程，不证明真实模型的资料理解准确率或与官方产品的体验完全一致。

这些限制均不以删除历史资料、迁移或回归测试来掩盖，后续应分别安排部署、恢复演练和实际资料试用。
