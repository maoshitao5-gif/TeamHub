# 双向实体查重验收

日期：2026-10-13。范围：本机 MVP 的云端发布／网页上传、个人库取回、投递附件收录与恢复。目标是减少实体副本冗余与版本分叉，保持两端独立、权限与来源可追溯。

## 行为与边界

- 单文件按完整字节 SHA-256 查重，不以名称、标签、路径或 file／archive 分类推断相同。文件夹独立按规范清单比较结构与内容。
- 取回和投递收录检查当前个人库 pending／organized 的实际受管工作内容，不使用历史快照或过期数据库摘要。实际大小先筛选，读取前后核对身份与修改信息；异常明确停止。
- 本地命中返回 `status=duplicate` 与已有资料入口，不下载、不新增资料、版本、来源或关联，也不改变待整理／已整理状态。旧 index 索引不是受管实体，不纳入；缺失、回收对象与仅存历史不报当前已存在。
- 新云端发布仅在目标空间的当前可见、未回收资料中匹配当前实体。“另建”不绕过重复检查，但已关联资料仍可明确另建不同内容资料。不可见资料不泄漏，不自动扩展授权、合并标签或替换来源。
- 首次个人发布捕获实际工作内容并先预检。命中时不额外创建版本、发布请求或关联；实际发送内容和本地记录来自同一捕获，重试不变成后来编辑的内容。
- 正式云发布在写事务中再次查重。并发重复为确定失败，个人端保存终态，同请求重试只重新查询并鉴权，不再上传。网络结果不明仍可核对，不混称为已确认失败。
- 已关联资料继续通过版本更新延续。与目标当前版内容一致时沿用；历史内容、恢复、未保存修改保护与基准冲突保持原有明确操作规则。
- 云端仅对命中的授权实体检查正常文件、摘要、大小与文件夹清单。缺失、损坏或读取中变化返回固定 `409 STORAGE_ERROR`，不误报已存在／未变成功，不自动修复或删记录；幂等结果也复核。

入口和产品规则见[推送与取回查重指引](../guides/推送与取回查重.md)、[项目基石 §8](../product/TeamHub项目基石.md#foundation-versions)与[接口契约 §10.4](../architecture/MVP数据与接口契约.md#104-双向实体查重修订2026-10-13)。

## 审查中发现并修复

1. 网页 `force_new=true` 绕过查重，以及按分类和全部历史匹配造成的漏判／误判。
2. 投递中断已冻结恢复负载后，另一次取回先入库，原收录重试仍会制造第二实体。现恢复也检查当前已登记实体，保留恢复文件和已有来源。
3. 确定重复仍标记 pending／未完成，以及结构损坏结果被误隐藏。现只隐藏明确的收录重复终态；真正未完成、矛盾记录、其他发送失败继续显示，过滤后才取 50 条。
4. 云端旧实体损坏时仍报告重复或未变成功。现授权命中对象、沿用与结果重放均检查实际内容。
5. 已关联资料选择另建时请求标志丢失。现冻结该明确意图，同时由服务端继续阻止相同内容。
6. 查看失权高亮资料残留旧详情、投递恢复查重混入以前选中的附件。现及时清空旧对象与动作，迟到响应不回显。

新增测试均先执行有效失败复现再修复。审查的投递恢复、云实体损坏独立复现脚本也由失败转为通过。
