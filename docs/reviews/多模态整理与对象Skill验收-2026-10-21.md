# 多模态整理与对象 Skill 验收

日期：2026-10-21。依据：[基石 §10.8.6](../product/TeamHub项目基石.md#foundation-document-cards)、[资料卡与 Skill 蓝图](../product/AI资料卡与Skill实施蓝图.md)。操作见[AI 预整理指引](../guides/AI预整理使用指引.md)和[资料卡指引](../guides/AI资料卡使用指引.md)。

## 交付内容

本轮扩大**个人端 AI 预整理和资料卡**的对象范围，图片按实际图像理解，压缩包按整套资料读取。用户继续在待整理中发起任务、审阅名称/标签/分类和资料卡，一次确认后入库；没有增加逐工具确认。默认自动预整理仍关闭，主动开启的当前库策略沿用原授权。

建立八份独立的对象 Skill：文字、Word、电子表格、演示文稿、PDF、图片、文件夹、压缩包。TeamHub 自动加载当前对象规则；集合内成员需要深入理解时，再按需加载对应类型。公共资料卡规则负责身份、事实、来源和结束条件，原有 text/tables/visuals/mixed 方法解决具体阅读难点，不把所有规则塞进每轮上下文。

系统依据不可变保存版本的文件名和真实文件夹身份选择处理方式。用户修改显示名不会将图片误作压缩包，Office 的 ZIP 容器也不会被当作普通归档。类型识别不等于已成功解码，工具结果与实际模型能力决定最终可读范围。

## 支持范围

| 对象 | 本轮能力和边界 |
| --- | --- |
| 文字、记录和结构化文本 | 独立规则关注范围、生效日期、例外、事件语境；复用现有正文工具。CSV/TSV 默认按表格理解 |
| Word | 独立规则关注章节、表格、文本框与嵌图；继续使用 DOCX/ODT 等现有解析能力，类型归为 Word 不代表旧 DOC 二进制格式已新增解码器 |
| 表格 | 独立规则关注工作表、表头、单位、实际/预测、样本与全表的区别；复用现有 XLSX/ODS/CSV/TSV 工具 |
| 演示文稿 | 独立规则区分背景、目标、计划和已完成结果，按页保留来源；复用 PPTX/ODP 和内嵌图片读取 |
| PDF | 独立规则结合正文、实际页图与扫描缺口；没有文字层时可阅读页图，不把提取正文等同于读懂图纸 |
| 图片 | 保留 PNG、JPEG、GIF、WebP、BMP、TIFF；增加 AVIF、JPEG 2000、ICO/ICNS、PNM、TGA、PCX 等本地解码，支持 macOS 原生 HEIC/HEIF 与安全 SVG 子集；实际图像转为受限 PNG 后进入现有模型通路 |
| 文件夹 | 沿用整体资料身份与内部结构，成员清单显示统一类型，成员图片同样支持新增格式；各类型规则按需加载 |
| 压缩包 | ZIP、TAR、TAR.GZ/TGZ、TAR.BZ2/TBZ/TBZ2、TAR.XZ/TXZ、单文件 GZ/BZ2/XZ、7Z、RAR；读取成员的正文、表格、PDF、图片和办公嵌图，形成整体卡片 |

HEIC/HEIF 和 SVG 的原生转换已在当前 macOS ARM64 验证，其他平台未完成同等交付验证。HEIC 本轮读取主图，无法可靠取得全部帧数时明确保留缺口；GIF/TIFF 等可用帧按实际读取记录覆盖。SVG 仅接受自包含安全子集；外部资源、脚本、嵌入文档等会被拒绝，不宣称支持任意 SVG。图片有输入大小、像素与帧数限制，缩放导致的细节损失保留说明。

图片进入模型需要配置的模型与接口接受图像输入。可在设置中使用“测试图像理解”。未接受图像请求时会显示明确原因，不把文字推断当作视觉成功，也不自动反复请求收费服务。

压缩包仍是**一个普通文件资料**，不是文件夹资料，不拆出子文档；原压缩字节、成员路径及内部结构保持。整理命名保留 `.tar.gz` 等完整复合后缀。嵌套压缩包本轮不递归展开，加密、损坏、超限、不可用算法会成为缺口；有可读的其他成员时可以形成部分卡片。普通伙伴聊天可利用整体资料卡导航，本轮没有向普通聊天开放递归读取压缩包/文件夹成员的完整工具集。

## Skill 如何发挥作用

- [文字](../../backend/app/skills/text-understanding/SKILL.md)：避免只读前段而遗漏后文的例外或废止条款。
- [Word](../../backend/app/skills/word-understanding/SKILL.md)：区分草案、计划、修订和实际完成状态，结合表单和嵌图理解。
- [表格](../../backend/app/skills/spreadsheet-understanding/SKILL.md)：保留行列关系和计量口径，不把预测当实际，不据样本统计全表。
- [演示文稿](../../backend/app/skills/presentation-understanding/SKILL.md)：目标和计划不转写为事实，图表按轴、单位和时间核对。
- [PDF](../../backend/app/skills/pdf-understanding/SKILL.md)：文件名不证明最终版，正文阅读不证明未读页或图形内容。
- [图片](../../backend/app/skills/image-understanding/SKILL.md)：实际看图后描述主体和参数，不补猜模糊字符或无阈值的正常性结论。
- [文件夹](../../backend/app/skills/folder-understanding/SKILL.md)：先列目录、再代表选读；跨文件关系须核对，目录名不能独自认证站点归属。
- [压缩包](../../backend/app/skills/archive-understanding/SKILL.md)：整体理解与成员来源并存，明确嵌套及未读范围，不执行成员内容。

Skill 随应用打包，不需要用户额外安装。按固定类别加载，拒绝任意路径、URL 和不合规资源；同类任务内只加载一次。规则没有自动自修改能力。公共卡片规则版本升为 2：旧卡保留并可能显示“待更新”，按需重新生成，不因升级自动分析整个资料库，也不覆盖人工补充。

八份对象 Skill 均通过格式校验。独立智能体用八组未提供标准答案的合成输入进行正向推演，结果均通过实际 `CardContent` 契约校验及来源归属核对：能区分废止条款、立项与建成、实际与预测、目标与完成量、送审与生效、无阈值的压力记录、两个目录内的同编号对象以及未完成的验收。图片案例实际查看了合成图像，其他案例使用给定的模拟工具输出。结果见[推演产物](../../.mvp-sandbox/multimodal-organize-2026-10-21/skill-forward-results.json)。这检验规则的执行方向，不是无 Skill 对照实验，不能据此量化准确率提升。

推演未发现阻断问题；后续可进一步细化表格、演示 Skill 在无概览工具结果时的直接阅读降级说明。当前通用规则已经允许使用有限的实际正文形成部分卡片，不要求伪造概览。纯文字短案例未观察到类型专项规则相对公共规则的独立增益，后续应使用更复杂样本评估。

## 数据、性能与边界检查

资料卡继续保存在个人库 `.teamhub/db.sqlite`，绑定父文档 ID、保存版本及内容哈希。压缩成员来源增加 `member_path`，不同目录内同名成员不会混淆；清单与结构不产生正文证据。实际读取形成来源、覆盖与已读成员统计，不能由模型自行声称全包已读完。卡片更新不生成文件版本。

压缩读取使用本机 libarchive，在隔离子进程接收已验证的快照文件描述符，不接收任意解包目标，不将成员写入用户目录。路径穿越、链接、特殊文件、大小写或 Unicode 规范化冲突、异常压缩和资源超限均作检查。上限为 10,000 条目、256 MiB 展开总量、32 MiB 单成员，并有子进程时间、内存与输出界限；任务内在快照状态未变化时复用清单验证。7Z/RAR 不增加独立应用或在线解压服务依赖，具体算法仍受系统解码器约束。

图像在受控渲染子进程解码，原生转换只接触工具临时文件，取消时清理子进程及临时目录。目录选读和原文来源按成员隔离，沿用原有预算与重复调用抑制。

审查修复了图片集合内类型清单不统一、先看结构后读图仍遗留“无文字”缺口、图片成员的下一步调用缺少成员路径、原生 SVG 缩放未报告细节损失等问题，均补充回归。Python、前端及通用安全审查未留未处理的 P1/P2。

核心实现：[类型与规则路由](../../backend/app/services/object_skills.py)、[图像解码](../../backend/app/services/image_formats.py)、[压缩包读取](../../backend/app/services/archive_reader.py)、[隔离解码器](../../backend/app/services/archive_native.py)、[整理工具](../../backend/app/services/organization_tools.py)、[资料卡持久化](../../backend/app/services/document_cards.py)。
