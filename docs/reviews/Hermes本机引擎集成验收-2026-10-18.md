## 2. 实际架构

TeamHub 个人服务按已确认的任务段启动独立 Hermes 进程，通过双向版本化 NDJSON 管道通信。进程调用固定上游 `AIAgent.run_conversation()`，不是用自写循环冒充 Hermes。没有新增需要用户配置的 Hermes 网址、账号或密钥。

上游固定 `NousResearch/hermes-agent v0.22.2`，归档 SHA-256 为 `db814cffb05e231a0ce54abcc997b77b690083c6395b41ddf8827ac373b6c6c0`，采用 MIT 许可证。构建使用独立 Python 3.14.6 和 48 包完整哈希锁；冻结程序随桌面包交付，首次运行不下载引擎或依赖。源码准备及每次冻结前均执行离线归档与完整源码集合校验，拒绝额外模块、`.env` 和符号链接。

Hermes 负责本段模型与工具循环；TeamHub 保管真实密钥、实际模型目标、资料路径、数据库、证据、草稿和任务状态。全部模型请求，包括辅助处理请求，都由宿主逐次进行授权守卫、真实计量和预算控制。上游错误不自动重试，迭代耗尽不调用隐藏总结模型。

已确认历史作为当前问题中标注的 `approved_history` 数据提供；本段原生工具链保留推理字段，原始推理不显示、不保存、不跨轮重放。不额外发送上游默认系统提示中的本机 home、profile、用户名或其他会话信息。

工具目录为既有七项：检索、结构查看、文字阅读、表格阅读、原页/独立图片、Office 内嵌图片及 Markdown/TXT 草稿。任意终端、原件任意编辑、组织自动发布和长期记忆没有因接入 Hermes 而开放。Word／Excel 文件加工、语义检索和真实模型效果仍需分别建设与验证。

## 4. 审查及适配修复

- 重复取消可以打断清理：以独立、受保护的清理任务等待连接关闭、子进程回收和临时目录清理，再传播取消。已覆盖忽略 TERM 后再次取消的场景。
- Hermes 默认工具目录折叠会隐藏 TeamHub 工具：关闭该配置并核对真实注册目录只含允许的七项。
- SDK 读到 SSE `[DONE]` 后提前关闭：排空本响应剩余管道帧，防止污染下次工具返回。
- 默认系统提示附加环境信息、原生历史缺失旧推理字段：以 TeamHub 系统规则及已确认历史数据封装接续，保留本段原生工具链。
- 工具前中间文字混入最终预览：在上游消息结束回调处清空缓冲，剔除边界分隔换行。真实 Hermes 的“中间文字＋工具→最终答复”回归通过。
- 缓存源码额外文件未校验：增加完整文件集合和哈希核验，并在冻结构建前强制执行；额外 `.env`、顶层/嵌套 Python 模块均被拒绝。

专项修复保留了失败重现日志与 GREEN 验证。没有重置数据库、覆盖用户资料或使用真实 API 密钥。

证据归档在工程忽略目录 `.mvp-sandbox/hermes-2026-10-18/`，含全量及专项日志、桌面 HTML/JUnit/JSON、截图和 trace。`desktop/` 为最终应用资源路径验收；`packaged/` 为完整应用冷启动验收。
