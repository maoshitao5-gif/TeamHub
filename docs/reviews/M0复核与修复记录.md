日期：2026-09-24。范围仅限 M0；未复核或修改 M1—M3 业务实现。本次基于未提交工作区实施，保留其他智能体已有改动。

**结论：本机 macOS 开发基线通过本轮 M0 验收。** 两个隔离后端、浏览器开发界面已实际运行；Electron 桌面壳与其他操作系统不在本次验证范围。

## 1. 本轮发现与修复

前一轮已增加沙箱开关、干净环境、健康检查，但仍存在以下缺口：

| 问题 | 本轮修复 |
| --- | --- |
| 本地 lifespan 仍从旧 `config.json` 恢复外部库路径 | 沙箱模式不恢复 bootstrap 配置；启动器显式指定个人库为 `.mvp-sandbox/personal-{a,b,c}/library`，禁用启动自动回收站清理 |
| 停止逻辑要求服务已监听端口，无法清理启动阶段卡住的服务 | 以 PID、非空启动时间和本仓库预期服务命令核验身份；停止不再依赖监听状态，等待退出，必要时对再次确认身份的进程升级终止 |
| 立即退出、异常中断或并发启动可能使进程记录与清理失配 | 增加退出清理、串行启动器锁、明确的失败返回和存活/健康检查；仅回收本次启动的服务 |
| 中文路径的实际服务命令与 C locale 下的 `ps` 输出无法匹配 | 启动时间使用固定 C locale，命令读取使用 UTF-8；回归测试目录包含中文和空格 |
| 界面验收只有 HTTP 层证据 | 用 Chrome 实际访问 Vite 页面，核验渲染、沙箱库路径及页面基础请求 |

主要文件：[启动脚本](../../scripts/mvp-dev.sh)、[应用启动](../../main.py)、[启停回归](../../scripts/test_mvp_launcher.py)、[真实配置隔离测试](../../backend/tests/test_m0_sandbox.py)。

启动器拒绝 a/b/c 以外的个人沙箱参数；端口占用时不终止占用者。`status` 在服务未运行或归属不匹配时返回非零。共享服务的工作目录也位于沙箱，沿用已有的禁用 `.env`、禁用 OSS 初始化设置。

## 3. 真实运行与浏览器证据

执行 `bash scripts/mvp-dev.sh start c` 后，两项健康检查均成功：

- 本地 `http://127.0.0.1:8001/api/health`：`status=ok`、`library_initialized=true`，库路径为本仓库 `.mvp-sandbox/personal-c/library`。
- 共享 `http://127.0.0.1:9000/api/health`：`status=ok`、`service=teamhub-cloud`。

在 `frontend/` 启动 Vite：

```bash
env -i PATH="$PATH" HOME="$HOME" node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort
```

通过电脑控制工具在 Chrome 新建本次验证标签页，访问 `http://127.0.0.1:5173/library`。可访问性树实际呈现了 TeamHub、欢迎回来、上述 personal-c 库路径、0 个文档及 0 B。后端日志确认页面的 `/api/settings/library`、目录、标签、待整理计数和 `/api/documents/search` 等请求返回 200，搜索 CORS 预检也返回 200。

验证中发现执行工具可能在短命令结束后回收其后台进程，因此最终通过保持启动终端会话存活完成浏览器联调。第一次后端退出后的页面网络错误没有被算作通过；以上证据来自重新启动、保持后端存活并刷新页面之后。

验证完成后已关闭本次新建标签页、停止 Vite，并通过启动器成功停止两个后端。没有通过端口号终止未知进程。

## 4. 使用与维护边界

```bash
bash scripts/mvp-dev.sh start a
bash scripts/mvp-dev.sh status
bash scripts/mvp-dev.sh stop
```

个人 A/B/C 为分别选择的沙箱库；当前固定端口一次运行一个个人后端。切换个人沙箱前先 stop，再 start。上述沙箱是开发配置隔离，不是操作系统级文件访问沙箱；不要通过资料库设置或导入操作主动选择真实敏感资料进行测试。

启动器通过 `.mvp-sandbox/launcher.lock` 串行化操作。如果启动器被不可捕获地强制终止，可能留下空锁目录；先确认没有启动器仍在运行，再用 `rmdir .mvp-sandbox/launcher.lock` 清除空锁。不会为了自动恢复而猜测或终止未知进程。

本轮不宣称 Electron 桌面壳、全平台兼容或完整业务流程通过；M1—M3 的历史审查意见仍按各自复验结果处理。M0-R01—R04 的本轮结论为已关闭。
