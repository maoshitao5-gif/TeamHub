# 推送与取回查重

更新日期：2026-10-13。适用：当前本机 MVP 的个人库、云仓库及投递附件收录。

## 使用规则

从云仓库取回文件，或收录收到的投递附件时，TeamHub 先检查当前个人库的待整理和已整理资料。实体内容相同时提示“本地已存在”，并提供“查看已有资料”。不会再复制一份，也不会新增资料、版本或替换已有来源。

推送个人资料或通过网页上传新资料时，TeamHub 检查目标云空间中你有权访问的当前资料。内容相同时提示“云端已存在”，可查看已有资料；不会因名称、标签不同或选择“另建”而重复建立资料。匹配对象的标签、作者、历史与访问范围保持原样。未获授权的资料不会出现在查重结果中。

同名但内容不同可以作为不同资料保存，不能凭名称自动合并。“本地已存在／云端已存在”表示实体内容相同，不代表两份资料的业务身份或版本来源相同，也不表示自动完成了共享关联。

## 如何延续版本

已经关联云端的资料，修改后应使用“更新原资料／提交新版本”；接收云端新内容应在本地资料详情中使用“检查并更新本地”。这样保留原资料身份、整理信息与连续历史，减少另存副本造成的版本分叉。

提交内容与云端当前版相同时沿用已有版本。接收云端内容继续遵循原有本地修改保护规则。只与历史版本相同不代表当前内容已存在；恢复历史、接收版本和提交旧内容仍按各自明确操作处理，不自动切换当前版本或删除必要历史。

## 判断范围

- 单个文件比较完整字节内容的 SHA-256；名称、路径、标签和文件类型分类不决定是否重复。
- 整套文件夹比较规范化清单中的目录结构、相对路径与文件内容；不与单个文件混判。
- 本地以实际工作内容为准，包含尚未保存为 TeamHub 版本、但已经由外部程序写入磁盘的修改。
- 本地仅检查当前个人库接管的待整理／已整理对象；缺失文件、回收站及仅存历史快照不算正在使用的实体。
- 云端仅检查目标空间中可访问、未回收资料的当前版本，不跨空间合并，不披露受限资料。
- 文件无法可靠读取或在检查中变化时明确报错；完成编辑、恢复文件可读状态后重试。

浏览器的“下载原文件”仍是普通下载，受浏览器和操作系统管理，不会扫描本机文件或自动登记到 TeamHub。要执行个人库查重，应使用桌面的“取回到个人库”或“收录投递附件”。

底层快照与云端对象继续按内容寻址复用；版本记录、资料身份与来源独立保留。本轮未删除既有重复资料或历史内容，也未进行无人确认的资料合并。
