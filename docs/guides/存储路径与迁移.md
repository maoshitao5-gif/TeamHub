# 存储路径与迁移

在桌面端「设置」中，分别点击文件库路径或待整理路径旁的「迁移」，选择新路径，预览登记资料清单，确认后保持应用运行，等待完成提示。

两个区域可以独立，也可以任一方包含另一方；不能完全相同，不能把区域根放进一份整体文件夹资料内部。

仅移动所选区域的已登记资料。另一区域保持原绝对位置，未登记文件保留原处。整体文件夹资料内部的文件、隐藏文件和空目录随资料一起移动。文件库迁移还携带数据库、版本对象和回收站；资料 ID、标签和版本历史保持不变。

迁移先复制并校验，再切换配置，最后清理原件，因此需要为复制阶段预留空间。目标同名文件不会被覆盖；缺失资料需先处理。旧位置可能保留空目录及 `.teamhub/storage-migration.json` 跳转日志，请保留该日志。

## 中断处理

重新打开设置，使用迁移恢复入口：

- 切换前中断：取消任务，继续使用原位置；目标中已复制的内容保留，重试请选择空目录。核对后可自行清理废弃副本。
- 切换后中断：继续校验并清理旧副本。内容发生变化时保留原件并提示，不能视为完整清理成功。

迁移前关闭操作同一库的其他实例及正在编辑这些资料的软件；迁移期间不要手工修改、移动或删除相关文件。此操作不影响组织服务器上的共享资料。

## 备份边界

现有维护备份工具按文件库根目录备份。待整理区放在库外后，需另外备份该目录；原有个人库备份不能视为两个区域的完整备份。
