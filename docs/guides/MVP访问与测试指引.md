# TeamHub MVP 访问与测试指引

适用：当前这台 Mac，项目位于 `/Users/maoshitao/开发项目库/TeamHub`。更新：2026-10-15。

推荐使用 **桌面端管理个人资料，浏览器体验云端协作**。现有桌面包和网页已构建，无需重新安装依赖。

推荐双击[启动TeamHub.app](../../启动TeamHub.app)，此入口直接运行启动检查，不唤起Terminal。主窗口打开表示就绪；失败时会显示错误和 `.mvp-sandbox/logs-desktop.log` 路径。原 `.command` 仍需Terminal响应，仅作为兼容入口。无需切换到audit目录中的旧验收包。

## 日常试用：默认9000云库

无需隔离云库时，优先使用默认9000服务：

1. 双击 [开通云端账号.app](../../开通云端账号.app)，无需Terminal；首次选择“系统管理员（首次使用）”，随后可选择“普通成员”。
2. 输入登录邮箱、名称和两遍密码，确认后开通。邮箱只是登录名，不发送邮件；密码隐藏输入，没有默认密码，也不会覆盖已有账号。
3. 登录 [云端资料库](http://127.0.0.1:9000/cloud.html)，选择 **MVP团队 / 组织资料**；系统管理员另可登录 [管理后台](http://127.0.0.1:9000/admin.html)。桌面云服务地址填写 `http://127.0.0.1:9000`。

该界面是本机维护入口，只管理 `.mvp-sandbox/shared-server/cloud.db`。数据库须已初始化到005，入口不会自动建库或迁移，也不启动云服务；服务启动及A/B/C路线见[本机启动指引](MVP本机试用启动指引.md)。网页公开注册仍停用，受限资料仍须明确授权。重建界面使用 `npm run accounts:build`。

**下文第1—6节是独立19000云库的备用隔离测试路线。开通云端账号.app不管理这套库；9000账号不能直接用于19000。**

## 1. 三个入口

| 入口 | 如何打开 | 用途 |
| --- | --- | --- |
| 个人桌面端 | 双击项目根目录的 `启动TeamHub.app` | 收录、整理、标签、文件夹、收藏、本地版本、共享及投递 |
| 云端普通网页 | 云服务启动后访问 `http://127.0.0.1:19000/cloud.html` | 浏览、上传、下载组织资料，指定共享、版本与收发件箱 |
| 管理后台 | 云服务启动后访问 `http://127.0.0.1:19000/admin.html` | 系统管理员查看账号、团队等管理信息 |

本指引特意使用 **19000端口** 和 `.mvp-sandbox/access-trial/cloud/` 独立试用云库。10月5日核对时，默认shared-server是无迁移标记的旧结构；10月13日已在确认其业务表为空后保留原库备份、恢复为005，9000服务可用。此处继续使用19000隔离账号试用，不与默认9000库混用。

本指引的19000账号与服务尚未替你创建或启动。这里的网页链接要在第3节启动成功后才能访问；自动化测试临时账号也不等于这些试用账号。

## 2. 独立19000云库：首次创建试用账号（只做一次）

打开终端，复制执行下面整段。它只在新的试用云库中创建管理员、A和B三个账号。

```bash
(
  set -e
  cd "/Users/maoshitao/开发项目库/TeamHub"
  export TEAMHUB_SANDBOX=1
  export DATABASE_URL="sqlite:///$PWD/.mvp-sandbox/access-trial/cloud/cloud.db"
  export STORAGE_DIR="$PWD/.mvp-sandbox/access-trial/cloud/storage"
  mkdir -p "$STORAGE_DIR"
  cd cloud_backend
  venv/bin/python manage.py init
  venv/bin/python provision_mvp.py --email admin@mvp.example --name 试用管理员 --team-slug access-trial --team-name MVP试用团队 --workspace-name 试用资料库 --role owner --system-admin
  venv/bin/python provision_mvp.py --email a@mvp.example --name 试用A --team-slug access-trial --team-name MVP试用团队 --workspace-name 试用资料库
  venv/bin/python provision_mvp.py --email b@mvp.example --name 试用B --team-slug access-trial --team-name MVP试用团队 --workspace-name 试用资料库
)
```

每个账号输入两遍自己设置的密码，至少8个字符。输入时终端不显示字符是正常现象。邮箱只是登录名，不会发送邮件；系统没有默认密码。

| 账号 | 角色和建议用途 |
| --- | --- |
| `a@mvp.example` | 普通成员，整理并发布/投递资料 |
| `b@mvp.example` | 普通成员，接收、查找和下载资料 |
| `admin@mvp.example` | 系统管理员及团队owner，访问管理后台 |

三个命令分别输出账号、团队、空间ID才表示全部创建成功。若提示“账号已存在”，不会重置密码；不要整段重复执行。部分成功时，在相同环境配置下只执行尚未创建账号的那一条命令。网页公开注册目前未开放。

## 3. 启动云端（每次测试）

终端复制执行：

```bash
(
  cd "/Users/maoshitao/开发项目库/TeamHub" || exit 1
  export TEAMHUB_SANDBOX=1
  export DATABASE_URL="sqlite:///$PWD/.mvp-sandbox/access-trial/cloud/cloud.db"
  export STORAGE_DIR="$PWD/.mvp-sandbox/access-trial/cloud/storage"
  export CLOUD_WEB_DIST="$PWD/frontend/dist"
  exec cloud_backend/venv/bin/python -m uvicorn main:app --app-dir "$PWD/cloud_backend" --host 127.0.0.1 --port 19000
)
```

看到 `Application startup complete` 后，打开普通网页，用A或B登录，选择 **MVP试用团队 / 试用资料库**。测试期间保留该终端运行；结束时按 **Control+C** 停止云服务。

这里的“云端”仍在你的本机，只监听本机回环地址，不是公网或正式内网部署。资料存放在项目下 `.mvp-sandbox/access-trial/cloud/`，重启后保留。

## 4. 打开桌面并连接该云端

1. 双击项目根目录 [启动TeamHub.app](../../启动TeamHub.app)。也可在Finder打开 `dist-electron/mac-arm64/TeamHub.app`。
2. 桌面沿用原有个人库，**不会自动切换成空试用库**。先准备3—5份资料副本测试；收录/拖拽会移动所选源文件。
3. 打开 **设置 → 云服务**，将云服务地址设为 `http://127.0.0.1:19000`，点击保存。只填服务根地址，不带 `/cloud.html`。
4. 点击“前往登录”，使用 `a@mvp.example` 及自己设置的密码，进入云仓库。单库自动进入，多库点击卡片；顶部“共享资料库”可直接切换，无需绑定。详见[共享资料库使用指引](共享资料库使用指引.md)。

本地整理不需要云端运行或登录。换云地址后要重新登录；桌面账号与网页账号分别登录。**退出账号不会切换个人文件库**，不要把同一桌面库误当成A、B各自独立的电脑。

模拟两人最方便的方式：桌面登录A，浏览器登录B。若同时测试网页A与B，使用普通窗口和无痕窗口，或不同浏览器；同一个浏览器配置中的两个普通标签页共享登录会话。

访问令牌正常到期后，桌面会自动续期。只有登录确实失效时，界面显示 **“云服务登录已失效，请重新登录”** 和入口；重新登录后返回原云端页面，个人文档库仍可独立使用。2026-10-15 修复前已撤销的旧刷新凭据需要重新登录一次；更新后先正常退出旧桌面实例，再通过一键入口打开新包。服务暂时不可用时可以稍后重试，不应反复要求重新登录。

## 5. 建议按这个顺序试用

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1. 收录 | 将副本拖入桌面，或待整理中选择“收录本机文件” | 文件移入待整理，原位置不再保留；可撤销移回 |
| 2. 整理 | 添加自由标签，完成整理 | 资料进入文档库“全部资料”；待整理中消失 |
| 3. 分类与收藏 | 归入文件夹、移出文件夹、收藏再取消 | 操作不删除资料，“全部资料”始终保留 |
| 4. 本地版本 | 编辑工作文件，保存新版本，再恢复v1 | 工作内容恢复v1；恢复本身不虚增版本，未保存修改会先保护 |
| 5. 共享 | A发布资料，明确选“空间全体成员” | B网页可搜索并下载；本地原资料和云副本独立 |
| 6. 指定共享 | A另发资料，只授权B查看 | B能查到；未授权的管理员不能默认读取；B只读时不能提交新版 |
| 7. 云端新版 | A将指定资料的B设为协作者，B网页提交新版本 | A本地不会自动覆盖；主动“检查并更新本地”后采用远端内容并保留历史 |
| 8. 投递与撤回 | A从资料详情投递给B，B查看收件箱；A再撤回 | B无需搜索即可看到提醒；撤回后不能新下载，已下载副本不被删除 |
| 9. 本地收录投递 | 在桌面明确登录收件账号，选择“收录到待整理” | 主动收录才生成本地资料；仅收到提醒不会自动入库 |
| 10. 离线与重启 | 停云后继续本地整理，再退出并重开桌面 | 本地功能仍可用，已保存资料与版本保留 |

第9步若在同一桌面换成B，仍然使用原个人库，只验证收录动作；真正的多人个人库隔离应使用另一台电脑或独立桌面profile。

## 6. 常见问题与退出

- **网页打不开：**确认第3节终端仍在运行，地址是19000。可打开 `http://127.0.0.1:19000/api/health` 检查服务；API地址本身不是用户界面。
- **提示端口占用：**不要强行结束未知进程。若改用19001，启动命令、两个网页地址及桌面云服务地址都要一起改。
- **没有账号/登录失败：**自动化测试临时账号不是你的试用账号；使用第2节创建的账号和自设密码。管理后台只允许系统管理员登录。
- **提示数据库需要升级：**核对是否误用了旧shared-server路径；本指引的新云库应使用005。旧库升级另见[迁移指引](云端与投递启动及迁移指引.md)，不要删除旧库来消除报错。
- **桌面未打开：**查看启动弹框和 `.mvp-sandbox/logs-desktop.log`，后端日志为 `~/Library/Application Support/teamhub-desktop/logs/backend.log`。若系统提示Terminal无响应，改用上述 `.app` 入口；当前包已验证本机ad-hoc资源签名，未作Apple发行签名/公证。
- **结束测试：**桌面用 **⌘Q** 退出，云端终端按 **Control+C**。根目录“停止本地测试.command”只停止启动器管理的服务，不负责停止本指引手动启动的19000云服务。
