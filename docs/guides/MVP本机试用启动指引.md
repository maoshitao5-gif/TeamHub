## 资料导航与收藏

文档库左侧分为「全部资料」「收藏」及「文件夹」。前两者始终可达，文件夹导航可在设置中隐藏；名称、标签、类型筛选适用于各列表。

- 在已整理资料的更多菜单或详情中选择「收藏资料」，即可从收藏入口直达；取消收藏只移除引用，资料仍在全部资料中。
- 从「全部资料」的资料卡片更多菜单选择「归入文件夹」，选择已有分类，或点击目录旁的加号新建分类，再点击「确认归入」。已归类资料也可通过此入口更换分类，标签、版本、收藏不变。分类目录与作为一份完整资料管理的整体文件夹不同，不能把其他资料归入后者内部。
- 分类文件夹内的资料通过更多菜单选择「移出文件夹」，确认后移到库根目录，保留已整理状态、标签、收藏和历史版本。同名内容存在时拒绝覆盖。
- 待整理资料需先完成整理。已收藏资料退回待整理或进入回收站后不在收藏列表显示；恢复为已整理后原收藏再次显示。
- 「移出文件夹」针对分类目录中的完整资料对象，不拆分整体文件夹资料内部文件。

设置中修改文件库或待整理目录的步骤与恢复说明，见[存储路径与迁移](存储路径与迁移.md)。

适用：当前这台 macOS ARM64 电脑，以及 `/Users/maoshitao/开发项目库/TeamHub` 项目。更新日期：2026-10-13。

**日常桌面试用：双击根目录 `启动TeamHub.app`。它独立打开 Electron 及个人后端；需要本机云端时另运行 `bash scripts/mvp-dev.sh cloud`，沿用桌面原有个人库；首次账号准备见第 2 节。浏览器试用见第 3 节。两种方式不要同时管理同一个个人库。** 当前电脑已有依赖与打包产物，通常无需重新安装或构建。

## 1. 先了解这次试用怎么运行

所有资料和服务都在本机，不需要部署内网服务器。页面中的“云仓库”“云服务”指本机组织共享服务，并不表示文件上传到公网。

| 组成 | 用途 | 本次位置 |
| --- | --- | --- |
| 浏览器界面 | 查看、整理、共享资料 | 通常 `http://localhost:5173` |
| 个人后端 | 管理当前个人库 | `http://127.0.0.1:8001` |
| 组织共享后端 | 保存组织副本、共享标签与权限 | `http://127.0.0.1:9000` |
| A/B/C 个人库 | 模拟三个人各自的私人资料 | `.mvp-sandbox/personal-a/library`、`personal-b/library`、`personal-c/library` |
| 组织共享库 | 三个人共同访问的组织资料 | `.mvp-sandbox/shared-server/` |

启动器一次运行一个个人库，可以顺序切换 A、B、C 模拟协作。**退出登录只切换共享账号，不会切换个人文件库。** 后文会同时切换库和账号，避免把“换账号”误认为“换人”。

先准备 3—5 份可用于试验的资料副本：一份文本/Word 文件、一份 PDF、一个小文件夹即可。第一轮先跑通流程，不必导入整个资料库。

## 2. 首次准备账号——只做一次

如果已经有可用账号、账号所在团队和工作空间，可跳过本节。自动化验收用的临时账号不等于你的本机试用账号；本指引不会预置或公布默认密码。

### 2.1 日常开通：无终端入口（推荐）

1. 双击项目根目录 [开通云端账号.app](../../开通云端账号.app)。
2. 第一个账号选择 **“系统管理员（首次使用）”**；输入登录邮箱、显示名称和两遍密码，核对信息后点击“确认开通”。
3. 再次打开入口，选择 **“普通成员”**，可为A、B、C分别开通账号。邮箱只是登录名，不会发送邮件；密码至少8个字符，输入框不显示密码。
4. 打开 [云端资料库](http://127.0.0.1:9000/cloud.html)，使用刚设置的账号登录，选择 **MVP团队 / 组织资料**。管理员另可访问 [管理后台](http://127.0.0.1:9000/admin.html)。

这是共享服务所在电脑的维护入口，固定操作 `.mvp-sandbox/shared-server/cloud.db`，不管理19000独立试用库。数据库须已初始化到005；入口不自动建库或迁移。已存在的账号会被拒绝，不会覆盖密码或提升权限。管理员也不能默认查看受限资料，仍须明确授权。界面缺失时可在项目根目录运行 `npm run accounts:build` 重建。

后文A/B/C路线以 `trial-admin@example.com`、`trial-a@example.com`、`trial-b@example.com`、`trial-c@example.com` 为示例；可在界面使用这些邮箱，也可使用自己的邮箱并替换后文账号。系统没有默认密码。默认云服务未运行时按第3节启动，开通界面本身不会启动云服务。

### 2.2 多人测试备用：维护者 CLI

以下命令与上述界面使用同一默认9000数据库和 **MVP团队 / 组织资料**。已有账号无需重复创建；只执行尚未创建的账号命令。若已有旧 `trial` 团队，它仍保留自己的账号和“试用资料库”，不会自动合并到MVP团队。

打开终端，进入项目：

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
```

如果之前用本项目启动器运行过服务，先停止它管理的服务：

```sh
npm run dev:stop
```

该命令不删除资料，也不会结束未知归属的服务。若桌面版正在运行，也先用 **⌘Q** 退出它。

在同一个终端复制执行下面整段：

```sh
(
  cd "/Users/maoshitao/开发项目库/TeamHub" || exit 1
  mkdir -p .mvp-sandbox/shared-server/storage
  export TEAMHUB_SANDBOX=1
  export DATABASE_URL="sqlite:///$PWD/.mvp-sandbox/shared-server/cloud.db"
  export STORAGE_DIR="$PWD/.mvp-sandbox/shared-server/storage"
  cd cloud_backend || exit 1

  venv/bin/python provision_mvp.py --email trial-admin@example.com --name 试用管理员 --team-slug mvp --team-name MVP团队 --workspace-name 组织资料 --role owner --system-admin
  venv/bin/python provision_mvp.py --email trial-a@example.com --name 试用A --team-slug mvp --team-name MVP团队 --workspace-name 组织资料
  venv/bin/python provision_mvp.py --email trial-b@example.com --name 试用B --team-slug mvp --team-name MVP团队 --workspace-name 组织资料
  venv/bin/python provision_mvp.py --email trial-c@example.com --name 试用C --team-slug mvp --team-name MVP团队 --workspace-name 组织资料
)
```

执行过程中，每个账号分别输入两遍密码。终端不会显示输入的字符，这是正常现象。使用至少 8 个字符的密码并自行记住；邮箱只是登录名，不会发送邮件。

每个账号成功后会输出 `user_id`、`team_id`、`workspace_id` 等信息。四个账号应属于同一个团队和空间。若某一步失败，先看错误，不要认为整段已经全部成功。

| 登录账号 | 用于体验 |
| --- | --- |
| `trial-a@example.com` | 收录、整理、发布资料 |
| `trial-b@example.com` | 获取资料、补充标签 |
| `trial-c@example.com` | 用别人的标签找到资料 |
| `trial-admin@example.com` | 共享回收站、恢复和成员停用 |

提示“该账号已存在”表示命令没有覆盖原账号，也没有修改原密码。已有账号不用重复创建；忘记密码时不要删数据库重新开始，可另行处理账号恢复。

公开注册在当前 MVP 中停用，登录页提示联系组织管理员，使用上述本机界面或维护者CLI开通。

## 3. 启动浏览器版——每次试用

### 3.1 浏览器启动

在仓库根目录执行 `npm run dev:browser`。该命令启动个人服务、组织共享服务和前端，检查就绪后打开 **http://127.0.0.1:5173**。根目录 `启动本地测试.command` 现在启动桌面版，不再作为浏览器入口。

全新启动默认使用 A 的个人库；如果 8001 被其他程序占用，启动器会选择 8001—8010 中空闲端口，保持占用者运行。若已有本启动器管理的健康服务，则复用当前个人库和共享服务，不会切换 A/B/C。重复双击不会启动第二套服务。它不会创建或重置账号，首次账号准备仍按第 2 节执行。

桌面版占用 8001 时，启动器会自动选择其他个人 API 端口，并继续保留桌面版运行；若 5173 已被其他程序占用，启动器会提示冲突，不会关闭该程序。

### 3.2 命令行等价入口和日志

浏览器入口为 `npm run dev:browser`。查看状态使用 `npm run dev:status`，停止使用 `npm run dev:stop`。

启动失败会保留终端提示。详细日志位于：

- 个人服务：`.mvp-sandbox/personal-a/logs-local-backend.log`（B/C 使用相应目录）。
- 共享服务：`.mvp-sandbox/shared-server/logs-cloud-backend.log`。
- 前端：`.mvp-sandbox/logs-frontend.log`。

若提示缺少依赖，按仓库 README 安装；一键入口不会自动下载依赖或修改资料。

### 3.3 确认个人库并登录

1. 欢迎页面中确认路径为 A 的沙箱库，点击 **“打开文件库”**。
2. 如果出现初始化页面，填入 `/Users/maoshitao/开发项目库/TeamHub/.mvp-sandbox/personal-a/library`，点击 **“开始使用”**。不要选择真实资料库替代沙箱。
3. 点击右上角设置齿轮，找到 **“云服务” → “云服务地址”**。
4. 填写 `http://127.0.0.1:9000`，点击 **“保存”**。
5. 点击 **“前往登录”**，使用 `trial-a@example.com` 和你设置的密码登录。
6. 登录后进入 **“云仓库”**，只有一个资料库会自动进入；有多个时点击对应资料库卡片。顶部显示 **“MVP团队 / 组织资料”**，可直接切换，无需绑定。沿用旧trial账号时选择其原资料库。
7. 应看到共享资料页面。新资料库没有资料是正常的；没有可访问资料库则联系管理员。

首次准备完成。下次启动后可能自动恢复账号；仍需核对当前个人库与账号是否匹配。

## 4. 建议按这条路线试用

### 第一步：A 收录、整理和查找

1. 打开 **“待整理” → “收录本机文件”**。
2. 输入试验文件的完整路径，例如 `/Users/你的用户名/Desktop/试用资料/检修说明.txt`，点击“收录”。路径不要额外加引号。
3. 系统将文件移动到个人库的待整理，并保存首版快照。关闭详情后，在待整理列表点击 **“整理”**。
4. 添加几个自己理解的标签，例如 `1号主变`、`检修`、`运行部`，点击 **“完成整理”**；存放文件夹可选。
5. 到 **“文档库”** 用名称或标签查找这份资料，并体验个人收藏。

在 Finder 中选中文件，按 **⌥⌘C** 可复制完整路径。浏览器模式没有桌面的原生打开文件能力，收录以手动输入路径为准。

观察重点：不记得文件夹分类时，能否用行业线索找到资料？不必追求只剩一个结果。

### 第二步：A 保存版本

1. 从资料详情查看其个人库工作文件路径，在 Finder/编辑器中打开**库内副本**。
2. 修改内容并保存，然后回到资料详情。
3. 在 **“个人版本历史”** 点击 **“检查工作文件修改”**，填写说明后点击 **“保存新版本”**。
4. 应看到 v1、v2 及当前版标记；可用 **“导出此版本”** 检查 v1 仍是原内容。

拖拽和快速收录采用移动，之后请编辑个人库内的工作文件。**点击“恢复到此版本”后，工作文件立即切换为所选版本，可直接打开使用。未保存修改会先自动保存为保护版本，原有历史版本继续保留。**

在“个人版本历史”中，可对非当前版本点击“删除版本”。确认后该版本从列表移除，不能再通过历史列表恢复或导出；当前版本和工作文件保留。此操作暂不清理底层快照文件，因此不等同于释放磁盘空间。

### 第三步：A 主动共享

1. 在文档库找到资料，打开右侧“…”菜单。
2. 选择 **“发布 / 更新共享资料”**。
3. 在对话框选择 **“发布到”** 的资料库，核对共享范围和标签，点击 **“确认共享”**；更新已有资料时核对固定显示的原位置。
4. 到“云仓库”确认这份资料已经可见。

首次发布会取当前工作内容并冻结为本次请求，先检查实体重复；成功后保存对应个人版本与共享关联。后续更新仍需明确操作，响应丢失的重试沿用原请求，不会重新取变化后的工作文件。详见[推送与取回查重](推送与取回查重.md)。

### 第四步：切换为 B，取回并补标签

需要模拟其他人的个人库时，在一个终端执行以下命令：

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
bash scripts/mvp-dev.sh stop
bash scripts/mvp-dev.sh start b
npm run dev:browser
```

刷新浏览器页面，确认个人库变成 `personal-b/library`。首次使用 B 时，重复第 3.3 节设置共享地址、登录 `trial-b@example.com`、进入同一个“组织资料”库。如果仍显示旧账号，先退出登录，再登录 B。

1. 到“云仓库”找到 A 发布的资料。
2. 点击 **“取回到个人库”** 并确认，检查 B 的文档库中出现个人副本。
3. 返回共享资料详情，补充一个 A 尚未使用的标签，例如 `年度停电计划`。
4. 确认新增标签显示 B 为贡献者；B 可以撤销自己的标签，不能撤销 A 的标签。

### 第五步：切换为 C，用 B 的标签找到资料

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
bash scripts/mvp-dev.sh stop
bash scripts/mvp-dev.sh start c
npm run dev:browser
```

刷新页面，确认 `personal-c/library`，设置同一个共享服务地址，登录 `trial-c@example.com` 并选择同一空间。

1. 到“云仓库”的标签框输入 `年度停电计划`，选择联想出的标签。
2. 检查能否找到 A 发布的那份资料。
3. 打开详情，体验 **“收藏此共享资料”**，再从 **“共享收藏”** 重新打开。
4. 尝试取回当前版或某个历史版到 C 的个人库。

**这一段是本次最值得验证的核心：B 顺手补充的线索，是否真正帮助 C 找到了同一份资料。**

### 第六步：管理员回收与恢复（可选）

在当前个人库退出共享账号，登录 `trial-admin@example.com`，进入相同空间：

1. 对试验资料执行 **“移入共享回收站”**，确认普通查找不再显示。
2. 到 **“共享回收站”** 恢复资料，确认可以再次找到。
3. 若要体验停用账号，进入 **“成员账号”**，选择一个试用成员。停用影响该账号全部空间，但保留其资料和贡献。

第一轮只需体验回收与恢复；永久删除可以等确认资料不再需要时再试。管理员在这里用于组织操作，登录管理员不会把当前 C 的个人库切成另一个库。

## 5. 正常退出、再次启动和保留数据

结束时双击根目录 **`停止本地测试.command`**，即可停止本启动器管理的三个服务。仅关闭网页或终端窗口不会停止后台服务。

停止不会删除资料、标签、版本或账号。下次执行 `npm run dev:browser` 即可继续使用 A 的浏览器沙箱库；需要 B/C 时使用第 4 节的切换命令。仍可用 `npm run dev:stop` 停止。

**不要删除 `.mvp-sandbox/` 来“重启”。** 它保存本次试用数据；也不要把本机测试脚本生成的临时账号或截图目录当成正式试用库。

开始积累重要试用记录后，按 [MVP运维与交接](MVP运维与交接.md) 第 3—4 节停写备份。设置页已移除旧云端数据库备份入口，显示维护者停写备份提示。

## 6. 想体验桌面版时

桌面版使用同一套个人与共享功能，额外提供本机文件打开等桌面能力。当前已生成本机测试产物，无需重新打包。

### 6.1 日常使用：一键启动（推荐）

双击项目根目录 [启动TeamHub.app](../../启动TeamHub.app)，无需打开 Terminal；`启动本地测试.command` 保留为兼容入口。启动器不依赖云端，优先打开 `dist-electron/document-cards-2026-10-21/mac-arm64/TeamHub.app`，缺失时依次回退此前的 `preorganize-format-fix-2026-10-21`、`security-audit-2026-10-21`、`ai-preorganize-2026-10-20`、`ai-natural-chat-2026-10-19`、`hermes-connection-fix-2026-10-18` 下的同名包，最后使用 `dist-electron/mac-arm64/TeamHub.app`。Electron 自己管理个人后端和按需启动的 Hermes，无需 Vite 或额外终端。重复双击会激活应用主窗口。先按 ⌘Q 正常退出旧版本，再启动新版；伙伴配置与功能见[使用指引](AI智能伙伴使用指引.md)，整理流程见[AI 预整理指引](AI预整理使用指引.md)，新增的理解保存、检索与更新见[AI 资料卡指引](AI资料卡使用指引.md)，本轮工程结果见[资料卡与 Skill 验收](../reviews/AI资料卡与Skill验收-2026-10-21.md)。

个人库沿用桌面版已配置的路径，不会自动切换为浏览器 A 库。退出桌面请按 **⌘Q**，再双击 `停止本地测试.command` 停止启动器管理的服务；停止脚本不会退出桌面应用。启动错误会弹窗提示，个人后端日志位于 `~/Library/Application Support/teamhub-desktop/logs/backend.log`。

以下 6.2—6.3 仅用于开发人员隔离 A/B/C 库的手动启动。开始前执行 `npm run dev:stop` 并按 ⌘Q 退出已有桌面，避免同时打开同一库。

### 6.2 终端一：单独运行共享服务

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
env TEAMHUB_SANDBOX=1 \
  DATABASE_URL="sqlite:///$PWD/.mvp-sandbox/shared-server/cloud.db" \
  STORAGE_DIR="$PWD/.mvp-sandbox/shared-server/storage" \
  cloud_backend/venv/bin/python -m uvicorn main:app \
  --app-dir "$PWD/cloud_backend" --host 127.0.0.1 --port 9000
```

保持终端运行。此服务使用前面准备的同一份组织库和账号。

### 6.3 终端二：打开桌面产物，指定 A 的试用库

```sh
cd "/Users/maoshitao/开发项目库/TeamHub"
mkdir -p .mvp-sandbox/personal-a/library .mvp-sandbox/desktop-profile-a
env -u ELECTRON_RUN_AS_NODE \
  TEAMHUB_SANDBOX=1 \
  TEAMHUB_USER_DATA_DIR="$PWD/.mvp-sandbox/desktop-profile-a" \
  LIBRARY_PATH="$PWD/.mvp-sandbox/personal-a/library" \
  TRASH_AUTO_CLEAN_DAYS=0 \
  "$PWD/dist-electron/document-cards-2026-10-21/mac-arm64/TeamHub.app/Contents/MacOS/TeamHub"
```

这样不会误用默认应用 profile 或其他个人库。进入后确认 A 库，登录 A，必要时按第 3.3 节设置共享服务地址和空间。

若要换 B/C，先 **⌘Q** 退出应用，把命令中的 `personal-a` 和 `desktop-profile-a` 同时换成 b/c 后再启动。不要让浏览器个人后端和桌面后端同时管理这一库。

桌面退出用 **⌘Q**，仅关主窗口在 macOS 上不等于退出应用。共享服务单独在终端一按 **Ctrl+C** 停止；它不是由 `mvp-dev.sh` 启动的，因此不使用 `dev:stop` 管理这个手动进程。

该 `.app` 已完成本机 ad hoc 签名和实测，尚未进行开发者分发签名或公证。如果系统阻止打开，先记录提示；不要修改系统整体安全设置。

## 7. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 8001 或 9000 已占用 | 是否已有本项目沙箱或桌面运行；沙箱用 `dev:status` 查看、`dev:stop` 停止，桌面用 ⌘Q。未知服务不要直接终止 |
| 网页打不开 | 双击启动后是否显示就绪；访问 127.0.0.1:5173，必要时检查 .mvp-sandbox/logs-frontend.log |
| 页面提示网络错误 | `npm run dev:status` 是否两个服务都正常；浏览器是否使用 5173/5174 |
| 账号登录失败 | 是否真的完成本机开通；密码是否正确；云服务地址是否为 `http://127.0.0.1:9000` |
| 已登录却没有共享资料 | 是否选了相同的团队和“组织资料”空间；A 是否已确认共享，而不仅是收录到私人库 |
| 换成 B 后仍看到 A 的个人资料 | 只换了账号，没有切库；按第 4 节 stop/start b，并刷新页面核对库路径 |
| 文件修改后版本没变化 | 是否编辑了库内工作副本；是否点击“保存新版本” |
| 无法用浏览器直接打开本机文件 | 浏览器能力限制；从 Finder 手动打开详情中的路径，或使用桌面版 |
| 点击旧云端备份/注册提示已停用 | 属于明确停用的旧入口；按本指引开通账号，按维护脚本备份 |
| 依赖缺失或 .app 不存在 | 按 [README](../../README.md) 的依赖安装/构建步骤恢复环境，不删数据目录 |

需要反馈时，记录：**当前 A/B/C 库、登录账号、点击路径、预期结果、实际提示**。不要提供密码或令牌。

沙箱个人日志：`.mvp-sandbox/personal-a/logs-local-backend.log`（B/C 替换字母）；共享日志：`.mvp-sandbox/shared-server/logs-cloud-backend.log`。

### 拖拽收录行为（2026-09-29 更新）

拖入主窗口或悬浮窗的本地文件会移动到个人库“待整理”，保存首版快照。通知中的“撤销”将文件移回原路径；原路径已存在其他文件时拒绝覆盖。内容重复时不移动原件。整个文件夹收录会移动整个目录；选择打散时逐项移动成功收录的文件，未处理、重复文件及原目录保留。个人库内部资料请使用库内整理功能，不能再次拖入移动。此操作不上传组织服务器。


### 标签优先的整理流程（2026-09-29 更新）

在“待整理”点击“整理”，选择或输入至少一个查找标签，点击“完成整理”即可。已有标签会带入，名称可以保留原样。默认直接放入资料库顶层，不必创建分类文件夹。

同一项目、成套图纸等需要一起使用的资料，可展开“文件夹（可选）”选择或新建收纳文件夹；取消选择即可回到默认。整套文件夹作为一项资料整理，内部目录不打散。批量整理为所选资料追加共同标签，保留各自原有标签。

拖入文件夹时默认主操作为“整套收录”，零散资料仍可主动选择“拆开整理”。整理后通过文档库标签查找；“文件夹浏览”仅是辅助浏览方式。
