# MVP 运维与交接

更新：2026-10-13。适用：本机 macOS ARM64 MVP；不是服务器正式上线手册。产品与权限决策以基石、蓝图和接口契约为准。

## 1. 数据根与启动

本地浏览器验证优先使用 `bash scripts/mvp-dev.sh start a`，沙箱内个人库与共享库分离。`stop` 后可 `start b` 或 `start c` 切换个人库；该启动器每次只运行一个个人端。M6 的四账号集成测试另用随机端口同时运行四个独立库。

查看 `bash scripts/mvp-dev.sh status` 输出；个人日志在 `.mvp-sandbox/personal-a/logs-local-backend.log`（B/C 对应替换目录），共享日志在 `.mvp-sandbox/shared-server/logs-cloud-backend.log`；不要根据端口号终止未知服务。浏览器前端另用 `npm run frontend:dev`。本地 API 为 `/docs`，通常是 `http://127.0.0.1:8001/docs`；共享 API 通常是 `http://127.0.0.1:9000/docs`。

需要自选数据根时，先创建目录，再在共享服务终端明确设置环境变量。示例中的绝对路径须替换为维护者准备的独立目录：

```sh
export TEAMHUB_SANDBOX=1
export DATABASE_URL=sqlite:////绝对路径/teamhub-shared/cloud.db
export STORAGE_DIR=/绝对路径/teamhub-shared/storage
export JWT_SECRET_KEY=替换为维护者单独保存的随机签名密钥
cd cloud_backend
venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 9000
```

`TEAMHUB_SANDBOX=1` 表示只使用明确环境配置，不读取仓库 `.env`；并非增加用户权限。新库启动创建结构；旧库先执行第 5 节副本迁移流程。MVP 共享启动不再访问旧 OSS 服务。

个人服务也可明确配置 `LIBRARY_PATH=/绝对路径/个人库` 后运行仓库 `venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8001`。不要让两份个人后端同时管理同一个库。个人库 `.teamhub/config.json` 中 `cloud_api_url` 指向共享服务；保留已有配置，只修改该字段，切勿用新 JSON 覆盖凭据及其他设置。

桌面通过 `TEAMHUB_USER_DATA_DIR` 支持独立应用 profile；未设置时使用 Electron 的用户数据目录。正式 `.app` 使用打包后端，动态端口由预加载桥在页面请求之前提供，不应手工固定前端为 8001。本地 HTTP 仅绑定回环地址。打包的 file:// 页面 Origin 为 null，仅桌面模式允许此来源；这不等于开放个人服务到局域网。

## 2. 开通与维护成员

### 2.1 默认本机库：无终端开通

维护者双击根目录 [开通云端账号.app](../../开通云端账号.app)，首次选择“系统管理员（首次使用）”，后续选择“普通成员”，输入登录邮箱、名称和两遍密码，核对角色后确认开通。管理员对应系统管理员及MVP团队owner；受限资料仍需明确授权。密码使用隐藏输入框，不进入命令参数或日志；邮箱只是账号名，不发送邮件。

该入口固定连接 `.mvp-sandbox/shared-server/cloud.db`，团队为 `mvp` / `MVP团队`，空间为 `组织资料`，仅用于默认9000本机服务；它不管理独立19000 `access-trial` 云库或自定义服务器目录。数据库须已存在且结构为005，界面只检查现状和开通账号，不运行初始化或迁移，也不覆盖已有账号。使用此入口无需停止已运行的默认云服务；账号提交复用维护者工具的事务开通逻辑。

登录入口：[云端资料库](http://127.0.0.1:9000/cloud.html)、[管理后台](http://127.0.0.1:9000/admin.html)。应用本身不启动云服务，仍需服务运行后访问网页。源码为 `scripts/cloud-account-setup.applescript` 与 `cloud_backend/account_setup.py`，项目根目录执行 `npm run accounts:build` 重建。生成的 `.app` 不提交到源码仓库。

### 2.2 服务器、自定义库及高级角色：维护者 CLI

公开注册仍被停用，管理后台没有新增账号入口。其他数据库或viewer、团队admin等角色使用共享服务器本机的维护者CLI。先停止对应共享服务，在与它相同的 `DATABASE_URL` / `STORAGE_DIR` / `TEAMHUB_SANDBOX` 环境中执行：

```sh
cd cloud_backend
venv/bin/python provision_mvp.py --email admin@example.com --name 管理员 --role owner --system-admin
venv/bin/python provision_mvp.py --email member@example.com --name 成员
```

密码在终端隐式输入并二次确认，不放入命令历史。默认团队 slug 为 `mvp`、名称为 `MVP团队`、空间为 `组织资料`，可用命令参数修改。首次建立团队必须有 owner/admin；后续成员复用相同团队和空间。命令拒绝覆盖现有账号，不会无提示重置密码或提权。

- member：发布、取回、补标签、撤销自己的标签贡献。
- viewer：只读访问。
- admin/owner：额外管理共享标签和回收站。
- system-admin：额外全局停用账号；这影响该账号所有空间，不能授予普通空间管理员代行。

停用保留组织资料、版本与贡献，撤销刷新令牌。恢复账号不会复活旧刷新令牌；本版没有 token epoch，不承诺恢复账号后未到期旧访问令牌永久失效。停用用户可在系统管理界面的状态开关重新启用；自停用/自降级被拒绝。组织成员日常权限维护继续使用已有团队成员接口，不能直接删除用户表记录。

## 3. 备份内容及一致性边界

备份是维护操作：**先停止对应服务与外部编辑，再传 `--services-stopped`**。该标志是维护者对停写前提的明确确认，脚本不会自动查杀服务或宣称能锁住外部编辑器。

备份复制窗口额外持有 SQLite 写锁，使用 SQLite backup API 包含已提交 WAL 数据。逐项校验文件内容、大小与目录集合，复制失败不发布正式备份。源与目标不能相同、互相包含或经过符号链接；不要将备份放入个人库内。

| 类型 | 保存 | 不保存 |
| --- | --- | --- |
| 个人 | 资料与关系数据库、全部受管快照、库内工作文件（包括未保存修改）、空目录、回收站、非凭据配置白名单 | 访问/刷新令牌及未知配置字段、库外 index 引用的原文件、应用 profile、日志、暂存和未完成发布请求日志 |
| 共享 | 全部组织数据库记录、资料/标签/作者/版本/当前版引用、受管内容对象 | JWT 密钥及环境凭据、刷新会话、上传暂存 |

共享备份保留密码散列及组织资料，仍是敏感资产，应放在组织认可的位置；“配置脱敏”不意味着备份没有敏感数据。个人源文件 `original_path` 等业务元数据保留，不把库外工作文件偷偷复制进备份。

清单为格式 2，记录每个文件 SHA-256/大小及目录集合。数据库另做 integrity_check / foreign_key_check；每个版本必须能找到匹配摘要的受管对象。文件夹区分内容摘要和 ZIP 归档摘要。旧实现生成的仅含对象数量的清单拒绝自动恢复；保留原备份，在副本中人工核验，不能手改版本号冒充新格式。

备份不包含未完成发布状态的完整恢复流程；恢复后重新登录，先查共享端提交结果，再决定是否发起新操作。已成功的 ShareLink、组织版本和发布请求数据库记录仍保存。

## 4. 备份、恢复与演练命令

在仓库根目录用个人端解释器运行维护脚本：

```sh
venv/bin/python scripts/mvp-backup.py backup-personal /绝对路径/个人库 /绝对路径/备份-个人-日期 --services-stopped
venv/bin/python scripts/mvp-backup.py restore-personal /绝对路径/备份-个人-日期 /绝对路径/全新个人库 --services-stopped
venv/bin/python scripts/mvp-backup.py backup-cloud /绝对路径/共享/cloud.db /绝对路径/共享/storage /绝对路径/备份-共享-日期 --services-stopped
venv/bin/python scripts/mvp-backup.py restore-cloud /绝对路径/备份-共享-日期 /绝对路径/新共享/cloud.db /绝对路径/新共享/storage --services-stopped
```

备份目录须不存在或为空；每次使用新目录。个人恢复目标同样只能为空。共享恢复的数据库路径须不存在，也不能有同名 WAL/SHM 文件；存储目录为空且与数据库文件路径互不包含（示例为同级 `cloud.db` 与 `storage/`）。任何现有库都不做原地覆盖。

个人恢复先在临时目录完整验证，再发布整个目标库。版本绝对路径按原对象根的严格相对关系迁移，不做字符串全局替换；当前版和版本号不变。共享恢复先验证并准备对象，最后排他发布数据库；第二步失败清理本次自建存储。断电可能留下独立的部分目录，需检查后换全新目录重试，不会据此覆盖源库。

恢复后先用独立 profile / 端口验收：资料数量、标签、收藏、当前版、历史文件摘要、文件夹空目录、回收站、停用账号状态。重新配置 JWT 密钥与登录；共享灾难恢复使用新签名密钥，防止旧访问令牌在恢复后继续使用。确认前保留原库与原备份，不删除源数据。

## 5. 升级及失败回退

1. 停止服务与外部编辑，记录程序版本、数据库位置、存储位置和依赖锁文件；保留上一可运行程序产物。
2. 对当前 MVP 格式生成并演练恢复备份。更早的旧格式可能不能通过新备份器版本校验：停机后完整复制数据库及其 WAL/SHM、受管目录到维护副本，原始目录只读保留，不在原库试迁移。
3. 新程序只连接副本。个人库启动执行幂等迁移，歧义版本历史会拒绝；共享旧库在副本上使用 `cd cloud_backend` 后执行 `venv/bin/alembic upgrade head`，环境中的 DATABASE_URL 必须明确指向副本。不要对未记录 Alembic revision 的现有库盲目 stamp 或重跑建表迁移。
4. 核对当前版、全部版本/内容摘要、标签、跨账号权限，完成收录、取回、共享与备份恢复。**旧 ZIP 摘要充当文件夹内容摘要的记录不能直接视作新格式，需逐份核验或重新确认发布。**
5. 若失败，停止新程序，保留错误日志和失败副本，使用上一程序重新连接未变的原库或经验证的旧备份副本。不要让旧程序读取已经迁移并写入的新库；不把数据库降级当作默认回退方案。
6. 完成副本验证后再安排正式切换。切换期间避免并行写入；新旧库若已各自产生新资料，先核对差异，不做覆盖式“回退”。

本轮已验证构造旧库的迁移、重复迁移、歧义预检保持原结构/历史不变，以及新备份的损坏拒绝/失败清理。真实旧资产迁移和跨历史二进制版本自动回滚没有验收证据，需拿到资产后在副本演练。

## 6. 已知限制与复验入口

- 只验证 macOS ARM64 本机 `.app`，未签名、公证或验证 DMG 安装；Windows/Linux/Intel Mac 单列后续工作。
- 暂存硬链接、未引用对象和发布日志回收仍未实现，试用要观察磁盘增长；永久删除不等于磁盘立即释放全部字节。
- 外部 index 工作文件不在受管库备份范围；其已保存版本仍受管备份。外部资料另有备份责任。
- 大容量真实样本、断电、强杀时恢复、内网服务器性能仍需专项验证；当前流程为停写维护备份。
- Python 双环境的安装依赖已执行 `pip check`，精确版本记录在各自 `requirements-mvp-macos.lock`；尚未用新虚拟环境重装全部依赖。
- 测试及操作证据见 [M6复核与修复记录](../reviews/M6复核与修复记录.md)。剩余真人价值验证按 M7 执行，不以测试数替代找资料收益。
