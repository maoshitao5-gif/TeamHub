# 云端与资料投递：启动、迁移与试用

本轮为本机隔离验收交付。约10人内网试用需要组织确定资料留存责任、容量和授权移交流程；不要把开发期保留附件解释为永久留存政策。

## 1. 独立运行

在项目根目录执行：

```bash
bash scripts/mvp-dev.sh local
bash scripts/mvp-dev.sh cloud
bash scripts/mvp-dev.sh all
```

三个命令分别是仅个人后端、仅云端、联调。桌面入口 `bash scripts/mvp-dev.sh start-desktop` 不再启动或依赖云端。双击原启动文件仍可启动桌面。云端网页由云服务同源提供，构建后访问 `http://127.0.0.1:9000/cloud.html`；管理入口为 `/admin.html`。local/cloud/all 使用 `.mvp-sandbox`；start-desktop 打开现有桌面应用并沿用其个人库，不自动切换到沙箱。首次试用可按[MVP访问与测试指引](MVP访问与测试指引.md)使用独立试用云库。

本机启动器首次为云服务生成独立随机签名密钥，保存在 `.mvp-sandbox/shared-server/.jwt-secret`，权限为 `0600`，后续启动复用。不要删除或共享此文件。首次从旧默认密钥升级后，云账号需要重新登录，账号和资料不会被删除。直接部署时必须显式提供至少 32 字符的随机 `JWT_SECRET_KEY`；空值、短值及历史示例值会阻止启动，不再回退到公开默认密钥。

首次构建网页：

```bash
npm run frontend:build
```

云端可以没有个人后端、Electron或本机8001端口；账号由管理员通过 `cloud_backend/provision_mvp.py --help` 中的显式参数开通，不提供默认账号密码。

## 2. 云端数据升级

新版拒绝直接运行未升级的旧云库。不要删除旧数据库来解决启动失败。

1. 停止对应服务。核对 `DATABASE_URL`、`STORAGE_DIR` 是预期的绝对路径。
2. 使用 `scripts/mvp-backup.py backup-cloud <db> <storage> <backup> --services-stopped` 备份数据库和对象；备份清除刷新凭据，保留服务身份、授权、投递和收件状态。
3. 在备份恢复出的独立副本执行升级并验收，再安排原服务维护窗口。
4. 从 `cloud_backend` 运行下列命令。环境变量必须显式指向目标，不能照抄占位路径。

```bash
DATABASE_URL=sqlite:////绝对路径/cloud.db STORAGE_DIR=/绝对路径/storage venv/bin/python manage.py upgrade --services-stopped
DATABASE_URL=sqlite:////绝对路径/cloud.db STORAGE_DIR=/绝对路径/storage venv/bin/python manage.py check
```

全新空库使用 `manage.py init`，它建立当前结构及005迁移标记。历史001是占位迁移，不能将对全空库的 `alembic upgrade head` 当作初始化方式。

旧公开资料迁移为全空间可见，不会被推断成指定共享。出现受限资料或投递后，不能降级到旧鉴权服务。回退必须停写、明确备份时点差异、恢复到空目标验收；不直接让旧程序读取新库。

## 3. 独立云端部署包

```bash
venv/bin/python scripts/build-cloud.py
```

输出 `dist/teamhub-cloud.zip`，包含云后端、迁移、依赖锁、普通成员/管理员静态网页和摘要清单；不包含个人库、真实数据库、凭据、Electron或Python虚拟环境。

解压后准备Python3.11环境，安装 `requirements.txt`（依赖锁当前在macOS ARM64验证；其他目标平台需实际安装验证）。显式配置独立数据库/对象路径、随机 `JWT_SECRET_KEY`，并设置 `CLOUD_WEB_DIST=/部署目录/web`。完成初始化/迁移、账号开通后：

```bash
python -m uvicorn main:app --host 127.0.0.1 --port 9000
```

内网通过同源HTTPS反向代理访问。网页会话只允许HTTPS或本机回环HTTP；代理需保留正确Host并把HTTPS协议可信传递给仅回环监听的服务。不要把个人服务端口暴露到组织网络。

恢复同一服务保留server_id。独立克隆服务在停机时执行 `manage.py clone-identity --services-stopped` 并配置新的JWT密钥，避免把克隆识别成原服务。桌面更换地址后须重新登录核对身份；不能把来源记录里的任意URL作为发送令牌的依据。

## 4. 试用路径

- A网页登录并进入共享资料库，单库自动、多库选择；上传资料，明确选择全库或指定成员。指定共享默认查看，可显式授予协作、管理权限；组织管理员身份本身不获得受限资料读取权。
- B无需安装桌面，可检索自己有权访问的资料、下载、上传新资料；有协作权才能提交新版本。授权管理通过资料详情的访问范围操作完成。
- A桌面打开一份待整理或文档库资料的详情，点击“投递给成员”，选择接收者并确认。首版整次撤回；发送后的记录在“已发送的资料”。
- B在“资料投递”看到未读提醒；网页可下载，桌面可明确“收录到待整理”。未操作时本地库不会增加资料。撤回不能删除已下载或收录的副本。
- 桌面发送未完成时保留固定请求和快照，收发页会列出待核对操作，重启后可继续；不要改请求编号把网络重试变成另一件投递。
- 已关联云资料的本地详情可“检查并更新本地”。不同云内容形成新本地版本，工作修改先保护；恢复已有本地历史仍直接切换所选版本。再次提交旧内容需要明确确认。

## 5. 首版策略与限制

整次投递撤回；投递对象和记录不自动过期；撤回后不提供收发附件取用；指定资料的永久删除暂不开放。创建者为初始资料管理者，主动移交须保留有效管理者；最后管理者失效不会自动公开，其他成员既有有效权限继续保留。上述为实施默认值，留存期限和离职例外流程仍须组织确定。

提醒在登录期间轮询，网页/应用关闭后不保证系统推送；重新连接可读取持久收件记录。一次投递一份资料，整体文件夹作为一个快照附件。网页普通上传支持文件/压缩包，不将浏览器文件夹选择冒充已验证的整体文件夹收录。

上传暂存有独立物理预算：默认总计 6 GiB、1000 份，24 小时后由后续上传清理过期暂存，不删除正式对象或活跃上传。参数见 `.env.example`。登录默认每账号每分钟 10 次、每来源 IP 每分钟 60 次，桌面和网页共用限制；当前单进程部署有效，多 worker 或多机部署须在反向代理或共享存储配置全局限流。文件锁目前在 macOS ARM64 验证，Windows 或网络文件系统需要另验。
