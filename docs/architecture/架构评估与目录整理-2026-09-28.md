# TeamHub 架构评估与目录整理

日期：2026-09-28。范围：当前 M0—M6 本机 MVP；不将 M7 内网部署视为已完成。

## 1. 结论

当前分层适合约 10 人的试用，不建议重新开发或引入微服务。个人库、组织库与桌面外壳各有清楚的职责；SQLite 和受管文件目录能支持本阶段验证。实际瓶颈是新旧实现、文档和操作入口混杂，以及少数跨层耦合，而不是技术栈本身。

这次整理清除了确认停用、无调用的旧实现，收敛了文档和配置入口。它不是全面消除技术债，也不意味着已证明多人生产负载、跨平台安装或内网部署可靠性。

## 2. 当前架构

```text
Electron 外壳：窗口、IPC、个人后端生命周期
    │
Vue 主界面 → 个人 FastAPI → 个人 SQLite + 工作文件/不可变快照
                   │
                   └→ 共享适配层 → 组织 FastAPI
                                      ├→ 账号、团队、空间、权限
                                      └→ 组织 SQLite + 受管对象目录
独立管理界面 ────────────────────────→ 组织服务
```

- 个人默认私有，主动发布；删除本地副本不等于删除组织资料。
- 已保存版本采用独立对象；哈希用于内容校验，文档身份和版本关系单独维护。
- 自由标签和组合筛选承担查找职责；文件夹作为整体快照资料保存。
- Electron 托管个人服务，组织服务独立运行；开发启动器使用隔离沙箱。
- 备份以停写后的数据库与受管对象整体为单位，恢复到新目录。

这些边界值得保留。未来用户量、文件规模和访问模式变化时，以实际测量决定是否替换 SQLite 或存储实现。

## 3. 本轮整理

### 3.1 删除与迁移

删除 **33 个文件**，原内容合计 **230,754 字节**；迁移 **16 份文档**。逐文件路径、哈希和迁移对应关系见 [清理清单](目录清理清单.json)。

| 类别 | 处理与理由 |
| --- | --- |
| 旧启动入口 | 删除 dev-all.js、旧 bat/sh 启动器及 MinIO 启动入口；保留 package.json 与 scripts/mvp-dev.sh 的当前启动路径 |
| 停用服务实现 | 删除组织侧旧 OSS、设备同步、分享和数据库云备份模块；它们未在当前路由注册，旧地址由 decommissioned 路由响应 410 |
| 无调用工具 | 删除个人侧 oss_client、validators，以及前端 oss、cloudOss、ConflictResolveDialog；根据导入和调用关系判定，不根据文件年代判定 |
| 旧部署材料 | 删除互相矛盾的阿里云/OSS 部署说明及旧 Docker 配置；当前 M7 尚未验证，避免把历史部署方式当作可用入口 |
| 重复文档 | 删除旧系统说明和前端更新说明；现行产品、操作、架构和历史评审分开管理 |
| 空文件 | 删除根目录 curl、python 两个空文件 |

每个删除文件都先复制到 `/private/tmp/teamhub-cleanup-30i23gjg`，其中 `manifest.json` 记录原路径、SHA-256 与大小。该位置是临时回退副本，可能被系统清理，不能代替长期版本归档。清理清单保留在仓库中。本轮没有创建 Git 提交。

### 3.2 内容整合

- 新增 [文档导航](../README.md)，文档分为 product、guides、architecture、reviews；迁移后重写相对链接。
- 更新 README 与 CLAUDE.md，移除将旧同步/OSS 流程描述为当前架构的内容。
- 两个 requirements.txt 分别引用各自的 macOS ARM64 锁文件，避免维护冲突的版本列表。没有卸载现有环境中的包；锁文件中历史依赖的进一步瘦身应经干净环境验证。
- 更新个人/组织环境变量示例与 config.example.json；去掉旧 OSS 和默认管理员示例。真实配置、密钥未修改。
- 补充构建目录忽略规则，修正文档乱码注释；保留现有依赖和构建产物。
- 设置页移除已经停用的云数据库备份按钮，改为维护者离线备份说明；登录页改为联系管理员开通账号。
- 个人资料详情移除重复且使用错误身份路径的旧“云端版本历史”；组织版本统一从共享资料页面查看。旧预签名下载接口改为明确的 410 提示，并加入停用接口测试。

### 3.3 有意保留

真实资料、数据库、沙箱、凭据、依赖环境、已有桌面产物和运行中的用户服务均不作为垃圾清理。数据库迁移、兼容模型字段、仍有调用的 changelog/device/pointer 等模块，以及 410 路由继续保留。

工作区原本已有大量 M0—M6 未提交修改；本轮没有回滚或覆盖这些成果。不能把最终 git diff 全部归为此次整理。

## 4. 剩余问题与下一步

| 优先级 | 问题与证据 | 建议边界 |
| --- | --- | --- |
| 高 | TeamPage、OnboardingPage 仍使用 api/cloud.js 的团队/空间直连客户端，而主登录状态由个人后端维护 | 统一主界面访问共享服务的适配入口，验证登录、创建团队、邀请成员、创建空间；独立管理 SPA 的独立认证不应混为同一问题 |

| 中 | settings_api.py 仍保留旧云数据库备份转发代码，但对应组织端点已停用；旧模型和锁文件还含历史结构/依赖 | 后续将无效入口统一成兼容提示，迁移和依赖清理分别实施，不能直接删除旧表或猜测卸载包 |
| 中 | 同步命名与旧配置字段仍存在 | 先明确职责并收敛调用，再考虑改模块名；公开接口路径维持兼容 |
| 验收待办 | 本轮共享 UI 测试在管理员切换时超时 | 保留失败证据，调查界面状态恢复/测试时序；不能用后端全绿替代 UI 通过 |
| 后续阶段 | 单机 SQLite 并发边界、真实资料体量、部署与干净安装尚待验证 | M7 用约 10 人实际样本验证，之后再决定数据库、文件服务或部署方案升级 |
