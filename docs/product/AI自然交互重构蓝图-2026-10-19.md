# AI 自然交互重构蓝图

建立：2026-10-19；最后更新：2026-10-20。状态：实施与隔离工程验收完成，真实模型体验待业务样本验证。依据：用户要求先分析架构，再优化代码，实现流畅、自然、少打断的 AI 伙伴。交付证据见[自然交互重构验收](../reviews/AI自然交互重构验收-2026-10-19.md)。

## 1. 问题判断

重构前的主要阻力来自 TeamHub 编排：每次提问强制准备和勾选；Hermes 每轮收到空的原生历史，旧消息被装入当前问题 JSON；旧结构化输出规则与自然文本引擎冲突；内部预算、空搜索、未知引用、SSE 字节限制等直接升级成整轮中断。更换同一系列模型或单纯提高调用次数无法解决这些问题。

产品目标：普通聊天、资料问答和连续追问均直接发送；读资料和内部阶段切换自然推进；停止、断线及失败保留用户已经看到的内容；后台保护不成为日常交互步骤。

## 2. 职责与技术选择

| 层 | 职责 |
| --- | --- |
| Vue 聊天页面 | 输入、可见的服务和资料范围、回复与来源、停止、重试、成果保存 |
| TeamHub 会话服务 | 会话持久化、幂等提交、按消息冻结版本、任务状态、范围与服务核验、真实用量 |
| Hermes | 原生角色历史、理解与规划、工具循环、上下文压缩、自然语言回答 |
| TeamHub 工具桥 | 固定快照读取、搜索、来源登记、草稿生成、针对工具失败提供可恢复反馈 |
| TeamHub 模型网关 | 保管密钥、锁定目标服务、流式转发、传输容量保护、明确的有限重试 |

采用“有状态会话、独立任务进程”。本轮不以常驻进程为前提：Hermes 每次启动时获得经过校验的原生历史，完成或内部暂停时返回原生状态。已有可靠的进程回收、固定版本、参数校验和资料边界继续使用。

## 3. 直接发送契约

- 新增 `GET /api/ai/partner/chat-config`：安全服务说明、`service_revision`、配置状态及默认交互选项。修订值绑定目标地址、模型与引擎身份，不公开密钥。
- 新增 `POST /sessions/{session_id}/send`：`message`、`scope_mode`、`document_ids`、`thinking_mode`、`request_id`、`expected_service_revision`、`consent: true`，可选高级预算。点击“发送”授权当前明确展示的服务和资料范围，不再另弹每轮审批窗。
- 后端完成当前版本冻结、上下文准备、任务注册与调度，返回 `202 task`。相同请求编号与相同规范化内容只创建一次任务；编号对应不同内容时拒绝复用。
- 新增 `POST /tasks/{task_id}/resume`：沿用原任务范围与已读证据，一次点击继续；服务身份变化时要求重新发送问题，不暗中切换外发目标。
- 新增 `GET /sessions/{session_id}/requests/{request_id}` 用于只读核对发送结果；公共 task 的 `last_request_id` 用于识别续行已被接受。原有 prepare/start/prepare-continue/continue API 保持兼容，新界面不依赖它们完成日常发送。
- 会话恢复上次范围和思考方式；新消息读取当前保存版本，已运行任务不自动扩权。全库模式按需检索，初始不曝光任意前 30 份文件名。
- 默认普通回复，用户可开启深度思考；高级预算折叠。暂停任务允许直接发新问题，先结束旧执行状态并保留其进度。

## 4. 会话与证据

- 在任务 `result_json` 的私有 `engine_history` 中保存经过校验、限容的 Hermes 消息，包含必要的角色、工具调用配对与模型协议字段。公共任务 DTO 不返回原始工具历史或模型原始思考字段。
- 下一轮仅在服务身份、当前允许范围和实际依赖版本仍匹配时复用；配置、权限或相关版本变化时安全回退到有效文字历史和重新核验的证据。
- 历史图片像素不无限复制保存；不能把已移除的图像假装成仍可见原图。
- 普通用户目标、修正和对话背景与资料证据区分；版本更新不应一并删除一般对话目标。历史另记授权资料 ID 来源，与精确版本依赖分离，并沿助手转述及跨轮引用继承。范围收窄时同时过滤用户原文、助手复述和旧摘要，不得重新发送已撤销资料内容。
- 保留原始会话记录。Hermes 的压缩请求必须通过同一宿主网关并纳入任务总用量，不能另用辅助服务绕开授权。

## 5. 任务推进与恢复

- 正常聊天使用合理的整项任务预算，内部较小执行段自动延续，沿用原生历史、检查点、草稿、冻结范围和服务；所有段累计同一个任务总额。
- 自动继续仅针对可恢复的内部模型/工具额度边界，不能无限重置总额度，也不对未知付费状态重放整轮。
- 无新增证据、单文件不支持、证据容量暂满等先返回可执行的工具反馈，让 Hermes 换方法或用已有内容回答；重复相同无效动作才进入收束保护。
- 未知引用移除有效来源外观并明确标注核验缺口，保留正文及有效引用；不因一个来源编号不符清空整份答案。
- Hermes 响应容量与旧 PydanticAI 分离，覆盖正常长思考与流式帧开销；最终答案长度统一，避免三处不一致的 18000 字符限制。
- 正在生成、已停止和可恢复失败的部分答案均能显示；未完成内容明确标注，不冒充已核实最终回答。
- 页面断流只重新获取同一个任务状态/事件；短暂网络错误退避重连。POST 响应不确定时保留原请求编号与内容，通过只读请求查询对账，暂时 404 继续核对，编辑新草稿不会覆盖原提交；不自动重发 POST。已出站请求中断不静默重放；确定的可重试失败按统一有限规则处理。
- 密钥错误、余额不足、服务限流、网络中断、资料变化分别给出原因；不统一要求用户缩小问题和重新确认。

## 6. 交互验收

1. 普通问答及至少三轮连续追问，每轮仅一次发送，无准备弹窗。
2. 实际 Hermes 第二轮模型请求保留第一轮原生角色与必要协议字段；当前问题为自然文本。
3. 资料检索、阅读、来源定位与成果保存完整可用；无关文件变化不使普通聊天失效。
4. 连续空搜索、单文件错误、未知引用不清空整轮回答；长回答及超过旧 512 KiB 的合法流正常完成。
5. 发生内部执行段切换时不弹窗，总额度仍严格累计；取消后无迟到最终答案或多余请求。
6. 已生成部分文字在停止/断线时保留；GET 重连不产生重复付费任务；POST 幂等保持。
7. 资料范围收窄、库切换、服务变更不能泄露旧资料；私有模型历史不进入公共响应或日志。
8. 用户向上阅读时不被每次流快照强行拉到底部。
9. 在隔离配置、合成资料和本机模型模拟服务中完成真实 Hermes/Electron 验收，重新打包并更新一键启动入口。

## 7. 实施顺序与所有权

1. 会话后端：direct send/resume、幂等、私有历史选择、自动分段、部分答案与上下文。
2. Hermes 适配：原生历史协议、自然提示、工具恢复、长流与答案容量。
3. 前端：单次发送、范围继承、消息内流式状态、停止/继续/重试、GET 重连与滚动。
4. 集成：定向测试、真实引擎与桌面流程、独立代码/权限审查、构建交付、基石与指引更新。

各层先验证目标行为的失败重现，再改生产代码。测试和构建不使用真实用户资料或真实收费模型。

## 8. 依据

- [DeepSeek 思考与多轮工具调用](https://api-docs.deepseek.com/guides/thinking_mode/)：工具会话需保留模型要求的推理协议字段，不能通过丢弃原生历史来替代会话管理。
- [Hermes Agent Loop](https://hermes-agent.nousresearch.com/docs/developer-guide/agent-loop)：提供原生会话输入与返回消息、流式和阶段回调。
- [Hermes 上下文压缩](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching)：压缩应作为上下文管理的一部分；本项目所有实际请求仍受宿主网关管控。

本轮目标是消除 TeamHub 自身造成的交互阻力，恢复模型与 Hermes 的完整协作。官方产品的模型服务速度和效果不由本地代码保证，合成模型验证不冒充真实模型质量评测。
