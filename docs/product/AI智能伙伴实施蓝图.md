## 1. 用户能力与完成标准

用户进入独立「AI 伙伴」页面，可创建和恢复会话，提出自由问题。伙伴可在本次授权范围内主动搜索、补查和读取资料，使用多份证据作答，也可在无资料授权时进行通用交流。标签建议和简短摘要属于既有功能，不能代表本轮交付完成。

必须打通以下实际任务：

1. 描述问题，授权查找个人资料，模型自行查询并找到候选，读取相关资料后回答，展示真实读取来源。
2. 选择两份以上资料，询问差异，模型读取各自固定版本，形成可核对的比较；后续追问能继承会话。
3. 指定 PDF 页面或图片，在支持图片输入的模型上发送原始页面图像，结合文字作答；无法处理的内容明确报告。
4. 请伙伴生成说明或报告草稿，先在界面预览，经确认保存为待整理资料，正常生成身份和初始版本；重复保存不制造重复资料。
5. 任务可取消；高级选项设置任务总预算，内部执行段在总额内自动衔接。达到总预算或无法继续取得进展时保留成果并说明原因，可一次点击继续或直接提出新问题。失败、配置变化或资料变化可理解，不自动重发可能已收费的请求。

工程测试使用临时资料库及可控模型替身，不调用真实收费服务，不外发用户资料。真实模型的阅读与分析质量需要用户配置服务后用实际样本验证。

## 2. 架构职责

| 模块 | 职责 |
| --- | --- |
| Vue AI 伙伴页 | 会话、自由提问、选择范围、外发说明、任务步骤、回答来源、成果确认保存 |
| FastAPI 伙伴接口 | 本机调用校验、直接发送与范围核验、请求幂等及只读对账、任务与会话读取、取消和成果保存；旧准备接口保留兼容 |
| 伙伴运行服务 | 短会话持久化状态、后台执行、库和配置守卫、限额、取消与中断处理 |
| 引擎适配与本机工作进程 | 当前连接 Hermes 执行模型—工具循环，按结果动态决定下一步；TeamHub 冻结任务范围并校验所有资料工具；PydanticAI 为此前阶段实现 |
| 资料工具 | 搜索、读取固定版本正文、读取 PDF 原页/图片、返回来源与缺口 |
| 既有资料服务 | 文件查重、收录待整理、初始快照和版本、正常后续整理 |

模型 API 负责理解和生成，TeamHub 负责决定模型能使用的范围及实际执行效果。工具参数使用明确类型和文档身份，不向模型提供任意路径、SQL、系统终端或全库凭据。第三方 SDK 的工具确认只能辅助交互，业务授权必须在 TeamHub 服务执行前重新核对。

Hermes 固定上游版本并以独立本机工作进程随应用交付，由 TeamHub 自动管理，用户无需额外安装。当前不引入独立 OpenClaw 服务、外部任务集群或新的向量数据库。原页读取采用受限 PDF 渲染和图片解码；依赖锁定、打包、运行时资源需实际验证。§6、§8—§10 保留 PydanticAI 阶段说明，§11 保留首次 Hermes 集成经过；当前自然交互与会话规则见下方 §12。

## 3. 任务授权与版本

- 当前页面持续展示目标服务和资料范围，点击发送即开始，无需逐轮准备和再次确认。默认选中资料；空范围允许通用交流，模型无法读取个人资料。用户可主动选择个人库检索范围。
- 问题、有效会话历史及按需读取内容使用页面展示的模型服务；一次任务可能多次调用模型。高级预算约束整个任务，内部执行段不重复要求确认。
- 任务开始冻结资料范围，文档 ID、已保存版本、内容哈希及必要元数据在读取和采纳前校验。新收录对象不自动扩大既有授权。
- 搜索在本机执行，只将命中的有界候选发给模型；禁止一次把全库正文发送到模型。
- 原始文件从不可变快照安全读取，验证内容摘要；索引可作为线索，但正文不可用时不能伪称已读原件。
- 每个来源包含文档、版本、位置和读取范围。模型生成的来源 ID 必须对应实际读取内容；原文、推断和处理缺口分别呈现。
- 历史对话作为明确告知的任务输入；版本或授权变化不能导致旧工具内容无条件重放。原始图片和完整工具负载不应反复写入会话历史造成膨胀。
- 更换个人库、服务地址、模型或密钥修订后，旧准备失效；后台任务不得向新库提交旧结果。

## 4. 会话、任务与接口

伙伴数据保存在所属个人资料库的本机数据库，新增表通过幂等初始化建立，不清空或重建旧库。会话及任务不属于组织共享资料，不随普通资料发布传播。

接口统一前缀 `/api/ai/partner`，继承已有 AI 本机来源与 Electron capability 检查。

| 接口 | 用途 |
| --- | --- |
| `GET /sessions`、`POST /sessions` | 列出和创建会话 |
| `GET /sessions/{id}`、`DELETE /sessions/{id}` | 查看和删除会话，运行中的会话需先结束任务 |
| `GET /chat-config` | 当前服务身份、修订值及默认交互选项 |
| `POST /sessions/{id}/send` | 一次提交问题、资料范围、思考方式与幂等请求编号，冻结版本并启动任务 |
| `GET /sessions/{id}/requests/{request_id}` | 启动响应不确定时只读核对同一请求，不重发模型请求 |
| `POST /tasks/{id}/resume` | 一次点击继续原任务；通过 task 的 `last_request_id` 核对续行是否已接受 |
| `POST /sessions/{id}/prepare` | 历史兼容：冻结问题、历史、`context={summary,evidence,sources}`、思考方式、服务与资料范围，生成短期准备凭据 |
| `POST /sessions/{id}/turns` | 历史兼容：确认后开始任务；当前页面改用 `/send` |
| `GET /tasks/{id}` | 查询运行步骤、正式回答、生成中 answer_preview、来源、草稿与安全错误 |
| `GET /tasks/{id}/events` | 带本机能力凭证的 fetch SSE；task 事件为完整任务 JSON，终态后 done 关闭；断流回退查询状态 |
| `POST /tasks/{id}/cancel` | 取消任务，停止后续模型与资料操作 |
| `POST /tasks/{id}/artifacts/{artifact_id}/save` | 确认将已生成草稿保存为新资料，重复请求返回原结果 |

状态包括排队、运行、暂停、完成、失败、取消和中断。每会话同一时刻只运行一个任务；暂停释放付费执行许可，用户可继续原任务，也可直接提出新问题，系统结束旧执行状态并保留进度。应用重启保留已持久暂停任务，将真正遗留的在途任务明确标记中断，不后台自动续费。工具报错可作为模型观察结果供其调整方法，未知付费状态的模型请求失败不自动重发。

## 5. 阅读与成果边界

本轮工具包括：

- 本机搜索资料名称、标签及可用正文线索，支持模型改写查询和翻页；候选结果有界。
- 读取授权文档的固定版本内容，保留段落、表格、页码或单元格位置，显示截断及缺口。
- 指定 PDF 页码渲染原页，不因已有文字层跳过图形；读取受管图片，限制文件大小、像素和每次页面数。
- 办公及开放文档先看结构，再按需读取正文、表格和真实引用的内嵌位图；内嵌图不能冒充完整页面排版，缺失内容保持可检查。
- 生成文本或 Markdown 草稿，保存在任务中供预览。实际入库由确认接口调用现有收录流程，不允许模型直接覆盖源文件。

旧版 Office、WPS、任意 CAD、加密文件或无法完整提取的对象不能凭扩展名假定可读，应返回可操作原因。模型不支持图片时，明确报告能力不匹配。通用能力指可围绕不同资料和问题组合工具，不等于首轮已经支持所有二进制格式。

## 8. 任务预算与持续处理优化（2026-10-16，历史）

首版真实试用暴露出固定 8 次请求与逐批 20 单元读取不匹配：较大 Excel 可能尚在正常阅读就被终止。该数字是首版工程默认值，不是 AI 能力边界。本轮同时调整预算、工具粒度及恢复机制。

### 8.1 用户可见预算

| 模式 | 模型请求 | 工具调用 | 输出 tokens | 本段最长时间 |
| --- | --- | --- | --- | --- |
| 快速 | 12 | 24 | 16000 | 3 分钟 |
| 标准（默认） | 32 | 80 | 48000 | 10 分钟 |
| 深入 | 64 | 160 | 96000 | 30 分钟 |

高级自定义允许四项整数分别在 4—128、8—256、4000—128000、60—3600 秒范围内设置。模型请求包括阶段整理；不因预留一次总结而暗中增加授权。偏好仅保存在设备的非敏感设置中，后端逐次验证，准备界面展示实际值。预算按每段执行计算，续做重新确认后增加一段预算，任务同时保留累计消耗。由于供应商价格、缓存计费和用量报告可能不同，不虚构固定金额上限。

### 8.2 有进度的阅读

通过 `document_overview` 先看结构和已读范围；正文按有界连续单元读取；Excel 通过 `read_table` 按工作表、行块及必要的列信息读取，单次仍有正文字符限制。表头只作为明确标注的上下文，不推断未读正文。超宽或长行返回可执行的下一位置，避免只按下一行跳过内容。步骤显示实际范围，实际覆盖按正文位置和页面计算，顺序翻页与新检索证据不应被误判为重复。

连续多次操作没有新增证据时，工具先提示已读范围与建议，达到阈值后暂停。这是缺少进展的检测，不是证明模型陷入了逻辑死循环；用户可检查阶段成果后继续或结束。

### 8.3 暂停、成果与明确续做

模型请求、工具调用、输出预算、时长及无进展分别给出原因。主循环为阶段整理预留请求和输出额度；无法生成阶段分析时，保留客观读取进度并如实说明，不能伪称已完成问题。

恢复检查点保存受控的完整已读文字、来源编号、读取位置、已暴露资料依赖和草稿；短摘录只用于来源卡片。检查点有容量上限，超限须明确告知可保留范围，不能静默丢弃已读正文。密钥、原始图片字节和 SDK 原始消息不进入检查点；再次视觉分析可能需要重新读取原页。

续做顺序为：展示原固定范围、版本、目标服务、将发送的完整保留证据和草稿及新预算 → 用户确认 → 幂等启动同一任务的下一段。每次继续重新核对库、资料、版本、元数据与配置，准备后变化即失效；不可将旧进度带入新库或静默扩大读取范围。暂停不添加完成回答，最终完成后只写一次正式助手消息。草稿可单独确认保存，不要求先完成整个长任务。

### 8.4 本轮验收重点

- 正常任务可超过旧 8 次请求完成；大表格能以少量模型往返取得完整行块与来源。
- 自定义预算真实生效，四类预算与无进展原因可区分，最终整理不超授权次数。
- 暂停保留超过短摘录长度的真实原文、稳定来源与草稿，刷新或重启后可以确认继续。
- 重复继续请求不重复收费、不重复保存，不从头读取已有文字；变更版本、库、配置和取消均阻止旧结果复活。
- 保持原有资料阅读、PDF/图片、来源、收录与桌面启动回归。本轮实际数据以专题验收记录为准。

该阶段历史工程验收：682 项个人后端、106 项前端、124 项伙伴专项、8 组冻结桌面完整任务及独立包冷启动通过，伙伴六模块合计行覆盖率 86%；独立 Python、JavaScript、通用与安全复核均通过。完整证据、产物和限制见[预算与持续处理验收](../reviews/AI伙伴预算与持续处理优化验收-2026-10-16.md)，这些统计不作为 §10 的最新结果。

## 9. 格式与多模态扩展（2026-10-16）

本轮沿用既有单服务配置和智能体工具循环，不另设视觉服务或第二套密钥。模型通过受控工具按问题取得文本、单元格、PDF 页图或内嵌位图；本机索引仍是可重建的文字检索底稿，不在收录时自动调用外部 AI。

1. **扩大文字覆盖。** 新增 PPTX 幻灯片文字及表格、ODT/ODS/ODP、CSV/TSV 逻辑单元格、HTML 可见正文；兼容已知 Strict OOXML 及常用宏/模板扩展，只读内容，不运行宏、公式或脚本。PPTX 按展示关系排序，CSV 引号换行与 ODF 重复单元格保留真实位置并设展开预算。Word 文本框只取一次，补取 DrawingML 文字。
2. **接入真实嵌图。** `document_overview` 枚举实际内部引用的 `visual_assets`。新增 `read_embedded_images(document_id,image_ids)`，每次至多 3 张，绑定固定版本与实际段落、工作表或幻灯片位置。未引用媒体、外链资源和嵌入可执行对象不读取、不发送。位图经受限子进程解码、缩放并重新编码 PNG，沿用图像来源、取消和检查点规则。
3. **报告实际缺口。** 没有文字时提示可查看内嵌图片或 PDF 原页；既无文字又无可读取图像时如实说明。未知来源编号继续拒绝。嵌图不代表整页布局，SmartArt、原生图表、矢量形状、页眉页脚等未读取部分保持缺口，不生成伪页面。
4. **验证当前模型。** 设置中的“测试图像理解”只在用户主动点击时发送随机合成几何图，比对实际颜色和形状。结果仅表示当前配置本次简单识图表现；编辑、保存或切库即清空，不持久宣称模型通用能力。网络、鉴权和限流错误保持独立原因，不能误报为没有视觉能力。
5. **控制边界与迁移。** 解析器升至 v2，旧派生索引重新排队重建，不迁移或改写资料实体。旧解析规则的暂停检查点不能盲目恢复。单任务图像交付数量与字节累计限制，含重复读取；传输再约束实际请求正文单次 16 MiB、单段累计 64 MiB，包括历史重复携带的图像。容量不足明确停止且不自动收费重试。

当前内置能力与限制以[使用指引能力表](../guides/AI智能伙伴使用指引.md#reading-formats)为准；旧 DOC/XLS/PPT、CAD、SVG/HEIC 视觉、音视频和完整 Office 页面渲染不列为已完成。未隐式依赖 WPS、Pages 或 LibreOffice。后续增加转换器须单独验证宏、外部资源、超时、取消、原生库打包及来源标注。

服务能力参考：[DeepSeek 官方图像理解说明](https://api-docs.deepseek.com/guides/vision/)（当前 `deepseek-flash` 提供图像输入）；实际接入仍以用户所配置端点和模型的测试表现为准。工程验证使用本机假服务与合成文件，不代表真实复杂图纸准确率。

## 10. 伙伴体验第一批：思考、流式与上下文（2026-10-17）

本节记录 2026-10-17 的历史交付：依据 2026-10-16 授权，当时保留 PydanticAI 的模型—工具循环，借鉴 OpenClaw、Hermes 的持续交互与上下文组织机制。真正的长会话语义压缩、长期用户记忆、会话历史搜索工具和自动学习 Skill 未纳入该批。2026-10-18 已新增集成 Hermes 的授权，当前引擎路线以 §11 为准。

| 工作 | 实施与验收要求 |
| --- | --- |
| 思考模式 | 每轮选择 enabled/disabled，默认深入思考，准备凭据冻结选择；与 quick/standard/deep/custom 任务预算独立，不改全局 AI 设置。DeepSeek 工具链按 SDK 正确接续本轮 reasoning_content，不展示、持久化或跨轮带入原始思考；其他服务不强加 DeepSeek 字段 |
| 真实流式 | SDK 接收 SSE 并提取结构化 answer 的未完成片段；answer_preview 仅在生成中保存在内存，最多 18000 字，不落库。上游逐块核验、解压后限量、取消即关闭，一次请求只计一次响应。供应商忽略 stream 而返回合法 JSON 时只转换该次响应，不重发 |
| 界面 | 正式回答、阶段分析和 Markdown 成果可读地显示标题、列表、表格和代码；markdown-it 设置 html:false 并禁用 image，HTTP(S) 参考链接经显式点击、Electron 主进程校验桥打开。步骤默认收起，显示当前动作；生成预览明确标识未完成，终态先清预览，来源及版本核验后才进入正式对话 |
| 连续上下文 | 完整历史保留在本机；近期最多 16 条／18000 字，较早消息按本机规则摘录完整句段，最多 12000 字并保留消息 ID，不冒称语义总结。普通追问从最近保存可核验检查点的完成任务接续实际文字证据，最多 100 来源／60000 字完整单元；省略明确说明，图像按需重读，不继承草稿、图像交付计量和旧 usage |
| 授权与一致性 | 准备展示实际 history、context={summary,evidence,sources} 和模式，无额外模型调用；确认及每次外发复核。范围、版本、状态或元数据失效的资料及关联消息不带入；准备之后历史或检查点变化需重新确认 |
| 来源编号 | v3 检查点增加 next_source_number 高水位，支持稀疏 S 编号，兼容有效 v1/v2；原有 180000 字／1 MiB／1000 来源的任务检查点硬上限不变。恢复后不能把原 S2 指向另一份证据；界面展示实际 [S#] 编号，未知引用继续拒绝 |
| 事件连接 | fetch SSE 携带本机 capability，task 事件为完整任务 JSON、终态后 done 关闭；无变化时 15 秒 heartbeat，客户端 45 秒无活动断开并回退 GET 状态，成功后每隔 1 秒继续，单次 30 秒超时。按个人库、任务和操作代次隔离；库绑定核验与会话建立在同一激活锁内，服务器短会话读取，等待不占库，切库关闭旧流。断流不重发模型任务 |

DeepSeek 开启思考时单次输出上限 32000 tokens，包含推理和答复；关闭思考或其他服务为 6000，均动态受本段剩余预算约束。阶段整理预留一次请求及最多 2000 输出 tokens（不超过本段输出预算四分之一），关闭 DeepSeek 思考，仍计入原授权；准备预览不产生额外收费请求。普通新轮与暂停续做分别处理，后者仍保留原任务的草稿、图像交付计量、证据和累计用量。

实施顺序是补有效 RED、模型和工具适配、运行时与 API、页面及安全展示、独立审查与修复、真实 SDK/生产 Electron 流程、独立包冷启动。验收覆盖取消、切库、旧响应、上游错误、预算暂停继续和原有多模态能力，使用合成资料和本机假模型，不以测试替身证明实际模型回答质量。

工程证据与最新测试包见[体验优化验收](../reviews/AI伙伴体验优化验收-2026-10-17.md)。实际配置能力仍需试用；相关协议参考 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[PydanticAI 事件流](https://ai.pydantic.dev/agents/#streaming-events-and-final-output)。

## 11. 独立本机 Hermes 引擎集成（2026-10-18，历史）

### 11.1 目标与交付形态

发起人授权按此前讨论集成 Hermes。用户仍在同一个「AI 伙伴」页面提问，继续使用设置中的模型服务地址、模型和 API 密钥。Hermes 及必要运行依赖随应用交付，由 TeamHub 按需启动、停止并随应用升级；用户无需另装 Hermes 或 Python，也无需管理第二套服务。当前支持平台必须以独立包的实际验收为准，不能将本机验证延伸为全部系统发布完成。

TeamHub 主定位是围绕资料库完成用户任务的伙伴。选定资料后的理解、分析与成果质量应先得到验证，再提升自动发现资料与跨资料任务能力；引擎接通本身不证明已接近官方聊天产品体验。

### 11.2 职责与连接

| 部分 | 本轮职责 |
| --- | --- |
| TeamHub 页面与任务服务 | 会话、准备授权、固定资料范围、预算、取消、幂等、来源检查、成果确认与实际入库 |
| 本机 Hermes 工作进程 | 每段任务按需运行真正的模型—工具循环，接收问题及获准上下文，返回步骤、回答与用量 |
| 引擎适配协议 | 交换任务、工具请求及结果、进度、终态；固定协议版本，拒绝不兼容或无效消息 |
| TeamHub 资料工具 | 查找、结构总览、正文、表格与实际图像读取、草稿生成；每次执行继续校验文档身份、固定版本和授权 |
| 外部模型服务 | 使用用户已配置的 API 完成推理；Hermes 本机运行不改变这部分资料外发关系 |

上游固定 `v0.22.2`，协议首版 `1`。准备信息的 `service` 包含 `engine`、`engine_version`、`engine_protocol`，与模型服务信息共同冻结；界面只在确认说明中展示「Hermes 本机引擎」，避免日常对话增加引擎管理操作。引擎按每个任务执行段启动，完成、暂停、失败或取消后释放；TeamHub 数据库和文字检查点继续提供跨段状态。

本机连接采用双向标准输入输出上的 NDJSON 消息，不另开 Hermes HTTP 监听端口。Hermes 的 Python 3.14 运行环境独立随包提供，不依赖用户电脑已有的 Python 或改变现有个人后端的运行环境；其依赖、启动路径和进程回收须在最终应用包中验证。

### 11.3 保留的规则与能力边界

- 使用原有 AI 服务与密钥配置；工作进程只接收当前段必要输入，凭据不写入资料、会话、检查点或普通日志。原始模型思考不持久保存。
- 只开放 TeamHub 明确提供的资料工具。Hermes 上游的终端、任意路径读写、浏览器、网络检索、外部 MCP、长期记忆和自动学习 Skills 不默认开放；工作进程不能作为操作系统级沙箱来宣传。
- 资料查找和读取继续受本轮授权范围及已保存版本约束。真实工具结果负责来源，模型输出不能自行制造来源、改写历史快照或扩大权限。
- 继续执行预算、累计用量、连续无进展暂停、阶段分析和取消。失败请求及旧引擎历史任务不自动重试，也不以更换引擎为由后台增加收费调用。
- 准备后引擎、协议、模型配置、资料或历史变化，旧准备失效。旧任务恢复必须兼容其原引擎标识和检查点；不兼容时明确结束并让用户重新发起。
- 当前成果仍为 Markdown／TXT 草稿，确认后进入待整理。直接修改原件、执行任意脚本、生成与加工原生 Word／Excel 不纳入此次引擎接入，也不能因上游具有某工具而宣称已在 TeamHub 开放。
- 本轮保持既有近期历史、原文摘录和有效文字证据策略。语义压缩、可检索历史、长期记忆与成果质量自检需独立验证，不默认声称已继承 Hermes 全部能力。

### 11.4 验证与后续质量评价

验收需覆盖真实 Hermes 工作进程及其适配层，而不能只验证一个名称为 Hermes 的模型替身：固定版本可导入与打包，任务能调用模型和 TeamHub 工具，步骤及用量可返回，取消和异常会回收工作进程，权限、版本、库切换、重复启动和旧任务不自动付费重试均有效。测试使用合成资料和本机可控模型，不读取真实用户资料或密钥。

随后以相同资料、问题、模型与相近预算比较「单份深入阅读、多份综合、形成可用成果」三类任务，分别记录正确性、完整性、来源、耗时与费用。当前集成的工程结果与真实模型质量结果分开报告；文件处理与检索底稿仍需要持续改善。


## 12. 自然交互与原生会话更新（2026-10-19 建立，2026-10-20 验收）

发起人反馈逐轮确认、内部额度中断和空历史导致体验不自然，已授权先完成架构再实施。当前方案见[自然交互重构蓝图](AI自然交互重构蓝图-2026-10-19.md)：TeamHub 管理资料与会话，Hermes 接续原生历史并执行工具，模型网关统一处理目标、凭据及计量。

本次取代 §11 及此前历史章节中的逐轮准备确认、问题 JSON 内嵌历史、内部执行段需再次确认、停止即丢弃流式片段等交互规则。当前默认普通回复，可开启深度思考；Hermes 原生消息和必要协议字段保存在私有任务状态，复用前核验服务、授权来源及实际证据版本。资料身份授权来源与精确版本依赖分别记录，范围收窄同时过滤用户原文、助手转述及历史摘录。

工具和文件权限保持清楚的业务入口，普通聊天直接发送。启动响应不确定时按原请求编号只读对账；停止及可恢复失败保留已生成片段并标明未完成。当前适配器握手为 `adapter_revision:2`，旧适配器在模型请求前明确拒绝。使用以[当前指引](../guides/AI智能伙伴使用指引.md)为准；接口以契约 §10.11 为准。实施和隔离工程验收已完成，见[自然交互重构验收](../reviews/AI自然交互重构验收-2026-10-19.md)；真实模型效果仍需典型业务问题验证。

## 13. AI 预整理与用户确认（2026-10-20—21）

用户已知资料内容，期望减少命名、分类和打标签的操作，并在使用中逐步建立尚不成熟的标签与文件夹体系。最新方向为「待整理中 AI 后台生成方案 → 用户查看或调整 → 一次确认 → TeamHub 完成整理并纳入文档库」，文件夹仍可选。此前直接自动入库的设想不作为默认方式，可选自动执行的范围和规则尚未确定。

后台预整理可复用 AI 伙伴和 Hermes 的理解、读取能力，用户无需逐份发起聊天；实际命名、标签关联、分类及状态转换由 TeamHub 资料服务执行。建议生成不应用正式变更，用户修改优先；普通聊天的直接发送体验继续保留。

本轮按单文件预整理，整体收录的文件夹暂不支持，可继续手工整理或分别收录子文件后再处理。分类文件夹作为可选整理目标不受此限制。

待整理中增加独立的「待 AI 预整理 / AI 预整理中 / AI 已预整理 · 待确认 / 预整理失败」展示和筛选方向，支持集中查看、批量确认。AI 完成、原文索引建立与资料已整理是三件事，不引入第三个仓库，也不要求深入索引全部完成才能整理。

共识与价值见[产品方案](AI预整理与用户确认产品方案.md)，核心原则见[基石 §4.9](TeamHub项目基石.md#foundation-ai-preorganize)，工程规则见[AI 预整理实施蓝图](AI预整理实施蓝图.md)。本轮新增独立任务及采用记录、后台范围启用、固定版本结构化方案、批量确认和撤销保护；新工具仅用于预整理，不扩大普通聊天工具集。Hermes 适配器升为 `adapter_revision:3`，替代 §12 的 revision 2；上游版本和协议主版本保持不变。使用步骤见[预整理指引](../guides/AI预整理使用指引.md)，实现与最终桌面包验证见[预整理验收](../reviews/AI预整理验收-2026-10-21.md)，真实模型对命名分类的效果仍待业务资料试用。
