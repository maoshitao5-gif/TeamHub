## 1. 从什么问题切入

用户已经知道大部分资料的内容，主要负担是命名、分类和打标签。现有标签、文件夹体系还不成熟，需要在使用中逐步建立。

因此，优先让 AI 完成整理前的准备，把用户的操作从填写空白表单转为检查、调整和采用一份完整方案。资料说明和内容理解为这些建议服务，不能把生成更长摘要、更多标签或更多索引本身当作价值。

预期有两类收益：

- **当下减负：** 减少命名、标签选择和分类操作，用户只处理需要判断的部分。
- **后续可用：** 人工确认的管理信息与有原文依据的内容索引共同支持回找、资料理解和 AI 查询。

是否有效，需要比较原有整理耗时、采用建议的比例、修改与返工成本，以及后续能否找到相关资料；本次不设未经验证的准确率或节省时间承诺。

## 2. 当前决定与方案演进

| 讨论项 | 当前结论 |
| --- | --- |
| 默认方式 | AI 在待整理中预处理，用户确认后才完成整理并进入文档库 |
| 最终决策权 | 用户可以接受、修改或放弃建议；AI 建议生成不等于用户已经采用 |
| 自动入库 | 曾讨论并倾向直接自动整理，随后修正为保留用户确认节点；不作为当前默认方案 |
| 可选自动模式 | 保留为后续可选方向，须由用户主动启用；本轮未确定启用范围和规则，也未实施 |
| 文件夹 | 可选分类入口；确认后进入文档库，不要求每份资料必须放入分类文件夹 |
| 状态提示 | 在待整理中区分待预整理、处理中、已预整理待确认及失败 |
| 实施状态 | 后台预整理、状态筛选、批量确认与撤销已实现，最终桌面包已通过隔离测试；交付与测试证据见[专题验收](../reviews/AI预整理验收-2026-10-21.md) |

调整默认方式的原因是：分类体系尚在建立，自动执行后的纠错可能抵消减负收益。通过预填、集中展示和一次确认，同样可以减少操作，同时保留用户的介入节点。

## 3. 默认流程

**资料收录并登记 → 留在待整理 → AI 后台预处理 → 用户查看或调整方案 → 一次确认完成整理 → 进入文档库。**

1. 收录沿用既有资料身份、位置登记和版本规则。AI 不重新建立一份资料副本。
2. 在用户启用并明确允许的处理范围内，后台生成整理建议，不要求打开聊天窗口逐份指挥。支持选中批次，或主动开启当前库待整理及未来收录范围，见 §9。
3. 用户打开整理界面即可看到已经准备的方案。AI 生成建议本身不修改正式名称、标签关联、分类位置或整理状态；用户仍可按原有方式手工整理。
4. 用户可直接采用整套方案，也可修改个别项目，或放弃建议按现有方式手工整理。
5. 点击「完成整理」后，由 TeamHub 执行最终方案。成功的资料才进入文档库并出现在「全部资料」中；有分类文件夹时，同时从该分类入口可达。
6. 进入文档库后仍可调整名称、标签和分类。撤销本次整理恢复原名称、标签及待整理位置；不恢复内容版本，不覆盖后续修改。

批量场景采用同样原则：集中展示多份资料的方案，允许选择一批确认，不要求逐标签、逐字段审批。归属不明确、可能重复或疑似已有资料新版本等需要判断的对象应突出显示，不能据 AI 推测直接合并身份、删除文件或追加版本。

本轮不更改既有“至少一个有效标签即可完成整理、文件夹可选”的规则。没有可靠标签时允许用户补充，不伪造标签只为通过校验；没有合适文件夹时可以不分类。AI 不可用或预整理失败不阻断现有手工整理入口。

## 4. AI 预整理状态

待整理列表及整理界面采用以下四状态；内部对应 `waiting / processing / ready / failed`，处理中再区分排队与正在运行：

| 展示状态 | 含义 | 用户可做什么 |
| --- | --- | --- |
| **待 AI 预整理** | 尚未生成整理方案 | 按允许的范围启动处理，或直接手工整理 |
| **AI 预整理中** | 正在分析资料并准备方案 | 查看状态，仍可使用手工整理方式 |
| **AI 已预整理 · 待确认** | 已有可查看、可调整的方案，尚未应用 | 查看、修改、确认；支持集中筛选和批量确认 |
| **预整理失败** | 未能生成可用方案 | 查看具体原因，修复后重试，或手工整理 |

### 状态含义的边界

- 四种状态都发生在「待整理」中，不增加第三个资料仓库或主要整理状态。
- “AI 已预整理”只说明整理方案已生成，不代表用户已确认、资料已进入文档库、全文已读完或索引已完整建立。
- 部分内容未识别时，方案说明缺口；完全失败不能显示为已预整理。可用方案须通过结构校验并引用本任务实际取得的正文或图像来源；元数据、文件名和自然语言“已完成”不能代替阅读依据。无可靠标签可留空，等待用户补充。
- 状态筛选是查看同一批待整理资料的入口，不复制文件；用户确认后按原规则进入文档库。
- 正在生成的旧结果不得覆盖用户已保存的修改，也不得把已经手工整理完成的资料重新移回待整理。

## 5. 整理方案应包含什么

整理方案遵循以下原则：

| 项目 | 建议原则 |
| --- | --- |
| 名称 | 原名清楚时优先保留；名称含糊时提出更明确的名称，方便用户比较和修改 |
| 标签 | 优先复用已有适当标签，必要时建议新增；保留个人使用线索，不要求先建立固定行业词表 |
| 文件夹 | 优先推荐已有合适分类；没有合适入口可以留空，新增类别先作为建议，不批量制造深层目录 |
| 简短说明 | 用于快速核对建议依据；不要求用户再阅读长篇摘要，不因生成说明就自动覆盖现有描述 |
| 关联线索 | 提示可能相关的项目、设备、资料或版本，标明依据和不确定性；疑似关系不等于确定的资料身份 |
| 处理缺口 | 说明无法读取、归属不明确或缺少依据的部分，便于用户集中判断 |

现有标签和文件夹不成熟，不应成为启用 AI 辅助的门槛。通过用户实际采用与纠正逐渐积累分类关系，保持文件夹少而稳定、标签灵活。建议尚未确认时，不直接创建正式标签关联或移动工作文件。

人工修改优先；如何从纠正中提炼可复用偏好，属于后续可验证能力，本轮不承诺已经具备长期记忆或自动学习机制。

## 6. 与内容索引、资料状态的关系

| 信息 | 回答的问题 | 是否意味着整理完成 |
| --- | --- | --- |
| AI 预整理方案及状态 | AI 是否准备好了可采用的名称、标签和分类建议 | 否，仍须用户确认 |
| 内容索引及其覆盖状态 | 当前内容中有哪些可检索原文、位置、辅助线索和未处理部分 | 否，与预整理状态独立 |
| 正式整理元数据及资料状态 | 用户最终采用了什么名称、标签、分类，资料属于待整理还是文档库 | 成功执行完成整理后，才进入文档库 |

人工标签表达用户的使用习惯，内容索引表达资料中实际可发现的内容。二者共同服务查找，不能以 AI 索引代替人工标签，也不能只凭若干标签宣称已经理解全部内容。

内容索引目标继续沿用基石 §10.6：可检索的原文单元、来源位置、资料概览、辅助线索及覆盖缺口。具体问题提出后的深入推理不必全部提前到整理阶段完成。索引可在后台继续建设，不把深入索引全部完成设为用户确认整理的前提。

原文索引和新预整理以已保存版本为依据，原有单份 AI 标签建议入口仍读取工作文件。新预整理绑定版本与管理信息；来源或版本变化后，旧方案失效，不能借重试覆盖人工结果。采用时还核验工作文件与该保存版本一致，避免基于旧内容整理尚未保存的修改。

## 7. TeamHub 与 AI 伙伴的分工

| 部分 | 职责 |
| --- | --- |
| AI 能力 / Hermes 引擎 | 根据允许读取的资料和整理语境，提出名称、标签、分类及关联建议 |
| TeamHub 预整理任务 | 调度后台处理，记录状态、方案来源、缺口和用户选择 |
| TeamHub 资料管理服务 | 用户确认后执行命名、标签登记、分类和状态转换，沿用既有身份、版本与存储规则 |
| 用户 | 决定建议是否采用、如何调整，以及是否完成整理 |

预整理是资料整理流程中的后台能力，复用 Hermes 的单份资料阅读工具，以专用结构化方案工具结束任务，不要求每份文件都创建一段可见聊天。工具只生成建议，实际采用由 TeamHub 事务执行。

普通聊天直接发送的现行体验继续保留。这里的确认针对把整理方案应用到资料对象，不重新引入每次阅读、每个字段或每次内部工具调用的审批。

## 8. 后续验收应观察什么

工程验收覆盖以下行为；第 7 项真实业务价值仍需用户试用：

1. 未经用户确认，资料始终留在待整理，正式名称、标签关联和分类位置不因建议生成而变化。
2. 四种 AI 状态可辨认、可筛选；“AI 已预整理”不会被误解为已经进入文档库。
3. 一次操作可以采用整套方案；修改个别建议无需重做全部流程，批量确认无需逐字段审批。
4. 无分类文件夹的资料可以正常进入全部资料；至少一个有效标签的既有规则保持一致。
5. 手工整理、处理失败、用户修改、内容变化及重复确认时，不覆盖新结果、不重复创建资料、不混用过期方案。
6. 原文索引、AI 整理方案与正式管理信息各自可解释，索引未完成不阻断正常整理。
7. 用实际资料比较整理总耗时与返工成本，并检验后续查找效果；不以建议数量或模型调用成功率替代用户收益。

## 9. 本轮工程决定与后续范围

2026-10-21 将开发规则收敛如下，具体接口、任务预算和实现证据见[实施蓝图](AI预整理实施蓝图.md)：

| 事项 | 当前决定 |
| --- | --- |
| 启用与外发范围 | 默认关闭；一次启用固定批次或当前库待整理及未来收录。说明服务、资料内容和已有分类语境；服务配置变更暂停旧授权 |
| 后台授权与最终确认 | 范围启用在调用前完成；最终采用仅确认实际改名、标签、分类和入库，不逐工具审批 |
| 内容依据与过期 | 已保存版本、元数据与库身份绑定；采用核验工作内容一致，旧结果不覆盖人工修改 |
| 任务调度 | 独立有界队列、共享请求通道、聊天优先；显式取消或失败不自动重放付费请求 |
| 建议有效性 | 结构及来源校验、宿主补充阅读缺口；新标签待采用创建，目录只推荐已提供的分类，或留空 |
| 撤销与批量执行 | 按份事务、幂等采用、失败项保留输入；撤销仅恢复本次整理元数据和位置，后续变化或原标签身份冲突则停止 |
| 后续可选能力 | 自动入库、从纠正中自动学习偏好尚未纳入；不能与本轮自动准备方案混同 |

操作见[AI 预整理使用指引](../guides/AI预整理使用指引.md)。既有[单份标签建议](../guides/AI辅助整理使用指引.md)、[索引](../guides/资料内容索引使用指引.md)和[AI 伙伴](../guides/AI智能伙伴使用指引.md)仍保持各自职责，不因新流程取消手工整理或增加普通聊天确认。
