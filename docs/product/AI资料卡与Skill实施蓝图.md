# AI 资料卡与 Skill 实施蓝图

建立日期：2026-10-21；更新日期：2026-10-22。本文承接[项目基石](TeamHub项目基石.md)、[AI 智能伙伴实施蓝图](AI智能伙伴实施蓝图.md)和[AI 预整理实施蓝图](AI预整理实施蓝图.md)，记录版本化派生理解、阅读方法与维护规则。整理到准确检索的总体阶段以[AI 整理与准确检索实施蓝图](AI整理与准确检索实施蓝图.md)为准。

本文是实施依据；功能是否已通过工程验收，以当轮测试记录为准。模拟模型测试验证协议与流程，不能替代真实模型的资料理解质量评测。

## 1. 要解决的问题

原来的预整理方案包含一段 `summary`，混合资料摘要和命名、标签、分类理由，存于当前预整理任务结果。它主要帮助用户确认整理方案，重新预整理可能替换它；它不是受版本管理的长期资料理解，也没有天然接入后续检索。

新的目标是：**一次理解形成可复用的成果，帮助准确找回资料、辨认版本和定位原文，再支持后续分析。** 资料卡为检索服务，卡片数量、摘要流畅或字段丰富不能单独证明成功。

资料卡定义为：对某份资料某个已保存版本的结构化理解，附带原文依据和实际理解范围。它是派生数据，具有明确来源，不代替原文件、人工标签或用户补充。

基本原则：

- 名称、人工标签、文件夹、收藏仍由现有资料对象管理，不在资料卡中复制另一套主数据。
- “资料理解”长期保存；“为什么这样命名、分类”的整理说明留在预整理方案中。
- 用户确认整理方案，只授权采用名称、标签和分类，不等于逐项认证 AI 提取的事实。
- 资料卡在待整理阶段即可产生。采用、拒绝或稍后处理整理方案，不应丢弃已经有效保存的理解成果。
- AI 提炼的检索用语不自动成为人工标签，AI 可能的用途与来自原文的事实明确区分。
- 只处理系统登记并在当前任务授权范围内的资料。个人卡片不会因生成而自动共享到组织空间。
- 基础索引尽量覆盖支持范围内的全文、结构与来源。资料卡是派生理解层，快速阅读、简卡和抽样不能取代完整底稿；正文提取、图像识别及模型理解覆盖分别表达。

## 2. 卡片组成

采用“通用骨架＋按实际内容选择专项阅读方法”。首版保持稳定的通用数据结构，专项方法决定如何阅读、哪些事实值得提取，不制造多个无法互相检索的资料卡系统。

| 部分 | 首版结构 | 约束与用途 |
| --- | --- | --- |
| 内容概览 | `summary`、`document_type`、`topics` | 短摘要和主题帮助判断相关性，不塞入命名、分类理由 |
| 内容导航 | `sections[]`：标题、简述、来源编号 | 记录章节、页、工作表或内容区域，定位值得继续阅读的位置 |
| 关键对象与事实 | `facts[]`：名称、值、来源编号 | 保留对象与事实间的联系；设备参数不能脱离设备、单位、位置 |
| 检索线索 | `search_terms[]` | 记录原文用语及合理的查找表达，不冒充人工标签 |
| 可能用途 | `uses[]` | 作为 AI 建议展示，支持选文件；不表示资料足以回答任何相关专业问题 |
| 缺口 | `gaps[]` | 明确未读、未识别、信息缺失或无法确定的部分 |
| 依据 | `source_ids`、来源明细与位置 | 原文片段和可核对位置；关键事实、导航条目须有对应来源 |
| 覆盖范围 | 服务端阅读记录派生的 `coverage` | 标明真实读取范围；模型不得自行宣布“全文已理解” |
| 人工补充 | 独立注释、修订号、来源版本、跨版核对状态 | 用户提供的背景和修正，与 AI 生成字段分开，重新生成不覆盖 |

例如巡视记录应能表达“5053 断路器、2 号气室、压力 0.78 MPa”，同时记录时间、地点、判定依据缺失。没有原文依据，不能补造站点、人员或“正常/异常”判断。表格中的填写示例、模板提示、空白栏位也不能被提取为已经发生的业务事实。

## 3. Skill 框架

Skill 的作用是提供可执行的阅读和判断方法。它不能补足模型本身没有的视觉能力，也不能补救被工具漏掉的原文。完整能力来自模型、工具、上下文、工作方法与评测的配合。

### 3.1 三层组织

1. **共同约定**：简短、稳定地定义资料身份、已保存版本、原文依据、用户补充、事实与推断，不将所有专项方法放入每轮提示。
2. **任务 Skill**：资料理解与卡片生成、预整理、资料查找分析各自有目标和结束条件。普通聊天无需执行完整卡片工作流。
3. **专项方法**：根据观察到的结构按需读取文字、表格、视觉阅读方法。格式只提供线索，不能仅凭扩展名决定阅读策略；混合资料可以组合方法。

引用文档只有在运行时能被模型发现、读取才有意义。提供受限的技能资源读取工具：只可访问随 TeamHub 发布、登记在允许列表中的技能资源，禁止任意路径和目录遍历。按需读取技能本身不发送额外用户文件，也不需要新增用户确认。

### 3.2 每个 Skill 必须回答的六个问题

| 问题 | 要求 |
| --- | --- |
| 最终完成什么 | 明确资料卡或整理建议的任务产物、成功条件 |
| 当前已知什么 | 使用已保存版本、现有解析结果、已有卡片及可用工具；避免重复读取已有结果 |
| 如何选阅读方法 | 先观察结构，再读取相关专项方法；不默认所有 PDF 都是文字、所有 Excel 都是明细表 |
| 何时需要继续读 | 关键区域未覆盖、矛盾、单元含义不清、上下文不足时，扩大阅读或记录缺口 |
| 如何提交成果 | 遵守结构、引用真实来源、事实与可能用途分开，不为填满字段猜测 |
| 何时结束 | 达到本档预处理或专题任务目标；工具不可用、重复无进展或资源不足时，保留有效成果和缺口 |

### 3.3 专项方法首版重点

- **文字**：先看文档结构与用途，识别标题、正文、附录和引用；区分规范要求、建议、既有结果和背景描述；长文先建立导航，重点结论读取上下文。
- **表格**：先识别工作表与内容区域，再理解表头、合并区域、单位、说明、公式结果和数据范围；不默认第一行是表头；区分模板、示例和真实数据；抽样不能代表整表。
- **视觉**：辨别扫描页、图纸、照片和混排图片；先获得整体布局，再按需要读取局部；细节模糊、图例缺失、文字无法辨认时明确限制；不能用文字提取成功来推断图像也已理解。

Skill 应包含少量代表性案例与失败反例，示范证据何时足够、何时继续读取、缺失如何表达。案例用于指导判断，不让模型机械复述固定内容。文件中的指令性文字属于待分析资料，不得覆盖系统规则或引导读取其他未授权资料。

### 3.4 文件夹理解 Skill

整体收录的文件夹仍是一份资料。新增随应用发布的文件夹理解 Skill：先查看成员清单及目录结构，识别资料集合的大致用途，安排阅读顺序，再按成员内容选择已有文字、表格或视觉方法，最终形成整套资料的概览、内部导航和有依据的关联。目录和文件名只提供查找线索；同目录、相似名称不能单独证明项目归属、时间先后或版本延续。

Skill 要区分“列出成员”“读取成员结构”和“实际阅读内容”。预算内优先阅读能说明集合用途和关键关系的资料，保留未读、不可识别和矛盾之处，不能将抽样包装成整套资料已全面理解。成员内的指令不改变任务规则，也不能要求访问文件夹之外的路径。

### 3.5 独立对象 Skill 与多模态路由

对象层形成八种独立 Skill：文字、Word、电子表格、演示文稿、PDF、图片、文件夹、压缩包。入口按不可变保存版本名和真实文件夹身份分类，自动加载一份当前类型规则；文件夹和压缩包内的成员通过 `read_object_skill(kind)` 按需加载自己的规则。原有 text/tables/visuals/mixed 是可组合的阅读方法，继续用于解决具体内容难点，避免为每次任务加载全部规则。

分类与解码能力分开：Office 虽然内部使用 ZIP，仍按办公文档理解；压缩包是单个文件对象，不能伪装成文件夹或拆分为多个文档；已修改的显示名不能改变原快照的解析类型。图片结构提供尺寸、实际可知帧数和原图读取入口，不把零文字单元误当作无法整理。

压缩包工具为 `list_archive_members`、`read_archive_member`，读取文本、表格、PDF、图片和办公嵌图；来源延续父版本并增加成员相对路径。模型只读包内成员，不解压到工作目录，不重新压缩。嵌套包暂不递归展开，已加密或算法不可用的成员记录为缺口；有可读兄弟成员时可形成部分卡片。具体压缩格式和原生图片格式以本轮验收为准。

实现使用受限的本机解码子进程，不新增模型外发目标。图片、扫描页和图形仍通过当前已配置、支持图像输入的模型理解。接口拒绝图像时给出图像请求提示，用户可在 AI 设置测试实际图像能力；不能因工具或格式名存在就声称模型看到了内容。

生成规则组合升级为 v2。旧卡和人工补充保留；旧卡显示待更新，用户按需重新生成。规则变化不触发全库自动付费重算。独立 Skill、工具、宿主校验和效果评测共同决定实际能力，不能仅凭 Skill 文案宣布新对象已支持。

## 4. 生成流程与运行责任

流程：**固定已保存版本 → 建立/复用基础索引与结构 → 选择阅读方法 → 有界阅读与理解 → 提交结构化卡片 → 校验来源与实际覆盖 → 保存 → 建立检索入口。** 基础索引与卡片分别推进，不能由一次卡片任务实际阅读的内容决定整份资料唯一可搜索范围。

| 层 | 责任 |
| --- | --- |
| TeamHub | 资料和版本、权限、快照读取、持久任务与分块结果、进度/租约/预算、数据库、校验、取消、更新策略及搜索 |
| Hermes | 对话与阅读策略、组织步骤、调用已授权工具、按需读取专项 Skill、在宿主预算内推进 |
| 模型 | 内容理解、阅读策略、相关性判断、摘要和检索表达 |
| Skill | 规定目标、方法、证据与退出条件，不代替程序执行权限检查 |

程序可以验证来源编号和版本真实存在，不能仅据此认定该来源支持模型的每个结论。语义准确性必须通过质量评测和用户核对验证。

资料预处理分为两档，共用基础索引并复用理解成果：

1. **快速整理**：支撑命名、标签、可选分类及简卡，让用户尽快确认入库；AI 有界阅读不意味着正文只索引这一部分。
2. **深入建档**：建立更丰富的章节、工作表、页内与成员导航、对象事实和检索线索；沿用原底稿、有效来源及人工信息，如实记录预算和解析限制。

**专题分析**是独立对话任务。用户提出问题后，伙伴找回资料并读取原文，进行核对、计算或综合；不是第三级整理，也不需要先完成深入建档才能发起。以上是产品分工，档位切换、精确续读等运行能力须按总蓝图逐阶段实现和验收。

“补全”表示尝试完善，不保证每种文件最终都被全面识别。首版不启动未经授权的全库后台付费分析，也不因普通聊天自动重建整库卡片。

执行时将已有卡片的摘要、导航位置、缺口和独立人工补充作为阅读线索传入；跨版本信息明确标识待核对，旧来源编号不继承为本轮证据。2026-10-21 首版提交自包含的新卡片，需要重新读取所引用的原文，未实现跨任务精确游标缓存或卡片分段增量合并。本轮新增索引片段的持久发布不等于这些能力已经完成。若新的阅读覆盖少于已有成果，保留原卡片并说明原因，避免一次短阅读覆盖原有理解。

### 4.1 整体文件夹的读取与产物

文件夹预整理和独立资料卡生成复用同一条任务流程，输入是整体文件夹当前已保存版本的 ZIP 快照，产物是父资料的一张汇总卡片及整套资料的命名、标签、分类建议。

- `list_folder_members` 分页提供快照成员清单；`read_folder_member` 按清单中的相对路径读取成员结构、文字、表格、原页图像或内嵌图片。按需读取，不把整包内容一次发给模型。
- TeamHub 校验归档完整性、成员路径和大小，只读取固定快照中的成员，不跟随符号链接、不读取工作目录或任意本机路径。所有成员共用本次任务的证据和图像预算。
- 来源保持父资料 ID、父版本及整体内容哈希，在来源位置中加入 `member_path` 和成员内的页、工作表或段落位置。相同页码、单元格坐标在不同成员中必须区分。
- 覆盖由宿主按成员记录，汇总总成员、已读成员及实际内容覆盖。查看清单不算读过正文；未读、超限、不支持或视觉不可用的内容明确留为缺口。
- 成员理解汇入父卡片的导航、事实和检索线索。本轮不创建成员级资料对象、独立版本或独立持久资料卡；不重命名、移动、拆分或删除成员。用户确认后，整套文件夹按原有整理规则移动，内部结构保持完整。

选择文件夹进行预整理或生成资料卡，范围包含该已保存版本内按需读取的成员。成员读取不增加逐文件确认；仍沿用服务显示、一次启动、取消和配置变化后的授权规则。自动更新以父资料为单位：整套内容保存为新版本后，只有该资料已启用自动更新才重新分析；恢复历史版本时复用仍有效的对应卡片。

这次扩展只开放预整理和资料卡任务的成员读取。普通伙伴对话可以利用汇总卡片查找和定位，但不因此获得直接读取文件夹成员原文的工具；不得把卡片当成本轮原文证据。

## 5. 保存、人工修正与更新

### 5.1 保存关系

资料卡与本机资料数据库同库保存，随资料库备份和迁移。以资料身份、已保存版本及内容哈希绑定来源，并记录卡片修订、生成时间、模型及生成方法版本。

- 文件内容版本和卡片修订是两条不同的记录。改善对同一版本的理解不创建新文件版本。
- 预整理任务可以被替换，独立保存的资料卡不依附于那条临时任务结果。
- 人工补充独立保存，具有修订号和来源版本。跨版本保留，但明确提示待核对。
- 人工补充采用乐观并发检查；发生冲突保留用户输入，刷新后展示服务器已保存内容，用户核对后再决定合并，不能静默覆盖。
- 重新生成先形成并验证新结果，失败不能使已有有效成果消失；不把旧版卡片伪装成当前版本理解。

### 5.2 更新规则

| 事件 | 处理 |
| --- | --- |
| 新内容保存为新版本 | 旧卡保留版本关系，当前卡显示待更新；只有该资料明确开启持续分析，才排队自动更新 |
| 仅更名、调整标签、分类或收藏 | 管理信息继续从资料对象读取，不因位置变化重读正文 |
| 恢复历史版本 | 以该版本对应的有效卡片作为当前理解；不存在有效卡片时显示待生成 |
| 人工补充或修正 | 更新独立注释和可用检索信息，不覆盖 AI 原文来源标记 |
| 模型、服务或生成方法变化 | 不自动引发全库付费重算；持续分析遇到目标服务或模型变化暂停，按新目标重新启用 |
| 生成过程中版本、库或授权变化 | 丢弃不再符合当前上下文的提交，不能把旧任务结果写给新版本 |
| 删除资料、版本或权限变化 | 资料卡及搜索结果跟随来源的访问与生命周期约束，不独立暴露已经不可访问的信息 |

持续分析默认关闭，以单份资料为单位。用户可以在显示目标服务和模型后，随一次明确的生成动作启用；可以单独关闭。关闭页面不等于取消已经发出的模型任务，需要明确取消；已经发送的请求可能计费。

## 6. 如何使用

### 用户界面

详情与待整理整理界面提供“AI 资料卡”。默认展示短摘要、当前理解状态和来源版本；内容导航、事实、用途、检索词、覆盖范围及依据按需展开。旧版卡片折叠展示并标明旧版。人工补充与 AI 摘要有明确视觉区分。

预整理审阅中的“整理说明”继续解释命名、标签和分类理由；卡片只读预览单独按需展开，且不随整理确认 payload 提交。原文索引保留，原有 AI 摘录增强作为兼容入口收起，避免用户误以为需要重复执行两套流程。

### 搜索和伙伴

检索联合使用名称、人工标签、原文和当前资料卡线索，按资料合并候选。当前推进持久片段、当前版本隔离、多词及字面匹配、相关性排序和具体命中片段；本轮集成与验收完成后再确认交付范围。伙伴通过卡片判断相关性和阅读位置，再读取原文形成有依据的回答。

卡片不是原文事实的替代来源；搜索命中用户补充时须保留用户来源标记，跨版待核对的信息不能自动变成当前版本已证实事实。失效卡片不能继续作为当前内容事实的依据。

首版复用本机原文检索设施和现有工具协议。后续真实 Embedding 语义召回与 SQLite FTS5 词法结果通过 RRF 融合，并在回答前回到原文核验；不要求为此改写原件或依赖组织云端。本轮不将现有关键词工具或卡片检索称为已接入真实向量语义检索。

## 7. 验收与质量评价

### 工程验收

- 正常生成、部分理解、取消、失败、恢复、重复请求和任务重启的状态明确。
- 已保存版本、资料身份、来源编号、服务与库授权均经服务端核验。
- 任务中切换资料、资料库、版本或关闭页面，不展示迟到的旧响应；前端请求可中止。
- 服务变化后不自动向新目标重发资料；生成与持续分析有明确范围和撤销入口。
- 人工注释不被轮询、AI 生成和并发写入覆盖；冲突保留输入。
- 预整理应用只修改原有名称、标签、分类字段，不把资料卡当作人工编辑字段写回。
- 检索过滤失效、已删除或不可访问的来源，用户补充与原文事实不混淆。
- Skill 路径读取严格限于发布资源，打包包含真实可加载的参考资料。
- 文件夹覆盖成员路径隔离、同名成员、混合格式、不可读及超限成员、部分阅读和整体版本失效；成员原件与目录结构在生成建议时保持不变，确认与撤销仍以整体资料执行。

### 模型质量评测

固定模型、工具、资料和大致预算，比较旧流程与新 Skill：

| 维度 | 观察点 |
| --- | --- |
| 内容覆盖 | 是否识别重要章节、工作表、图像及确实未读的部分 |
| 事实与依据 | 是否误造对象、遗漏单位或范围；引用是否真正支持结论 |
| 检索收益 | 真实检索集的前 5/10 召回与精度、版本混淆和位置正确性，单列未进入索引的范围 |
| 交互成本 | 用户需要修改的次数、重复读取、模型调用、等待与费用 |
| 不确定性 | 缺失、矛盾、无法识别和无法回答时是否如实表达 |

样本覆盖短文、长文、模板表、多区域表格、扫描件、混合图文及缺失信息；保留未参与 Skill 调优的样本。真实业务资料外发必须在既有授权范围内，不因跑测试而自动调用用户的真实付费服务。

## 8. 本轮边界与后续扩展

2026-10-21 首轮目标是建立“生成—保存—检索—原文核对—更新”的闭环，保持本地与云端解耦。首版允许单份卡片较简洁，前提是确实可复用、可追溯和可更新；简洁卡片不能成为减少全文覆盖的理由。

2026-10-22 起按[准确检索总蓝图](AI整理与准确检索实施蓝图.md)推进：先做持久原文片段、相关性和具体命中位置，再做可续的分块解析/理解、成员缓存及真实语义混合检索。文件夹缓存绑定父资料、成员相对路径、成员内容哈希及生成规则，优先更新变化成员，再重建汇总；当前卡片任务尚无精确的持久成员理解缓存或增量合并，重新生成仍可能重读。全格式大文件流式解析、全库自动视觉识别、真实 Embedding 和更丰富的专业方法不能提前宣称已完成。跨资料关联、组织共享卡片和偏好学习继续根据真实收益选择。
