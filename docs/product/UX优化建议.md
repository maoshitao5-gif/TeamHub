## 二、详细优化建议

### 1. 搜索与过滤体验

**现状描述**

`LibraryPage.vue` 顶部搜索栏仅支持单关键词模糊搜索，配合标签多选下拉筛选。无高级过滤选项，无搜索历史，关键词在结果中不高亮。

**存在问题**

- 无法按文件类型、文件大小、修改时间等维度精确筛选
- 标签筛选使用 `el-select` 下拉多选，当标签数量多时操作不直观
- 搜索无结果时仅显示空状态，没有引导用户下一步操作
- 关键词在结果列表中不高亮，难以快速定位匹配内容

**具体建议**

1. **高级搜索面板**：在搜索框右侧添加"高级"展开按钮，展开后显示：
   - 文件类型多选（PDF / Word / 图片 / 视频 / 其他）
   - 文件大小范围滑块（< 1MB / 1-10MB / > 10MB / 自定义）
   - 时间范围选择（今天 / 本周 / 本月 / 自定义区间）
2. **搜索历史**：本地存储最近 10 次搜索关键词，搜索框获得焦点时下拉展示
3. **空结果引导**：搜索无结果时展示"未找到匹配文档，是否新建文档？"快捷入口
4. **关键词高亮**：文档名称中高亮显示搜索关键词（`<mark>` 标签 + CSS 高亮色）
5. **标签云替代下拉**：将标签筛选从 `el-select` 改为标签云（水平滚动排列的可点击 Tag），点击切换选中状态，更直观

**实现难度**：中（高级搜索面板需要前后端联动扩展查询参数，标签云改造纯前端）

### 2. 标签管理体验

**现状描述**

整理对话框的标签输入依赖 `computed` 属性实时计算 + `onKeydown` 拦截 Enter 键，计算量大；标签管理页需要点击编辑按钮才能修改名称；`Tag` 数据模型已有 `color` 字段，但 UI 中未充分展示颜色。

**存在问题**

- 标签输入框在大标签列表下存在卡顿（每次键入触发 computed 重新计算）
- 标签管理页编辑流程繁琐（点击编辑 → 输入 → 保存 → 关闭）
- `color` 字段数据存在但颜色在文档列表中展示不一致
- 缺少标签使用频率统计和可视化

**具体建议**

1. **输入防抖**：标签输入框 `v-model` 改为防抖绑定（300ms），减少 computed 触发频率
2. **行内编辑**：标签管理页支持双击标签名称直接行内编辑，按 Enter 保存，按 Escape 取消
3. **颜色选择器**：标签编辑时显示颜色选择器（Element Plus `el-color-picker`），在文档列表标签徽章中统一展示颜色
4. **全局标签云**：在标签管理页顶部添加标签云可视化，按使用频率调整字体大小（最少 12px，最多 24px）
5. **整理弹窗标签预览**：整理对话框的标签输入改为带颜色点预览的 Tag 组件，新增的标签实时显示颜色预览

**实现难度**：低-中（防抖和行内编辑纯前端，颜色展示需小量 API 联动）

### 3. 文档整理流程优化

**现状描述**

整理对话框通过目录树组件选择目标路径，操作步骤较多（展开树 → 找到目标目录 → 点击选中）；没有"最近使用目录"快捷选项；批量整理后无操作摘要。

**存在问题**

- 重复整理到同一目录需要每次重新浏览目录树
- 批量整理后用户不清楚实际执行结果（成功 N 个，失败 M 个）
- 误操作后无法快速撤销，只能手动重新移动文件

**具体建议**

1. **最近使用目录**：整理对话框顶部添加"最近使用"区域，展示最近 5 个整理目标目录（本地 localStorage 存储），一键选中
2. **操作摘要弹窗**：批量整理完成后显示摘要通知：
   ```
   整理完成
   ✓ 成功整理 12 个文件到 /归档/2026年
   ✓ 分配标签：年度报告, 财务
   ✗ 失败 1 个（权限不足）
   ```
3. **短时撤销**：整理操作完成后 30 秒内在通知栏显示"撤销"按钮，点击可回滚文件位置（仅 move 模式支持）
4. **拖拽支持**：整理对话框中允许从系统文件管理器拖入目标文件夹，自动填充路径

**实现难度**：中（最近目录纯前端；撤销需后端新增回滚接口）

### 4. 进度反馈与后台任务

**现状描述**

文件夹递归扫描、批量整理等耗时操作使用模态进度对话框（`el-dialog` + 进度条），对话框打开期间用户无法进行任何其他操作。

**存在问题**

- 模态进度弹窗强制阻塞用户，无法同时查看其他文档
- 任务运行时无法查看当前处理到哪个文件
- 操作完成后无持久化通知（消息条 3 秒后消失）

**具体建议**

1. **非模态进度条**：将进度弹窗改为右下角浮动通知条（宽 320px），可最小化，显示任务名称 + 进度百分比 + 当前处理文件名
2. **任务队列面板**：添加右下角"任务中心"图标按钮，点击展开任务列表（类似浏览器下载管理器），展示运行中和已完成的任务
3. **暂停/继续**：批量整理支持暂停，暂停后可继续，可取消（取消时已完成的部分保留）
4. **系统通知**：任务完成后通过 Electron `Notification` API 发送桌面通知（即使应用最小化也能收到）

**实现难度**：中-高（需重构批量操作为异步任务模型，前端实时轮询或 WebSocket 推送进度）

### 5. 文档详情 Drawer 体验

**现状描述**

文档详情 Drawer 宽度固定（约 480px），版本历史仅展示列表，无法下载旧版本；添加新版本需在输入框手动输入文件路径，不支持拖拽。

**存在问题**

- 固定宽度不适应不同分辨率，文件名较长时截断
- 版本历史无法恢复/下载旧版本（核心功能缺失）
- 添加版本的路径输入框体验差，需要手动输入完整路径
- 版本间无差异对比

**具体建议**

1. **可拖拽宽度**：Drawer 左边框添加拖拽手柄，允许调整宽度（最小 360px，最大 800px），宽度记忆到 localStorage
2. **版本下载**：版本历史每行添加"导出"按钮，弹出路径选择对话框（调用 `window.electronAPI` 文件保存对话框），复制旧版本文件到指定位置
3. **文件拖拽添加版本**：添加版本区域支持拖拽文件到 Drawer，自动填充路径并触发确认
4. **版本对比**：选中两个版本后显示对比信息（文件大小差异、修改时间差、文件名变化）
5. **键盘导航**：
   - `Escape`：关闭 Drawer
   - `←` / `→`：切换版本时间线
   - `Ctrl+D`：触发下载当前选中版本

**实现难度**：中（拖拽宽度纯前端；版本下载需后端提供文件导出接口）

### 6. 批量操作体验

**现状描述**

选中多个文档后底部出现固定操作栏，包含"整理"、"删除"、"添加标签"等按钮。操作前无确认摘要，完成后仅短暂消息提示。

**存在问题**

- 批量删除等危险操作仅有简单确认对话框，缺少影响范围说明
- 不区分"全选当页"和"全选全部"，分页场景下容易误操作
- 批量操作结果不可追溯（消息条消失后无法查看）

**具体建议**

1. **操作预览提示**：底部操作栏按钮 hover 时显示 tooltip，说明操作范围：
   - `"将对已选中的 15 个文件执行整理"`
   - `"将删除 15 个文件（移入回收站）"`
2. **全选区分**：选中全页时显示提示条 `"已选中本页 20 个文件，点击选中全部 356 个文件"`（参考 Gmail 模式）
3. **操作结果持久化**：批量操作完成后结果记录到"操作历史"面板（右下角），可查看最近 20 次批量操作的详情
4. **标签分布可视化**：批量操作"添加标签"前，显示已选文档现有标签分布（"已有 8 个文件含标签'合同'，7 个无标签"）

**实现难度**：低-中（全选提示纯前端；操作历史面板需要少量本地存储）

### 7. 待整理页面工作流

**现状描述**

`PendingPage.vue` 展示待整理文件列表，支持智能扫描给出整理建议，但"一键应用"后无法单独拒绝某条建议；文件卡片信息密度较低（仅文件名 + 基本信息）。

**存在问题**

- 智能扫描建议全部接受或全部拒绝，缺少细粒度控制
- 文件卡片缺少视觉预览，图片/PDF 文件无缩略图
- 逐一处理大量文件效率低，缺少快速整理模式

**具体建议**

1. **逐条接受/拒绝**：智能扫描结果每条建议独立显示接受（✓）/ 拒绝（✗）按钮，支持逐条确认，已拒绝的建议变灰但不消失（可重新接受）
2. **文件缩略图**：
   - 图片文件：显示图片缩略图（通过后端 `/api/thumbnail` 接口生成）
   - PDF 文件：显示首页预览
   - 其他文件：按文件类型显示图标（已有逻辑可扩展）
3. **快速整理模式**：添加"快速整理"按钮，进入全屏卡片模式，每次展示一个文件：
   - 显示文件预览（尽可能）+ 建议整理目录
   - 快捷键：`→` 或 `Space` 接受建议，`←` 或 `Delete` 跳过，`E` 自定义编辑
4. **自定义排序**：待整理列表支持拖拽调整文件处理顺序，顺序记忆到本地

**实现难度**：中（逐条接受/拒绝纯前端状态管理；缩略图需后端新增接口；快速整理模式为新页面）

### 8. 导航与信息架构

**现状描述**

顶部导航包含"文档库"、"待整理"、"标签"、"回收站"、"设置"五个文字标签，无图标、无当前位置面包屑、无目录结构侧边栏。

**存在问题**

- 文档库缺乏目录树视图，无法按文件夹浏览已整理文件
- 文档数量多时缺少快速返回最近访问的机制
- 导航栏在小窗口下标签文字可能被截断

**具体建议**

1. **目录树侧边栏**：文档库页左侧添加可收起的目录树面板（默认展开）：
   - 展示已整理文件的目录结构
   - 每个目录节点显示文件数量徽章
   - 点击目录节点过滤右侧文档列表
   - 侧边栏宽度可拖拽（最小 160px，最大 320px），收起状态显示展开图标
2. **面包屑导航**：目录树选中某目录时，文档列表顶部显示面包屑（"文档库 / 归档 / 2026年"），点击任意层级可跳转
3. **最近访问**：导航栏添加"最近访问"下拉（最多显示 8 个最近打开的文档 Drawer 记录），快速跳回
4. **导航图标化**：每个导航项添加图标，窗口宽度 < 900px 时自动收起文字只显示图标（配合 tooltip）

**实现难度**：中（目录树侧边栏需要后端扩展目录统计接口；其余纯前端）

### 9. 错误处理与用户引导

**现状描述**

错误通过 `ElMessage.error()` 显示（3-5 秒后消失），无持久化错误历史；首次使用无引导流程；空状态页面（待整理为空时）仅显示默认空状态图。

**存在问题**

- 错误消息转瞬即逝，用户来不及记录错误内容
- 首次使用用户需自行摸索核心功能
- 空状态缺少积极引导，用户不知道下一步该做什么
- Windows 权限相关错误提示不够具体（仅显示 "操作失败"）

**具体建议**

1. **错误历史面板**：右下角添加"通知中心"图标，错误、警告级别消息自动记录到面板，保留最近 50 条，可逐条清除
2. **缺失文件操作**：`status: "missing"` 文件的警告弹窗添加"在资源管理器中定位"按钮（调用 `shell.openPath` 打开文件库目录）
3. **新手引导**：首次设置文件库后触发 5 步 onboarding tour（使用 [Intro.js](https://introjs.com/) 或纯 CSS 实现）：
   - Step 1：文件库概念介绍
   - Step 2：如何添加待整理文件
   - Step 3：如何整理文件（演示对话框）
   - Step 4：标签系统说明
   - Step 5：版本管理介绍
4. **空状态优化**：
   - 待整理为空：显示插画 + "拖拽文件到此处开始整理" + "打开文件夹添加文件"按钮
   - 文档库为空：显示插画 + "还没有整理任何文件" + "立即添加文件"按钮
   - 搜索无结果：显示"未找到 '{keyword}'" + "清除搜索"按钮
5. **权限错误优化**：检测到 Windows 权限错误（`EPERM` / `EACCES`）时提供具体建议（"请以管理员身份运行" 或 "检查文件夹权限"），并附操作步骤说明

**实现难度**：低-中（空状态和错误历史纯前端；新手引导需集成第三方库）

### 10. 设置页面体验

**现状描述**

设置页分为 5 张卡片（基础设置、版本管理、自动化、存储方式、文件库信息），每张卡片有独立"保存"按钮，逻辑割裂。存储方式用文字 radio 选择，不够直观。

**存在问题**

- 用户修改后需要逐张卡片点击"保存"，流程繁琐
- 修改设置后未保存离开页面无提醒（数据丢失风险）
- 存储方式（move/copy/index）的区别仅靠文字说明，不够直观
- 版本管理设置无当前磁盘占用统计

**具体建议**

1. **自动保存**：设置改为修改即自动保存（debounce 1000ms 后触发保存请求），页面顶部显示"已自动保存"状态提示；移除各卡片独立保存按钮
2. **未保存离开提醒**：如保留手动保存模式，导航离开设置页时检测未保存变更，弹出确认对话框
3. **存储方式图形化**：将三种存储方式改为卡片式选择：

   | 图标 | 移动文件 | 复制文件 | 仅索引 |
   |------|----------|----------|--------|
   | ↗️ 箭头图 | 原位置文件移入文件库 | 保留原文件，文件库保存副本 | 文件原地不动，仅记录路径 |
   | 节省空间 | ✓ | ✗ | ✓ |

4. **版本占用统计**：版本管理卡片添加"当前版本文件占用空间：1.2 GB / 上限 5 GB（刷新）"统计，刷新按钮实时重新计算
5. **配置导出/导入**：设置页底部添加"导出配置"（将 `config.json` 保存到用户指定位置）和"导入配置"（从备份 JSON 恢复设置），便于迁移到新设备
6. **文件库刷新按钮**：文件库统计卡片右上角添加手动刷新图标按钮

**实现难度**：低（自动保存前端 debounce 即可；图形化卡片纯 CSS 改造；导出/导入需后端小接口）

### P0-2：清理 console.log 调试日志
