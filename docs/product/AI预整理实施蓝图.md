# AI 预整理实施蓝图

更新日期：2026-10-22。依据：[产品方案](AI预整理与用户确认产品方案.md)。本文保留 2026-10-20—21 已实施的工程约定；隔离测试及当时桌面包的验证证据见[预整理验收](../reviews/AI预整理验收-2026-10-21.md)。2026-10-22 整理到检索的主次、两档预处理及后续工程阶段以[AI 整理与准确检索实施蓝图](AI整理与准确检索实施蓝图.md)为准，真实模型建议及回找质量仍须业务资料验证。

## 1. 本轮闭环

待整理 → 在明确允许的范围内后台生成方案 → 查看、调整 → 一次确认进入文档库。保留手工整理。至少一个有效标签，文件夹可空；本轮不提供跳过最终确认的自动入库模式。

自动预整理默认关闭。用户可以启动选中批次，也可以主动开启**当前个人库待整理及以后新收录的资料**。启用界面一次说明目标服务、读取已保存版本、可能发送文字和图像，以及已有标签和分类名称会作为整理语境；不逐文件、逐工具弹窗。修改服务或模型后暂停原授权。密钥配置不代表后台外发授权。

2026-10-22 明确：预整理首先服务后续准确找回资料。快速整理与深入建档是两档预处理；前者尽快形成可确认的方案与简卡，后者丰富导航、对象事实和检索表达，两档共用尽可能完整的基础索引。专题分析是独立对话任务，不是第三级整理。档位选择和跨任务精确续读仍按总蓝图分阶段实现；本节不宣称已有切换界面。用户确认入库规则保持适用，索引未完成时单独显示覆盖和缺口。

## 2. 职责与内容边界

- TeamHub 管理任务、授权、资料身份、事务、方案持久化与撤销。
- Hermes 使用当前目标资料的只读工具，提交结构化 `propose_organization` 方案；不开放任意文件系统或数据库操作工具，不传递实际 API 密钥。工作进程不是操作系统级沙箱，资料权限由 TeamHub 工具边界校验。
- 预整理使用独立工具集，不扩大聊天工具权限、不生成可见聊天会话。有效方案提交即结束，避免额外总结请求。
- 根据已保存版本生成方案；工作副本未保存修改时不得无提示采用旧内容的方案。建议生成和采用均核验版本及管理信息，采用另外核验实际工作内容。
- 最初单文件阶段曾不支持整体文件夹；2026-10-21 已扩展为按整套快照读取成员，形成父资料的汇总卡片及整体名称、标签和分类建议，见[文件夹验收](../reviews/文件夹AI整理验收-2026-10-21.md)。文件夹、压缩包内部结构与整体身份保持，成员不自动拆成新资料。作为分类目标的文件夹是另一概念。
- 分类语境只包含有界的标签名称和已有分类目录；不为了关联建议读取其他资料正文。关联先以有依据的项目、设备等文字线索表达。
- 原文索引仍独立运行，尽量覆盖支持范围内的全文、结构及位置。方案完成不意味着全文阅读或索引完整；不能只索引 AI 抽样阅读内容，未读、未识别部分明确列入缺口。解析、视觉识别和 AI 理解覆盖分别记录，来源 ID 存在不代表其中的判断已经正确。

## 3. 状态、调度与失效

面向用户只有 `waiting / processing / ready / failed` 四种状态，分别对应待 AI 预整理、AI 预整理中、AI 已预整理 · 待确认、预整理失败。`processing` 内区分 queued / running。正式资料状态仍只有 pending / organized 等既有生命周期状态。

独立队列单并发，复用现有 AI 收费租约；聊天优先。每份初始预算为 12 次模型请求、32 次工具调用、16000 输出 token、180 秒。后台不得无限重试。尚未执行的排队任务可恢复；运行中崩溃、取消、网络失败或付费状态未知的任务不自动重放。

以上是已实施首版的单次执行预算，不是大文件的长期产品上限。后续由 TeamHub 持久任务分批保存解析片段、游标、覆盖及累计用量，达到预算保留成果并允许继续；原文件大小不应一刀切导致整份整理成果丢失。现有解析安全上限、一次任务及模型上下文限制仍实际存在，R1 片段持久化不等于已完成全格式大文件续处理。租约、缓存和不确定付费请求的恢复策略见总蓝图 §5—7。

授权、服务配置、库绑定、任务 generation、资料保存版本、名称、标签与位置都参与守卫。切库、取消、手工整理、换版或修改管理信息后，旧结果不得写回。取消后自动模式不重新认领同一内容，用户可以明确重试。

## 4. 方案与确认

结构化建议主体：

```json
{
  "name": "便于查找的名称，保留原扩展名",
  "tags": ["已有或建议的新标签"],
  "target_dir": "",
  "summary": "便于用户核对的简短说明",
  "related_clues": ["有原文依据的项目或设备线索"],
  "gaps": ["尚未识别或未读的部分"],
  "source_ids": ["S1"]
}
```

`target_dir` 只能为空或本次提供的已有分类目录；新分类的想法可放在说明中，AI 不自动创建目录。名称禁止路径与控制字符；来源必须由本任务真实阅读生成，不能只根据文件名生成假定的内容方案。标签可以为空，界面要求用户补充后再确认。

宿主附加 proposal ID、文档 ID、源版本/hash、管理信息指纹、来源明细、实际阅读进度、usage 和更新时间。模型不能自报这些可信字段。

采用时以资料为事务单位，统一改名、标签、工作文件位置和 organized 状态，同时保存 before/after 记录。批量逐项返回结果，失败项保留用户输入。request ID 实现重复提交幂等。

撤销仅恢复该次整理的名称、标签、位置和 pending 状态，不恢复或改写内容版本。当前资料与整理后的记录不一致、工作内容改变或原位置被占用时拒绝撤销并说明原因，不覆盖后续修改。保留历史采用记录；不删除可能被其他资料使用的全局标签。

## 5. 接口约定

统一前缀 `/api/ai/preorganize`，沿用本机 AI 请求与桌面 capability 校验。所有写请求携带 `library_token`，防止旧页面操作另一资料库；所有发起外部调用的请求还需当前 `service_revision` 和 `consent: true`。

| 方法与路径 | 输入与输出 |
| --- | --- |
| `GET /config` | 返回 `library_token`、`service_revision`、`service`、`configured`、`policy: {enabled, active, paused_reason}` |
| `GET /documents` | `search`、`state`（空或四状态）、`page`、`page_size`；返回 `items`（现有资料字段 + `preorganize`）、`total`、四状态 `counts` |
| `GET /documents/{id}` | 返回 `document_id, state, phase, proposal_id, error, proposal, sources, progress, source_version, updated_at`；失效方案不可作为 ready 返回 |
| `POST /start` | `library_token, service_revision, consent, request_id, document_ids`，最多 100 份；返回 `items`（逐项状态） |
| `PUT /policy` | `library_token, service_revision, consent, enabled`；关闭不需要外发授权，返回 config |
| `POST /cancel` | `library_token, document_ids`；取消所选排队及运行任务，返回逐项状态 |
| `POST /apply` | `library_token, items: [{document_id, proposal_id, request_id, name, tags, target_dir}]`；返回 `items: [{document_id, ok, operation_id?, error?}]` |
| `GET /operations` | 最近 10 次采用/撤销记录，用于刷新后找回撤销入口；包含 `id, document_id, document_name, applied_at, undone_at` |
| `POST /operations/{id}/undo` | `library_token`；成功返回 `operation_id, undone: true` |

`preorganize` 摘要及详情统一采用 `state`、`phase`、`proposal_id`、可读 `error`、`gaps`。所有失败项的 `error` 为可直接展示的字符串。已保存方案的 `proposal` 使用 §4 主体；读详情不会发起 AI 调用。

## 6. 交互与验收

待整理顶部提供状态筛选、所选批次启动、当前库自动预整理开关和最近整理撤销入口。卡片显示四状态，ready 可查看方案，失败可重试，处理中可取消。手工整理入口始终可用。

审阅支持单份和批量，复用现有标签与可选目录选择器；同一窗口集中展示并一次确认。后台状态轮询不得清空选择、修改正在编辑的表单，或让打开的对象随翻页消失。切库、关闭、卸载后丢弃迟到响应。旧卡片“撤销”明确为“撤销收录”。

验证顺序：测试先失败 → 实现 → 针对性回归 → 独立代码/安全审查 → 后端及前端回归 → 使用真实 Hermes、合成资料和本机模拟模型的桌面端闭环 → 打包与启动验证。模型质量仍须实际业务资料试用评估；模拟模型测试只能验证流程与边界。
