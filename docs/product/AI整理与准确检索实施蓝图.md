# AI 整理与准确检索实施蓝图

**更新日期：2026-10-23。** 本文承接[项目基石 §10.9](TeamHub项目基石.md#foundation-accurate-retrieval)、[资料卡与 Skill 蓝图](AI资料卡与Skill实施蓝图.md)和[预整理蓝图](AI预整理实施蓝图.md)。目标是让 AI 准确找回用户需要的资料及其原文位置；整理、卡片、方法和任务系统都服务这一目标。

本文区分已存在的基础、本轮实现及后续设计。R1 的实际范围和证据见[第一阶段验收](../reviews/AI整理与准确检索第一阶段验收-2026-10-23.md)；后续阶段不因蓝图形成而视为交付。真实业务检索效果不能由模拟模型测试代替。

## 1. 产品决定与成功含义

1. 用户用名称、标签、业务语言、编号、参数或自然问题寻找资料时，系统应尽量找回正确资料、正确版本和可核对的原文位置。
2. 快速整理和深入建档是两档资料预处理，差别在 AI 理解、导航和派生线索的丰富程度。两档共用尽可能完整的基础索引，不以低档位为由只索引摘要或抽样正文。
3. 专题分析是用户围绕问题发起的独立对话任务，可复用底稿、卡片和来源，按需补读、计算、比较及生成成果；它不是整理流程的第三级，也不作为入库门槛。
4. 沿用“后台准备方案 → 用户查看或调整 → 一次确认入库”。整理成功、索引覆盖、AI 阅读深度分别表达；手工整理和 AI 不可用时的原文查找仍有价值。
5. 完整是处理目标与可测量范围，不是对任何文件、任何大小或所有问题的绝对找回承诺。解析、识别、检索、版本、权限和问题表达都会影响结果。

| 产物 | 解决的问题 | 不应替代什么 |
| --- | --- | --- |
| 原件与固定版本 | 保留真实内容和版本依据 | 不因改进检索而改写原件 |
| 基础索引与片段 | 覆盖可处理正文、结构和原文位置 | AI 摘要、抽样和简卡不能替代全文覆盖 |
| AI 资料卡、识别与线索 | 解释内容、增加业务表达、导航和语义入口 | 派生判断不能冒充原文事实 |
| 名称、人工标签和补充 | 保留用户的使用方式与背景 | 不要求用户先建立完美分类体系 |
| 专题任务成果 | 回答具体问题，核对、综合、计算 | 不能倒推未阅读部分已被理解 |

## 2. 当前基础与本轮边界

以下是 2026-10-22 本轮变更前已核对的基础，不表示所有后续设计已经实现：

- `DocumentIndex` 保存当前已保存版本的解析结果、generation 和状态；`IndexText` 与 SQLite FTS5 trigram 提供原文、AI 线索、资料卡及用户补充的搜索投影。
- 现有搜索主要按完整输入作字面匹配，资料列表按名称排序；FTS 表的存在不等于已经具备按相关性排序、多词召回或语义检索。
- `DocumentCard` 保存版本化理解及来源，人工补充独立维护。Hermes 可调用宿主工具，卡片和预整理已有持久任务、取消、预算及外发授权机制。
- 解析器有文件字节、页数和单元数等边界，部分读取工具可按行块或页面读取；这不等于全格式大文件流式解析和跨任务精确续读。
- 图片、PDF 原页、办公嵌图及文件夹/压缩包成员可在相应受控任务中按需读取；现有工具不代表全库图像已自动识别并进入索引。

| 阶段 | 本轮定位 | 状态 |
| --- | --- | --- |
| R0：目标与契约 | 两档预处理、独立专题任务、全文底稿、版本和覆盖边界 | 本文记录，已纳入当前实施依据 |
| R1：片段与检索基础 | 持久 `IndexChunk` 与 `IndexWorkItem`、解析产物落盘后的分批发布/续跑、旧索引兼容回填、当前版本隔离、多词相关性排序、具体命中片段，接入伙伴工具和界面 | 已实现；交付范围与工程验证见第一阶段验收 |
| R2：大文件持续处理 | 解析阶段的分块游标、扩展持久任务/租约、成员缓存、解析及理解断点/局部重试、全面覆盖报告 | 后续设计，不能以 R1 分块持久化宣称已完成 |
| R3：多模态与语义混合 | 图像覆盖与有界识别、真实 Embedding、词法与语义融合、按需重排 | 后续设计；本轮不接入真实 Embedding 模型 |
| R4：真实检索集闭环 | 对照基线、失败归因、成本和体验试用，按证据决定调优 | 工程样本先行，真实资料评测待开展 |

R1 不承诺解除现有全部解析安全上限，也不承诺全格式、全成员、全图像自动识别。两档预处理的切换界面也不在 R1 交付内。阶段推进不得默默降低覆盖标准；暂时无法覆盖时，应保留缺口、原因和可继续处理的范围。

## 3. 两档预处理与用户体验

| 档位 / 任务 | 目标和产物 | 基础索引与预算 |
| --- | --- | --- |
| 快速整理 | 尽快准备名称、标签、可选分类及简卡，让用户确认入库 | 基础索引独立推进；AI 有界阅读支撑建议，明确未读区域 |
| 深入建档 | 在已有成果上完善章节/表格/成员导航、对象事实、用途与检索表达 | 复用同一底稿及有效缓存，按批次继续，显示理解范围与费用 |
| 专题分析 | 根据用户问题找资料、核对原文、比较、计算和形成成果 | 作为独立对话任务执行，可按需要补读，不自动重建全库资料卡 |

两档是当前产品设计，不能据此宣称界面已经提供档位切换或精确增量续读。沿用现有逐资料、批次或当前库范围的外发授权；深入建档若扩大资料范围或变更服务，须按新范围启用，不以“已入库”推导出新的付费外发授权。

界面应让用户分别看到：

- **资料状态**：待整理 / 已整理；AI 方案是否待确认。
- **基础覆盖**：已提取的页、章节、行块或成员，待处理、失败、不支持及图像未识别范围。
- **AI 理解**：快速或深入的处理范围、已读来源、缺口和最后更新时间。
- **任务状态**：排队、处理中、暂停、部分完成、完成、失败或取消，以及是否可继续。

不要显示一个“100%”混合以上四类含义。总量未知时报告已完成数量和未知范围。用户可以先确认有效整理方案，随后继续处理索引；入库不等待所有昂贵分析。

搜索结果应先提供资料名、命中片段、命中类型、来源版本和具体位置。搜索命中 AI 线索或人工补充时明确来源；用户按需打开原文核对，避免先读长篇模型解释才能辨认候选。

## 4. 工程分工与模块边界

| 层 / 现有模块 | 责任与计划扩展 |
| --- | --- |
| `backend/app/index_models.py`、`services/indexing.py` | 当前版本索引、generation、分块存储、发布、搜索和失效；R1 增加片段检索基础 |
| `services/index_content.py`、`index_formats.py` | 格式解码、原文单元和位置；R2 拆出可恢复解析批次，保留真实格式边界 |
| `services/folder_reader.py`、`archive_reader.py`、`document_visuals.py` | 成员与图像入口、结构和安全读取；后续补覆盖清单与缓存 |
| `services/card_jobs.py`、`preorganize.py` | 现有持久 AI 任务、授权、预算和取消；R2 扩展阶段检查点，复用收费调度机制 |
| `services/document_cards.py`、`card_context.py` | 版本化 AI 成果、独立人工补充、卡片有效性与搜索投影 |
| `services/partner_tools.py`、`hermes_tools.py` | 向 Hermes 暴露有界检索、定位和原文读取能力；所有权限与版本由宿主再核验 |
| `core/hermes_agent.py`、`services/partner_runtime.py` | Hermes 对话及策略执行、工具调度与模型交互；不接管资料身份、数据库和业务授权 |
| `backend/app/skills/` | 预处理及检索方法、类型阅读、补读和停止条件；Skill 不模拟不存在的工具能力 |
| `api/indexing.py`、`api/document_cards.py`、`api/preorganize.py` 及前端调用方 | 明确状态、片段、位置和授权范围；现有接口兼容演进，具体契约随实际实现落档 |

TeamHub 持有资料身份、版本、权限、进度、成本和发布事务；Hermes 安排对话与工具策略；模型负责理解与相关性判断；Skill 提供方法。来源 ID、结构校验和版本核对只能证明证据可定位，不能单独证明语义结论正确。

本机能力不依赖组织服务器在线。未来云端按服务身份、资料库与实际成员权限分别索引；本地个人卡片、片段和模型配置不因连接云端自动上传。

## 5. 数据、迁移与发布

### 5.1 数据分层

| 层 | 最小绑定与内容 | 生命周期 |
| --- | --- | --- |
| 原件/快照 | `document_id + version_id + content_hash` | 权威内容，按现有版本规则维护 |
| 原文片段 `IndexChunk` | 父资料及版本/hash、parser/结构版本、generation、稳定片段键、文字、顺序和位置 | 可重建派生底稿；R1 落地字段以代码为准 |
| 任务检查点（R1 基础 / R2 扩展） | 任务 ID、generation、阶段、游标、已提交块、预算用量、租约、错误和时间 | 持久恢复；不保存密钥或以运行内存作为唯一进度 |
| AI 派生信息 | 来源片段、模型/Skill/规则版本、覆盖、识别文本/卡片/线索及修订 | 与原文分开，失败不覆盖有效成果 |
| 搜索投影与向量（R3） | 片段键、当前版本条件、字段类型；向量另含模型版本与维度 | 可重建；模型更换不混用不同向量空间 |

片段键应由固定来源范围与结构标识决定，不能直接使用每次随机产生的 `S1` 作为跨任务主键。来源展示还须带父资料、版本/hash、成员路径和片段内部位置，避免同名文件或相同页码混淆。

### 5.2 发布与幂等

先解析/识别并形成有界批次，再用短事务提交。提交前同时核验资料库绑定、任务 ID/generation、资料状态、当前版本/hash、解析器及任务授权；失配任务不得覆盖当前投影。

R1 用 `IndexWorkItem` 持久保存解析产物、发布游标与租约，每次最多发布 128 个原文单元；块与游标在同一事务提交，重启后继续未提交批次。已完成解析但尚未发布完的块可以逐批进入检索，并明确显示未完成。解析产物落盘前仍采用既有限额内的一次解析，中断后可能重解析；R2 再改造解析器内部的页/表/成员游标和模型理解检查点。任何阶段都不能把不同版本或 generation 的片段混成一份“完整正文”。

当前版本切换后查询立即排除旧版，旧版尚存也不能混入默认结果。重建同一版本可按兼容规则保留已有有效投影，但必须明确旧解析版本与更新中状态；不要为重建而制造短暂的错误版本可见窗口。

### 5.3 迁移、备份和回退

1. 通过现有数据库初始化/迁移入口幂等建表、索引和 FTS 触发器；升级前按现有资料库备份规则备份。
2. R1 从有效的旧解析单元回填片段；回填期间沿用兼容搜索，不能由旧摘要虚构未保存的原文。
3. 对片段总数、版本/hash、孤儿记录和 FTS 一致性做检查。派生数据可重建，原件、资料身份、人工补充及历史任务证据不可随意清除。
4. 回退新检索入口时保留新派生表，使用兼容接口；不得直接降级读取未知结构的数据库。资料库迁移、备份和清理同时覆盖新增记录及缓存。

## 6. 大文件、结构与覆盖

原文件大小不应成为业务上“整份整理失败”的唯一判断。安全硬限额仍必要，但超限应在合适的处理单元上解释，尽量保留可用结构、已处理成果和后续路径。现有整文件字节上限尚未全部解除，此项属于 R2 的解析器改造目标。

| 类型 | 分块与来源要求 | 不能遗漏的上下文 |
| --- | --- | --- |
| 文字 / Word | 按章节、段落或有重叠的文字块；保留章节路径与段落位置 | 标题、注释、表格、文本框及嵌图覆盖分别统计 |
| Excel / CSV / ODS | 按工作表、表区与行块，返回行范围和单元格位置 | 真实表头、合并表头、单位、表名、说明、公式结果与空值语义；不能只保留明细行 |
| PDF | 按实际页分批；页内文字块有位置，图像阅读保留页号/区域 | 有文字层不等于图示已识别；扫描页、图纸和混排图像独立报告 |
| 演示文稿 | 按幻灯片及内容区域；保留页序 | 标题、备注/文字、图表和嵌图分别表达覆盖，避免次序失真 |
| 文件夹 / 压缩包 | 按父版本、成员相对路径、成员内容哈希及内部位置 | 成员清单不等于正文已处理；目录/包整体身份和内部结构保持不变 |
| 图片 / 扫描件 | 原图或受控渲染、按页/帧/区域形成识别单元 | 缩放、裁剪、模糊、未读帧和未识别区域必须可见；OCR/视觉输出属于派生结果 |

解析覆盖、视觉识别覆盖和模型理解覆盖分别记录。确定性解析尽量处理全部支持内容；昂贵视觉识别可分批执行并受授权及预算约束，未识别区域不能计为已进入可检索文字。

缓存按资料库隔离：解析缓存绑定内容哈希、真实格式、解析器/结构版本；成员缓存再绑定成员路径/哈希；AI 缓存还绑定模型、Skill、生成参数及来源范围。相同哈希不自动授予其他资料访问权，跨资料复用须重新绑定来源及核验权限。不同授权目标和跨库的敏感缓存不共享。

## 7. 持久任务、租约与成本

R2 处理阶段为：发现结构 → 分块解析 → 建立词法投影 → 分批 AI 丰富/视觉识别 → 更新卡片及可选语义投影。各阶段可独立报告部分成果，不要求一次模型上下文装下整份文件。

- 使用现有持久任务体系扩展检查点与租约，避免另建一套只存在于 Hermes 历史中的任务状态。队列认领以原子条件更新实现，短事务持有数据库锁。
- 租约记录 owner、过期时间和心跳；超时仅接管可幂等的本地步骤。取消、切库、换版及授权变更递增 generation，所有迟到提交均拒绝。
- 逐次限制请求数、工具调用、输入/输出 token、图像数/字节、解析时间、内存和磁盘。保存累计用量及下一阶段估算；单批预算不等于整个大文件必须一次完成。
- 聊天优先，后台任务复用现有收费租约并有并发上限。达到预算时暂停并保留成果，展示剩余范围和继续动作；不要因一次预算耗尽丢掉整份资料的可用索引。
- 本地幂等步骤可以恢复。外部模型请求发送后结果未知时先标明计费不确定，不因重启自动重放；只有明确的继续/重试授权才发起新的付费请求。
- 关闭自动处理停止后续自动认领；取消停止当前任务的可控后续步骤。已发出的外部请求可能仍收费，不能把取消按钮描述为费用撤回。

## 8. 检索与原文核验

### 8.1 词法检索（R1）

查询在资料可见范围和当前版本内执行，联合名称、标签、原文片段、有效 AI 派生线索和人工补充。SQL 汇总全部授权匹配，按资料去重、排名及分页后，每份资料选取最佳命中片段；不以固定候选截断代替完整计数，也不能让一份长文件独占前十项。

SQLite FTS5 用于词法候选定位，R1 在 SQL 中按关键词覆盖数量及命中来源加权排序；精确编号边界单独核验。尚未以 BM25 或向量模型替代该评分，后续是否引入由基准结果决定。中文短词、设备位号、大小写及百分号/下划线等保留安全字面回退；多词策略区分共同命中和部分命中，查询输入作为参数和字面内容处理，不把用户输入直接解释为 FTS 运算语法。具体打分参数由固定检索集确定，不能只凭直觉宣称质量提升。

结果包含具体 `snippet`、命中字段/类型、片段标识和来源定位。纯 AI 线索命中只说明“值得检查”，不能直接作为事实引用。原文命中片段也可能不足以支持结论，回答前按需要读取上下文。

### 8.2 语义与混合检索（R3）

Embedding 面向片段及其必要结构上下文，记录实际模型、版本和维度。它解决词语不同但含义相近的召回，不能替代精确编号或参数查找。选择本地或外部模型必须说明部署资源、授权范围与实际成本；未接入真实模型前不使用“已支持语义检索”的交付表述。

词法与语义分别召回后，先按同一权限及版本约束过滤，再用 RRF（倒数排名融合）合并，并按资料去重。后续可有界重排；其调用、延迟和失败回退纳入预算。无向量或模型不可用时使用词法结果，明确当前检索能力，不静默把向量缺失当作没有资料。

### 8.3 伙伴读取与事实边界

Hermes 根据问题拆出业务词、编号和可能同义表达，必要时改写查询、扩大候选，并用卡片选择原文位置。回答应读取当前固定版本的相关片段及上下文；表格核对表头、单位和对象，图示核对原页/原图，涉及成员时带成员路径。

来源 ID 有效只代表该来源存在。事实是否被来源支持、是否遗漏限制条件、是否把旧版或相邻设备的参数混用，仍需模型核验和真实评测。找不到充分依据时如实表达不足，保留可检查候选，不补造答案。

## 9. 接口演进约定

下表同时包含已实现的 R1 职责与后续设计。R1 已接入资料搜索、伙伴搜索和索引状态；实际字段以[数据与接口契约](../architecture/MVP数据与接口契约.md)为准，不能据设计推定其他新路径或继续接口已可调用。

| 能力 | 兼容入口 / 设计要求 |
| --- | --- |
| 索引状态与内容 | 沿用 `api/indexing.py` 当前资料索引接口；分页返回结构单元，扩展独立的解析/视觉覆盖与后续游标 |
| 片段检索 | 资料列表及伙伴 `search_documents` 复用同一检索服务，统一相关性、版本过滤、分页和命中片段 |
| 片段读取 | 输入父资料、已保存版本、片段/成员位置；宿主校验后返回有界原文及来源，不接受任意磁盘路径 |
| 整理 / 卡片任务 | 沿用 `/api/ai/preorganize` 和 `/api/ai/cards` 的授权、任务与幂等入口；后续扩展档位、检查点和继续行为 |
| 任务进度与继续 | 返回任务 ID/generation、阶段、已处理/总量、缺口、预算和可继续性；继续请求核验 library/service revision 及范围 |
| 取消 / 重建 | 取消使旧提交失效；重建采用新 generation，保留可解释的既有有效成果与人工信息 |

任务请求中的版本、预算和来源可信字段由宿主生成/验证，模型不能自报完成进度、计费数或权限。分页/游标绑定查询、版本和 generation，失效时返回明确原因，不能悄悄接到另一版本。

## 10. 安全与运行边界

默认私有；片段、摘要、向量、缓存和日志继承来源可见范围。敏感资料不因开启检索自动发送外部模型，也不因组织管理员身份被读取。向量与摘要同样可能泄露内容，应纳入外发授权、备份和删除规则。

成员路径校验、压缩膨胀、页图像素、内存/时间/磁盘上限和受控解码进程保留。尽量按可处理单元给出局部失败，不为“支持大文件”移除安全保护。日志记录任务、数量、状态和脱敏错误，避免原文、图像、密钥与完整提示词无界落盘。

文件正文中的指令属于资料，不改变 Skill、工具白名单、宿主权限或外发范围。删除、换版和权限撤销必须在查询时再次过滤，缓存命中不能绕过；后台回收派生数据不应阻止权限立即生效。

## 11. 验收、真实检索集与推进条件

### 11.1 工程验证

- 旧库升级/重复升级、有效旧单元回填、FTS 与片段一致性、资料库备份及迁移。
- 重复发布、并发重建、进程重启、取消/切库/换版后的迟到提交；当前结果不得混入旧版本、旧 generation 或其他资料库内容。
- 设备位号、短中文词、多个业务词、字面符号、无命中和不同字段命中；结果按资料去重并提供实际命中位置。
- 长表末尾记录、跨章节上下文、同页不同成员、PDF 页码、表头单位、图片/图形缺口；片段不能只有一段总摘要。
- R1 验证发布中断续跑、租约接管和批次回滚；R2 扩展到解析器及模型处理单元的检查点、局部重试和累计预算；R3 增加向量版本、权限、混合召回和模型不可用回退。

### 11.2 真实检索集

在用户授权范围内建立小而真实的资料集，固定原版本与问题、相关资料集合、原文位置和适用条件。问题应来自实际回找任务，覆盖名称不记得、业务同义词、设备编号、参数/单位、表格尾部、图示/扫描件、成员路径、旧新版冲突、跨资料及无答案。保留未参与调优的测试集，由用户或独立核对者标注；不只选系统容易命中的问题。

每次评测固定资料快照、检索器/解析器/模型/Skill 版本和预算，对比现有名称/标签/字面搜索基线、R1 片段检索及后续混合方案。分别报告全文覆盖和已覆盖内容上的检索效果，防止漏解析被排名优化掩盖。

| 指标 | 统计口径 |
| --- | --- |
| 前 5 / 前 10 召回 | 每题相关资料在前 5/10 中被找回的比例，按题平均；另报至少找到一份正确资料的题目比例 |
| 前 5 / 前 10 精度 | 前 5/10 返回项中相关资料的比例，按预定少结果口径统计，按父资料去重 |
| 版本混淆 | 期望当前版却返回/引用旧版、错资料或错成员的题数及比例，逐例保留证据 |
| 定位正确性 | 命中能否落到正确页/章节/工作表行列/成员，片段及上下文是否真正支持所述结论 |
| 内容覆盖 | 按格式统计已处理/总单元及未知范围，单列图像未识别和不支持部分 |
| 延迟与成本 | 本机查询 p50/p95、索引与 AI 各阶段耗时、token/图像/请求及实际费用；冷启动与缓存分开 |
| 用户完成 | 从提问到辨认/打开正确资料的时间、改写次数、仍需问人或返工的情况 |

初始数值门槛须在真实基线上定，不将讨论示例变成未经验证的承诺。权限泄露、版本污染、虚假覆盖和损坏原件属于阻断问题；总体召回改善不能抵消这些错误。召回、精度、定位和成本应同时报告，避免用增加大量候选“改善”召回。

### 11.3 阶段完成定义

- **R1**：相关代码集成、针对性回归通过，文档写明片段及排名实际能力和剩余解析限制；无需真实 Embedding 即可交付词法改进。
- **R2**：在真实大文件上验证多次有界处理、可恢复检查点、覆盖统计和局部失败，不依赖一次整文件读入或一次模型上下文。
- **R3**：使用真实所选 Embedding/视觉模型验证覆盖、同义召回、融合、权限及成本；方法文案和模拟返回不计作能力完成。
- **R4**：留存真实问题、候选、位置、版本、费用和失败归因，判断准确找回是否改善，再决定是否扩大处理范围和自动化。
